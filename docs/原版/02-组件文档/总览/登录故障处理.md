# 登录故障处理：登录成功却进不去

> 记录时间：2026-10-20
> 状态：已定位并修复，方案已验证有效

## 一、症状

在 PS 里打开稿定设计助理面板，输入账号密码：

```
提示"登录成功，正在加载…"
     ↓
加载完成
     ↓
又回到登录页（要求重新输入账号密码）
```

无限循环，永远进不了主界面。账号本身没问题，网页版能正常登录。

## 二、根因

UMS（`ums.gaoding.com`）已经**不再下发 `refresh_token`**，只给：

```
access_token, access_token_expires_at, access_token_life_time,
refresh_token_expires_at, refresh_token_life_time,
appid, client_id, is_new, referer_uri, timestamp, user_id
```

注意：有 `refresh_token_expires_at`，但没有 `refresh_token` 本体。

而面板（3.6.2，2022 年代码）的登录校验是硬性的：

```js
function II(t) { return t && t.access_token && t.refresh_token }
```

**少一个字段就判定未登录**，于是清空界面回登录页。

所以不是登录失败，是登录成功后**本地校验**把它判死了。

## 三、快速修复

前提：已经登录过一次，token 文件已生成。

```
双击 D:\稿定设计助理-存档\工具\修复登录态.cmd
```

看到「已补 refresh_token，回读校验通过」后，**关闭面板重新打开**即可。

脚本做的事：

1. 找到 `%APPDATA%\SheJiZhuLi\LmjcuscH3U.ini`
2. AES 解密，读出 token JSON
3. 备份原文件为 `.bak`
4. 把 `access_token` 的值复制一份给 `refresh_token`
5. 重新加密写回，回读验证

脚本是幂等的，字段已存在时只提示「无需修复」。

## 四、手动步骤（脚本失效时）

```bat
node D:\稿定设计助理-存档\工具\修复登录态.js
```

如果连脚本都跑不起来（没装 Node），那就只能临时用网页版。

## 五、什么时候会复发

| 场景 | 是否需要再修 |
|---|---|
| access_token 过期（约 24 小时） | 需要。重新登录后 token 文件被重写，又会缺字段 → 再跑一次脚本 |
| 在面板里点"退出登录" | 需要，流程同上 |
| 面板热更新 / 重装插件 | 不一定，看是否重新生成 token 文件 |
| 换了台电脑 | 需要，先登录再修 |

**结论：每次在面板里重新登录成功之后，都要跑一次修复脚本。**

## 六、为什么不能一劳永逸

有两种根治办法，都不太划算：

1. **改面板代码**把 `II()` 放宽 → 面板每次启动会自我热更新覆盖 `fz.FengZi1Hao`，改动活不过一次启动
2. **从扩展入口接管**（本地服务方案）→ 能持久，但要多一个常驻进程，之前实测会拖慢

对比之下，"登录后跑一次脚本"成本最低。

## 七、排查树（修复无效时按顺序查）

### 1. token 文件到底写没写进去

```
%APPDATA%\SheJiZhuLi\LmjcuscH3U.ini
```

- 不存在 → 登录根本没成功，不是本问题
- 存在但脚本说"解不开" → 文件格式变了，重新分析

### 2. token 是否有服务端效力

拿 `access_token` 直接请求：

```
GET https://zhuli.gaoding.com/api/v1/user-info
Authorization: Bearer <access_token>
```

- 200 → token 有效，问题在本地校验
- 401 → token 无效，服务端问题或账号问题

### 3. 设备校验（setupCheck）是否卡住

面板登录后还会调 `/api/v1/device/exists/check` 校验设备绑定。
如果设备数超限或被移除，会弹「设备被移除，请重新登录」，表现和登录失败很像。

验证：

```
GET https://zhuli.gaoding.com/api/v1/user/devices
Authorization: Bearer <access_token>
```

本机当时的返回：

```json
{"deviceInfo":[{"deviceName":"Windows(xinye)","cpuId":"6bed8463..."}],
 "quantity":2,"usage":1,"left":1}
```

`left` 为 0 或设备被踢，就需要在官网设备管理里删旧设备。

### 4. 是否被热更新覆盖

检查 `%APPDATA%\fz.FengZi1Hao` 下文件的修改时间。如果和 PS 启动时间接近（差 20 秒左右），说明面板刚自我更新过，任何对面板文件的改动都已失效。

## 八、技术附录

### token 文件格式

```
路径：%APPDATA%\SheJiZhuLi\LmjcuscH3U.ini
算法：AES-128-CBC
key ：1234123412ABCDEF      （16 字符，UTF-8）
iv  ：ABCDEF1234123412      （16 字符，UTF-8）
输出：大写 HEX 字符串
明文：token JSON（access_token / refresh_token / 过期时间等）
```

key/iv 硬编码在 `chunk-vendors.a06ad4b7.js` 的 `33bc` 模块里。

### 相关代码位置

| 函数 | 作用 |
|---|---|
| `II(t)` | 判定 token 是否有效：`t && t.access_token && t.refresh_token` |
| `OI()` | 启动时读 token 文件、解密、校验 |
| `m(t)` / `TI()` | 把 token 加密写入文件 |
| `CF()` | 启动流程：无 token → `ft["i"]()` 跳登录页 |

### 关键接口

| 用途 | 地址 |
|---|---|
| OAuth 登录 | `POST https://ums.gaoding.com/api/oauth/token` |
| SSO 页面 | `https://ums.gaoding.com/ums/sso?env=prod&mod_id=client&appid=pszhuli&redirect_url=...` |
| 用户信息 | `GET https://zhuli.gaoding.com/api/v1/user-info` |
| 设备列表 | `GET https://zhuli.gaoding.com/api/v1/user/devices` |
| 面板资源 | `GET https://zhuli.gaoding.com/api/device/active/file?type=CEP001` |
