## 一、架构：清单走 API，文件走 CDN

```
面板
 ├─ GET  https://zhuli.gaoding.com/api/sync/file-list      ← 拿清单（含每个文件的直链）
 ├─ GET  https://pszhuli.dancf.com/...                     ← 按 fileUrl 下载文件内容
 └─ POST https://zhuli.gaoding.com/api/sync/file-list/...  ← 上传（part/add 或 all/add）
```

**关键点**：`fileUrl` 是服务端下发的完整直链，客户端不做拼接。这意味着**换存储只需要换 fileUrl 的域名**，客户端逻辑完全不用动。

## 二、清单接口

### 请求

```
GET /api/sync/file-list
Authorization: Bearer <access_token>
```

### 返回结构 `[确证]`

```json
{
  "first": false,
  "syncInfo": {
    "usn": 3,
    "lastSyncTime": 1785825121216,
    "list": [
      {
        "usn": 4,
        "guid": "SJDB604FF393382A7F",
        "fileUrl": "https://pszhuli.dancf.com/sync/design/2021-11-22/9uyj8r2xgn9g09rwzi1od8s1h83eqco4/sj_ztglStar.ini",
        "clientPath": "/sj_ztglStar.ini",
        "fileStatus": 0,
        "syncStatus": 1,
        "lastSyncTime": 1637544783100
      }
    ]
  }
}
```

| 字段 | 含义 |
|---|---|
| `first` | 是否首次同步（为 true 时客户端会走全量上传分支） |
| `syncInfo.usn` | 全局版本号，增量同步基准 |
| `list[].usn` | 该文件的版本号 |
| `list[].guid` | 文件唯一 id，形如 `SJ` + 16 位大写 hex |
| `list[].fileUrl` | 完整下载直链 |
| `list[].clientPath` | 本地落盘路径（相对 `%APPDATA%\SheJiZhuLi`） |
| `fileStatus` / `syncStatus` | 状态位，0/1 |

## 三、文件内容格式 `[确证]`

**双层编码**：

```
base64( gzip( base64( JSON ) ) )
```

解码步骤：

```js
let buf = Buffer.from(raw, 'base64');            // 第一层
if (buf[0] === 0x1f && buf[1] === 0x8b) {        // gzip magic
  buf = zlib.gunzipSync(buf);
}
let text = buf.toString('utf8');
if (/^[A-Za-z0-9+/=\s]+$/.test(text)) {          // 第二层
  text = Buffer.from(text.replace(/\s+/g, ''), 'base64').toString('utf8');
}
const data = JSON.parse(text);                   // 最终 JSON
```

> 注意：`.ini` 后缀的文件，内容其实是 **JSON**，不是 ini 格式。

### 已确认的文件类型

| 文件名模式 | 内容结构 |
|---|---|
| `sj_ztglStar.ini` | 字体收藏 |
| `sj_ztglTags.ini` | 字体标签 |
| `sj_kuGra*.ini` | 渐变库：`[{name, show, list:[{name, gradient:{...}}]}]` |
| `sj_kuCol*.ini` | 颜色库 |
| `sj_kuFon*.json` | 字体库 |

## 四、两种 URL 形态 `[确证]`

### 形态 A：新版（带日期目录）

```
https://pszhuli.dancf.com/sync/design/<YYYY-MM-DD>/<32位小写字母数字>/<文件名>
```

例：
```
https://pszhuli.dancf.com/sync/design/2021-11-22/9uyj8r2xgn9g09rwzi1od8s1h83eqco4/sj_ztglStar.ini
```

中间那 32 位是**随机串**（不是 MD5，看不出与内容相关），作用是避免同名覆盖 + 缓存失效。

### 形态 B：旧版（用户目录）

```
https://pszhuli.dancf.com/<用户ID+随机码>/SJ<16位大写HEX>
```

例：
```
https://pszhuli.dancf.com/314373138SqqFcom/SJA91E487AA0799CDB
```

**下载时可能带 `?timestamp=<毫秒>`**，属于防缓存参数，服务端忽略。

## 五、上传流程 `[推断]`

从静态代码提取到的接口：

| 接口 | 用途 |
|---|---|
| `POST /api/sync/file-list/part/add` | 增量上传（只传有变化的文件） |
| `POST /api/sync/file-list/all/add` | 全量上传 |
| `POST /api/sync/file-list/delete` | 删除云端文件 |
| `POST /api/sync/status/check` | 上传前状态检查 |
| `POST /api/sync/upload/tokens` | 上传（OSS 直传令牌？） |

`part/add` 与 `all/add` 返回结构相同：

```json
{
  "syncInfo": {
    "list": [...],
    "lastSyncTime": ...,
    "usn": ...
  }
}
```

客户端收到后用返回值覆盖本地 `syncInfo`。

**未验证**：上传请求体的完整字段（静态代码里看到 `{list: [...]}`，每项的字段需要抓一次真实上传才能确认）。

## 六、换成自己服务器要做什么

### 最小可行方案

只需实现 **2 个动作**，客户端零改动：

**1. 替换清单接口**

自建服务实现 `GET /api/sync/file-list`，返回：

```json
{
  "first": false,
  "syncInfo": {
    "usn": 1,
    "lastSyncTime": 0,
    "list": [
      {
        "usn": 1,
        "guid": "SJ0000000000000001",
        "fileUrl": "http://127.0.0.1:9000/files/sj_ztglStar.ini",
        "clientPath": "/sj_ztglStar.ini",
        "fileStatus": 0,
        "syncStatus": 1,
        "lastSyncTime": 0
      }
    ]
  }
}
```

**2. 提供文件直链**

`fileUrl` 指向自己的存储（本地目录、自建 HTTP、OSS、S3 都行），返回**同样格式的双层 base64**。

### 拦截面板请求的两种做法

| 做法 | 说明 |
|---|---|
| 改 bundle 里的域名 | 把 `zhuli.gaoding.com` 指向本地服务（现有本地模式方案） |
| 用 hosts + 自签证书 | 不改代码，但麻烦、证书警告 |

### 数据迁移

首次迁移时，从官方拉一遍完整清单 + 下载所有 fileUrl，转存到自己的存储，然后把 `fileUrl` 改成自己的。之后面板每次同步都走你的服务。
