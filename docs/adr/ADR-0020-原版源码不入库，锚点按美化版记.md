- **状态**：已取代

## 判据（它凭什么成立 / 为什么不成立）

> ⚠️ **已被 ADR-0025 取代（2026-10-23）**：源码已于 2026-10-23 入库（`docs/原版/`），「不入库」的前提没了；「检索用字符串定位、不按行号」也随之作废。本条正文保留，因为它记录了「为什么当初只能靠字符串定位」。仍成立的部分：别的插件安装副本不得据以核对（版本不一致）。

- **决定**：
  - 原版还原源码**不入库**（体积大、涉及版权）。
  - **那份安装副本不可用于核对**：它是更早的安装版本，与文档调查所用版本不一致，**不得据它下任何结论**。需要复核时须另取与文档同版本的源码。
  - 文档里的原版锚点**按美化版记**；检索时用字符串定位，**不按行号**。
  - 二手证据可直接据以开工，锚点是将来复核的入口，不是当下必须重跑一遍。
- **原因**：不入库是因为体积与版权。该副本版本不可信，因此复核只能依赖锚点，以及将来取得的与文档同版本的源码；字符串（class 名、脚本函数名、stringID、提示文案、文件后缀）在压缩版里原样保留，是定位手段，但不能替代版本确认。
- **代价**：
  - 行号锚点在压缩版上失效，只能当「美化版的坐标」用；
  - 压缩版函数名被 mangle，函数级定位要靠调用处的字符串；
  - 文档里的行号一旦美化设置变了就会漂移。
- **复核方法**：先取得**与文档调查同版本**的源码（更早的安装版不可用），再用字符串定位取命中点前后一段上下文；结论标注格式为「已核（源文件名，字符串定位：关键字）」，**不写行号**。
- **什么时候推翻**：拿到可入库的授权副本时；或取得与文档同版本的源码并把锚点重挂到它上面时。
