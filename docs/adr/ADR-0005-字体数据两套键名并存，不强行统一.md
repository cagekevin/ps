# ADR-0005 · 字体数据两套键名并存，不强行统一

- **状态**：生效
- **结论**：字体数据两套键名并存不强行统一：脚本返回值与磁盘缓存各自既定，靠唯一一处归一转换。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：两套键名都是外部既定格式

## 背景

两套键名都是外部既定格式（一套是原厂脚本给的，一套是原面板写在磁盘上的），强行统一会导致要改写原面板的文件。

## 判据

1. **两套键名并存，不强行统一**：应用内部的字体形状用「脚本返回值」那套；磁盘缓存那套保持原样。
2. **转换只许一处**：由唯一一处归一（字体归一模块）把磁盘缓存形状转成内部形状。
3. **不许在消费点直接按任一套键名读另一套来源**。

**唯一入口**：字体归一 = `src/domain/font-normalize.ts`。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 出现第三套字体键名 | 三套并存，归一无法收敛 |
| 归一之外还有一处直接按脚本键名读磁盘缓存（或反之） | 两套形状各读各的，对不上时静默取空 |

**什么时候推翻**：我们自己接管了缓存文件格式（不再依赖原面板写入）时，两套并存的理由消失。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：出现第三套字体键名；或归一之外还有一处直接按另一套键名读。
