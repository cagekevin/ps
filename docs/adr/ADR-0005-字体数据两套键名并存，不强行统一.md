# ADR-0005 · 字体数据两套键名并存，不强行统一

- **状态**：生效
- **结论**：字体数据两套键名并存不强行统一：jsx 返回值与磁盘缓存各自既定，靠 normalizeFont() 转换。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：两套键名都是外部既定格式

## 背景

源文档（`docs/架构/决策记录.md`）本条未单列「背景」段：旧约定与原因写在「决定 / 原因 / 由来」字段里，已随「判据」段逐字搬来。

## 判据（它凭什么成立 / 为什么不成立）

- **决定**：`FontItem` 用 `family/weights/names/postScriptNames`（jsx 返回值），磁盘缓存 `SysFont2.json` 用 `name/zz/mz/hjm`，靠 `normalizeFont()` 转换。
- **原因**：两套都是外部既定格式（一套 jsx 给的，一套原面板写的），强行统一会导致要改写原面板的文件。
- **什么时候推翻**：如果我们自己接管了缓存文件格式（不再依赖原面板写入）。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果


- 📌 **违反时的判据**：出现第三套字体键名；或 `normalizeFont()` 之外还有一处直接按 jsx 键名读磁盘缓存（或反之）。
