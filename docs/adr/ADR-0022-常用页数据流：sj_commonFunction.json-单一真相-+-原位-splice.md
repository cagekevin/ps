# ADR-0022 · 常用页数据流：`sj_commonFunction.json` 单一真相 + 原位 splice

- **状态**：生效
- **结论**：常用页唯一真相是 sj_commonFunction.json（根为裸数组），排序用原位 splice；子面板参数与折叠态一律落官方设置文件。
- **日期**：2026-10-23（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：上一版把页面常量当真相，页面与命令各有一份

## 背景

原版把这一页的全部可变状态放在一个文件里，设置页写的也是同一个数组。我方只有同文件同形状才不互相抹。上一版把页面常量当真相，页面与命令各有一份 —— 本条把真相定回文件。

子面板参数必须落在官方读取位置：原版连**执行时**也现读设置文件，放别处就会出现「面板里设的值」与「真正执行用的值」分叉。

原版那条「读坏文件 → 覆盖成默认值」是会丢用户顺序与显隐的缺陷，与本项目的数据安全判据直接冲突，故只借它的**建种子**行为、不借它的兜底。

## 判据

1. **网格项 / 顺序 / 显隐的唯一真相是 `sj_commonFunction.json`；文件根是裸数组**（14 项）。读侧兼容早期写错的旧形状，**写侧一律归一成裸数组**。
2. **排序用原位 splice**（落点计算收口在 `src/domain/reorder.ts`），**不用全量覆盖数组**。
3. **子面板参数不落会话态**，一律落在官方设置文件的官方键位；**写入口只许在 `src/cep/data/legacy-settings.ts` 的窄函数里**，不新建第二个读写该文件的模块。嵌套 patch 口径：**递归到叶子**、数组整体替换、深对象不整块替换、未知键不进 patch。
4. **折叠态与显隐一律落官方设置文件**（与官方读取位置一致）。
5. **首建语义**：文件不存在才建种子；**损坏 / 读失败一律抛错、不写**。不照抄原版「读坏 → 用默认值覆盖」。
6. **重置照语义、不照文案**：官方那条重置是「全清 + 复位种子 + 连用户显隐一起复位」，而按钮文案写的是「重置排序」。我方按语义实现，并把文案改成「恢复默认常用功能」，**且加二次确认**（原版无确认 = 我方有意偏离）。
7. **自由面板项的 key 是官方派发表 key**，它与调用名**不总是同名**，所以映射是**两跳**：官方 key → 命令 id → 调用名。旧自造 key 收进一张别名表（`src/domain/free-panel-legacy.ts`），表头必须写清加它/删它的条件。
8. **两处窄例外**：① 新增一个纯 UI 态命令承载跨会话折叠（store 不许写、页面不许直接依赖数据层）；② 事件通道从「一个 ID 一个语义名」改为「一个语义名 + 载荷路由」——**不新增语义名**，ID 与语义名仍是一对一。

**唯一入口**：常用项仓库 = `src/cep/data/common-use.ts`；官方设置仓库 = `src/cep/data/legacy-settings.ts`；排序落点 = `src/domain/reorder.ts`。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 出现第二份常用页可变状态真相（页面 / 命令里的常量） | 页面与命令会互相抹 |
| 写出对象根形状 | 原版读不到 ⇒ 真机显示「还没有常用功能」 |
| 重置没有二次确认 | 会连用户顺序与显隐一起清掉 |
| 读坏文件时用默认值覆盖 | 会丢用户顺序与显隐 |
| 新建第二个读写官方设置文件的模块 | 双写热点无法收敛 |
| 别名表无加入 / 删除条件 | 变成没人敢删的表 |

**代价**：官方设置文件成为**双写热点**（原版会整份重写，我方按路径 patch）。已核实原版**没有周期落盘**，所以只剩「用户在两个面板同时改同一键」这一种窗口，靠仓库重读 + CAS 兜。

**什么时候推翻**：原版若新增「用户自定义常用项」能力，本条「只显隐 + 排序」的边界作废；原版若不再写该文件，「必须与官方同形状」的理由消失，可换成我方 schema。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：出现第二份常用页可变状态真相；或写出对象根形状；或重置没有二次确认。
