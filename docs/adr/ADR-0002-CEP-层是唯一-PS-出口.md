# ADR-0002 · CEP 层是唯一 PS 出口

- **状态**：生效
- **结论**：页面禁止裸调 CEP；PS 出口全部收口在 src/cep/。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：需要统一的超时、错误码、初始化顺序、mock 切换

## 背景

散落在页面里的宿主调用没法保证统一的超时、错误码、初始化顺序与模拟切换。

## 判据

1. **页面禁止出现宿主注入对象、脚本执行接口、脚本文件执行接口。**
2. **PS 出口全部在 `src/cep/`**：传输层（唯一脚本执行出口）、脚本域文件、事件通道、文件读写、初始化与只读门面。
3. **新增一个宿主能力要改三个地方**：脚本域实现 + 域类型声明 + 模拟实现；初始化门面**只读**，只负责初始化与读取。
4. **页面层不得直接依赖 cep 层**（唯一例外：只读门面）。
5. **不要为某个页面的一次性调用就加宿主能力。**

**唯一入口**：`src/cep/transport.ts`（传输层）、`src/cep/jsx/`（脚本域）、`src/cep/events.ts`（事件通道）、`src/cep/fs-read.ts` 与 `src/cep/disk-write.ts`（文件读写）、`src/cep/ps.ts`（初始化与只读门面）。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 页面 / 组件里出现宿主注入对象或脚本执行接口 | 超时、错误码、初始化顺序无法统一 |
| 出现第二个脚本执行出口 | 同上 |
| 页面层直接依赖 cep 层（只读门面除外） | 越过出口边界，能力会散回页面 |
| 初始化门面里新增对外能力 | 门面只负责初始化与读 |
| 为页面的一次性调用加宿主能力 | 能力越加越多，边界失守 |

**代价**：加一个新宿主能力要改三个文件。

**什么时候推翻**：不推翻。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：页面或组件里出现宿主注入对象 / 脚本执行接口 / 脚本文件执行接口；或出现第二个脚本执行出口。
