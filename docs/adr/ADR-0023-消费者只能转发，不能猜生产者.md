# ADR-0023 · 消费者只能转发，不能猜生产者

- **状态**：生效
- **结论**：消费者只能转发不能猜生产者：不拼文案、不重分类、不下因果结论、不替生产者决定可见性与频率。
- **日期**：2026-10-23（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：同一个失败被提示两次，且「目录与参数」是页面猜的因果

## 背景

同一个失败被提示了两次：命令层已经报错，页面又补一句自造文案，而那句文案里的原因是页面猜的。同一个降级信号被三页拼成三种后缀，而生产者只说了「哪份数据没读出来」。

根因不是某处写错，是**消费者开始替生产者补信息** —— 一旦开始补，生产者就永远不知道自己缺了东西。

## 判据

1. **消费者只做转发**：拿到什么显示什么。
2. **不许自己拼文案**：失败文案由失败描述与命令结果给出，页面不另写一句「请检查…」。
3. **不许重分类**：不按文案、错误码、字段有无重新判断「这算什么错」；分类只在生产者或命令层做一次。
4. **不许下因果结论**：不知道原因就不写原因。
5. **不许替生产者决定可见性与频率**：提示一次还是两次、浮层还是内联、要不要防抖，都由产出失败的那一层决定；消费者只把已经决定的东西显示出来。
6. **前置校验直接报错是允许的**（空名、重名这类）—— 那不是生产者产出，是消费者自己的前置判断。

**唯一入口**：命令消费 = `src/components/command/useCommand.ts`（失败自动提示，调用方只拿到成功与否，拿不到文案 —— 所以页面写不出第二条）。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 页面自己拼一条失败文案 | 同一个失败提示两次 + 猜的因果 |
| 页面按文案内容换一种提示 | 重分类 |
| 页面把降级信号再加工成结论 | 下因果结论（生产者只说「哪份没读出来」） |
| 页面给同一个失败加防抖 / 去重 | 替生产者决定频率 |
| 页面自己捕获异常包住命令执行再自己提示 | 绕开唯一消费点 |

**与既有 ADR 的关系**：ADR-0016 是上游（生产在命令层，消费只转发）；ADR-0014 的降级标记是本条的输入（生产者给信号，消费者负责显示、不负责解释）；本条不推翻任何既有 ADR。判据面在本条，执行面在 `AGENTS.md` 硬规则 20 —— 两处指向同一件事，改一处必须同时改另一处。

**什么时候推翻**：若命令层不再产出失败原因与降级标记（例如改成直接抛给页面），本条的「转发对象」消失，那时要重写而不是作废。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：页面里出现自造失败文案；按文案重分类；把降级信号再加工。
