# ADR-0017 · 与 PS 之间是双向的：命令下行，事件上行

- **状态**：生效
- **结论**：下行只走 commands→cep/jsx→cep/transport；上行只走 cep/events；同一语义只允许一个订阅点。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：四个页面四套查法，查询点散落，行为不可统一

## 背景

只有下行时，任何「跟随 PS 状态变化」的需求都会退化成「在页面里操作前查一次」—— 字体面板要当前文字属性、常用页要选区类型、动作页要文档切换、重命名要图层选择，四个页面四套查法，查询点散落，行为不可统一。原版就是这么散的。

## 判据

1. **应用 → PS 只有一条路**：命令 → 脚本域 → 传输层。
2. **PS → 应用也只有一条路**：宿主事件通道。
3. **新增宿主事件只改事件 ID 表一行 + 一个消费者**。
4. **同一语义只允许一个订阅点**；新增订阅必须复用已有订阅点，不许各写一份「这条事件对我意味着什么」。
5. **一条事件频道不得混载两种语义**（刷新信号与执行指令必须分道）。
6. **文件 → 应用不做监听**（外部变更靠切页重读），这是明确取舍，不是遗漏。

**唯一入口**：事件 ID 表与订阅 = `src/cep/events.ts`；脚本域 = `src/cep/jsx/`；传输层 = `src/cep/transport.ts`。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 出现第二条下行通道（绕过命令 → 脚本域 → 传输） | 出口分散，超时与错误码无法统一 |
| 为某个页面单开私有订阅 | 同一语义多份判定，行为不可统一 |
| 同一语义多处各自订阅 | 每处各写一份含义判断，迟早分叉 |
| 一条频道同时承载刷新信号与执行指令 | 订阅者按各自语义处理同一条消息 |
| 对文件变更做监听 | 明确的取舍，不做监听 |

**机制依据**（不是猜）：原版用事件派发注册 + 监听回调，按事件 ID 分发并做去抖；事件 ID 由脚本层取，不硬编码。

**代价**：事件注册与回调格式按原版契约实现，注册失败或事件不来时自动退回「执行前查询」，功能不受影响。

**什么时候推翻**：宿主版本不支持事件派发时通道恒不可用，退化为纯查询 —— 结构不变。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：新增宿主事件开了私有订阅；或出现第二条下行通道。
