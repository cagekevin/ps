# ADR-0015 · 数据文件四种形态，全部收口在 `data/`

- **状态**：生效
- **结论**：持久化只许出现在 data/，每文件一个仓库；读只容错、写必保守，落盘原子写 + 写前备份。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：全部数据文件都来自原面板，原面板会同时读写

## 背景

全部数据文件都来自原面板的同一批目录，**原面板会与本面板同时读写同一批文件** —— 所以读只能容错、写必须保守。

四种形态的 IO 语义差别很大（目录枚举、任意路径、高频写），不集中收口就会各写一套读改写实现。曾经就有两套读改写实现并存（一套有备份与原子写、一套没有），连点收藏会丢更新。

## 判据

1. **持久化只允许出现在 `src/cep/data/`**，按四种形态处理：平铺 JSON / 子目录多文件 / 外部交换（任意路径 + 文件对话框）/ 低容忍高频写（星级、标签、频率与历史）。
2. **每个文件一个仓库**（仓库形状，读侧与写侧分开暴露）。**新增数据文件必须先有仓库定义**，不能随手读写就改。
3. **读只容错、写必保守**：读失败可降级但必须标记（判据见 ADR-0014），写失败一律抛。
4. **落盘必须原子写 + 写前备份**（判据见 ADR-0012）；备份与「原文已坏则另存隔离副本」的判定**只有一处**。
5. **变更通知只有一个来源**：每文件一条变更通道，不在多处各建一套监听表。
6. **同一文件只能有一条读路径**：不许同一文件被两套读实现或两套解码器覆盖。
7. 写操作必须经仓库（保证原子写、备份与并发保护），不许在仓库外直接落盘。

**唯一入口**：仓库形状 = `src/cep/data/types.ts`；落盘与备份 = `src/cep/disk-write.ts`；数据层 = `src/cep/data/`。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| `src/cep/data/` 之外出现新的持久化实现 | 各写一套读改写语义 |
| 新增数据文件没有对应仓库定义 | 绕过原子写、备份与变更通知 |
| 备份 / 隔离判定在两处各写一遍 | 同一判据两份实现，改一处就漂 |
| 同一个文件有两条以上读路径或两套解码器 | 结论会分叉 |
| 变更通知表在多处各建一套 | 刷新时机不一致 |
| 写操作不经仓库 | 丢原子写与备份，用户资产无法回退 |

**代价**：新增数据文件必须先加一行仓库定义，比「随手读写就改」多一步。

**收口之后还剩一层**：本条把持久化收进数据层，但数据层之下仍可绕过读原语直接读文件 —— 唯一读入口见 ADR-0026。

**什么时候推翻**：完全接管这批文件、原面板不再共存时，可去掉备份与部分容错。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：`src/cep/data/` 之外出现新的持久化实现；或新增数据文件没有对应的仓库定义。
