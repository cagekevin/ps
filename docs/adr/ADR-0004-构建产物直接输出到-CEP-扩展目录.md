# ADR-0004 · 构建产物直接输出到 CEP 扩展目录

- **状态**：生效
- **结论**：构建产物直接输出到 CEP 扩展目录，build 即部署；原厂脚本包必须来自 public/。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：省掉「构建 → 复制 → 忘复制某个文件」这类问题

## 背景

「构建 → 复制 → 忘复制某个文件」是这类项目最常见的一类事故。

## 判据

1. **构建产物直接输出到 CEP 扩展目录**（宿主扩展目录），**build 即部署**。
2. **清单与原厂脚本包放 `public/`**，随构建一起进产物。

**唯一入口**：`vite.config.ts`（输出目录）。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 输出目录指向仓库内目录、构建之外还要手工复制文件 | 「忘复制」事故源 |
| 手工把原厂脚本包放进输出目录 | 构建会清空输出目录，手放的会被抹掉 |

**代价**：构建会清空输出目录，所以原厂脚本包必须来自 `public/`，不能手动放。

**什么时候推翻**：需要同时维护多个扩展版本时（比如做灰度）。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：输出目录指向仓库内目录而构建之外还需手工复制文件；或原厂脚本包被手动放进输出目录而不是来自 `public/`。
