# ADR-0001 · UI 全重写，PS 能力继续用原厂 jsxbin

- **状态**：生效
- **结论**：UI 与数据流全部用 Vue 3 重写；PS 能力继续调原厂 jsxbin，不逆向、不重写。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：原面板 Vue 2 EOL、1.5MB 单包、无类型；jsxbin 是 68 个函数的行为黑盒

## 背景

原面板是 Vue 2，已 EOL；组件全塞在一个 1.5MB 单包里；没有类型。但原厂脚本包是 68 个函数的行为黑盒，重写成本远超收益。

## 判据

1. **界面与数据流全部用 Vue 3 重写**。
2. **PS 操作继续调原厂脚本包**，不逆向、不重写。
3. **不引入官方 CSInterface 库**（判据见 ADR-0006）。

**唯一入口**：脚本包 = `public/lib/all.decrypted.js`（只读，不得改动）。

**替代方案（已评估，不采纳）**：全量反编译脚本包（字节码，无可靠工具）；或自己用 ExtendScript 重写全部 PS 操作（68 个函数）。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 页面直接调宿主注入对象或脚本执行接口 | 越过 cep 层边界（判据见 ADR-0002） |
| 反编译脚本包里的某个函数，而没有「那个函数行为必须改且改不了」的证据 | 反编译不可靠，且黑盒行为足够用 |
| 改动脚本包本体 | 它是只读的一手依赖 |

**什么时候推翻**：某个函数的行为必须改、且改不了 —— 那时只针对**那一个函数**反编译。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：页面出现宿主注入对象 / 脚本执行接口；或有人提议反编译脚本包里的某个函数而没有「那个函数行为必须改且改不了」的证据。
