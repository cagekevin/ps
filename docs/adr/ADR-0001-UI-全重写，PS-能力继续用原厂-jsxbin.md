# ADR-0001 · UI 全重写，PS 能力继续用原厂 jsxbin

- **状态**：生效
- **结论**：UI 与数据流全部用 Vue 3 重写；PS 能力继续调原厂 jsxbin，不逆向、不重写。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：原面板 Vue 2 EOL、1.5MB 单包、无类型；jsxbin 是 68 个函数的行为黑盒

## 背景

源文档（`docs/架构/决策记录.md`）本条未单列「背景」段：旧约定与原因写在「决定 / 原因 / 由来」字段里，已随「判据」段逐字搬来。

## 判据（它凭什么成立 / 为什么不成立）

- **决定**：Vue 3 重写全部界面和数据流；PS 操作继续 `$.evalFile` 原厂 jsxbin。
- **原因**：原面板 Vue 2 已 EOL、组件全塞在 1.5MB 单包里、无类型。但 jsxbin 是 68 个函数的行为黑盒，重写成本远超收益。
- **替代方案**：全量反编译 jsxbin（字节码，无可靠工具）、或自己用 ExtendScript 重写 PS 操作（68 个函数）。
- **什么时候推翻**：某个函数的行为必须改，且改不了——那时只针对**那一个函数**反编译。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

- 📌 **违反时的判据**：页面出现 `window.__adobe_cep__` / `evalScript` / `$.evalFile`，或有人提议反编译 jsxbin 里某个函数而没有「那个函数行为必须改且改不了」的证据。
