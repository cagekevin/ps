# ADR-0018 · `build.target` 用 `esnext`，不用 chrome91

- **状态**：生效
- **结论**：build.target 用 esnext：esbuild 0.28.2 在 Windows 删不掉自己的临时目录，只有产物级 transpile 崩。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：npm run build / deploy 在 Windows 上必失败（Access is denied）

## 背景

构建在 Windows 上必失败，报「删不掉自己的临时目录：拒绝访问」（esbuild 0.28.2）。构建产物没出来。

**根因不是项目代码**：是 esbuild 在 Windows 上删不掉自己的临时目录。报错发生在构建的**产物级**转译那一步（大输入整包转译之后清理临时目录），而这一步**只在目标里有需要降级的语法时才运行**。

**证据**：换临时盘符、换短路径、设临时目录环境变量、脱离 shell 用独立进程跑构建 —— 都还报同样的错，与调用方式无关；对照实验是**模块级转译正常**（开发与测试环境里 esbuild 跑得好好的），只有产物级转译崩。把目标提到 esnext 后构建成功。

## 判据

1. **构建目标用 esnext**，跳过产物级转译。
2. **不降到 chrome91**：宿主是 Chromium 99，现代语法都支持，风险可接受；但「支持 chrome91」这条保证没了。

**唯一入口**：构建配置 `vite.config.ts` 的 `build.target`。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 目标回到 chrome91，而「拒绝访问」未在换机器 / 升级 esbuild 后复核过 | 会重新触发构建必失败 |
| 为绕开构建失败去改系统清理策略或给杀软加排除 | 换台机器就复现，等于把问题藏起来 |

**代价**：产物不再向 chrome91 降级语法，现代语法原样保留。

**被放弃的方案**：改 esbuild 版本（本轮不许动依赖，也没验证过哪个版本不犯这个毛病）；给杀软加排除或改系统清理策略（改的是开发机环境，换台机器就复现）；给依赖包打补丁（离线重建就失效，属于「补丁式绿灯」，不做）。

**什么时候推翻**：换机器、或 esbuild 升级后再验证一次「拒绝访问」是否消失 —— 只要它不再复现，就应把目标降回去，并复核真机面板。另外：如果宿主运行时降到 Chromium 99 以下（换 PS 版本），这条必须重新评估。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：`build.target` 回到 chrome91 而「拒绝访问」未在换机器 / 升级 esbuild 后复核过。
