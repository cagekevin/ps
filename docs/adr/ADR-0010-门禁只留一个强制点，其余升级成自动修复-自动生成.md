# ADR-0010 · 门禁只留一个强制点，其余升级成自动修复 / 自动生成

- **状态**：生效
- **结论**：门禁只留一个强制点 npm run deploy，其余降级为自动生成/自动修复；build 不带任何检查，不做 pre-commit hook。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：门禁净收益公式；样式守卫是颜色散落真实发生后才加的

## 背景

门禁净收益 = 概率 × 损失 × 频次 ×（收益 − 绕过成本） − 成本 × 频次 − 维护。

- **能被绕过的门禁净收益接近 0，但成本照付** ⇒ 软门禁比没有门禁更差。
- 同一件事，做成「自动修复 / 自动生成」比「报错阻止」便宜一个数量级（前者机器干活，后者人肉改）。
- **门禁应该事后建**（基于真实事故），不是事前建（基于想象）。样式守卫是颜色散落真实发生后才加的；「漏登记」一次都没发生过，所以降级。

## 判据

1. **`build` 就是构建，不带任何检查**；检查放在 `check` 链里。
2. **文档生成器改成纯生成器**（扫描 + 自动补骨架 + 重写文档），不阻塞任何东西。
3. **唯一强制点是 `npm run deploy`**（检查 + 类型检查 + 构建），部署前必跑。
4. **不做 git pre-commit hook**。

**唯一入口**：`package.json` 的脚本段。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| `build` 里混进检查命令 | 破坏「构建即产物」的直觉，且检查成本人人付 |
| 出现第二个强制点 | 强制点越多越会被绕过，净收益归零 |
| 做 git pre-commit hook | 钩子可被跳过，且污染本地工作流 |

**代价**：文档生成器不再强制，有人忘了跑，文档会过期。

**什么时候推翻**：团队超过 2 人，或真的发生过「漏登记导致重复造轮子」。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：`build` 里混进了检查命令；或出现 git pre-commit hook；或出现第二个强制点。
