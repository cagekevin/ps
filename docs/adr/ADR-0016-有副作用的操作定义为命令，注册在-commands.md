# ADR-0016 · 有副作用的操作定义为命令，注册在 `commands/`

- **状态**：生效
- **结论**：有副作用的操作定义为 Command 注册在 commands/；命令元数据与实现分层；页面只消费注册表，不各自实现操作。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：原版用事件总线让同一批操作被至少 4 个入口触发

## 背景

原版用事件总线让同一批操作被至少 4 个入口触发。没有命令这个单位，同一功能只能在每个入口各写一遍。

设置页管理的正是「命令的显隐 / 顺序 / 快捷键」，即命令元数据；导航和常用功能列表都是它的投影。命令 id 是唯一能把 UI、设置、快捷键、日志、错误归因串起来的稳定标识。

## 判据

1. **一切会改变 PS 文档、PS 应用状态或用户资产的操作，必须定义为命令**，注册在 `src/commands/`。
2. **命令元数据与命令实现分层**：元数据（id / 标题 / 分组 / 图标 / 前置条件 / 类型）与实现体分开；命令实现只做编排，**判定与映射落在领域层与数据层**。
3. **命令执行统一经命令注册表**：前置条件检查 → 执行 → 异常归一 → 日志 + 耗时。
4. **页面、常用页、自定义面板、快捷键只消费注册表**，不各自实现操作。
5. **页面层不写 store**；投影要能被刷新，所以**写入口只在装配层**（装配层负责把读结果写回投影）。
6. **命令 id 是唯一稳定标识**；载荷形状从命令实现导出，**不另建一张 id→载荷映射表**（那张表会变成第二个命令真相）。

**唯一入口**：命令形状与元数据 = `src/commands/types.ts`；执行 = `src/commands/registry.ts`；命令实现 = `src/commands/`。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 页面 / store 里出现不经命令注册表的副作用操作 | 同一功能多份实现，行为不可统一 |
| 命令实现里塞判定与映射 | 业务逻辑漏进命令层，命令体越长越不可复用 |
| 为同一能力另建一张 id→载荷映射表 | 第二份命令真相，命令增删要改两处 |
| 页面自己写 store 字段 | 页面绕过投影边界 |
| 命令 id 与载荷形状各写一份 | 形状与命令不同源，加命令必漏改 |

**代价**：新增功能至少两个文件（命令定义 + 实现），比「直接在组件里写方法」多一步。

**什么时候推翻**：不推翻。命令总数长期少于 10 时不必引入注册表（现在已经超过）。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：页面或 store 里出现不走命令注册表的副作用操作；或命令实现里长出判定与映射；或出现第二个命令真相表。
