# ADR-0024 · 缺了先补生产者：禁消费侧转型 / 默认值 / 猜字段

- **状态**：生效
- **结论**：缺了先补生产者：禁消费侧双转型/默认值/猜字段，第三方边界先写类型声明，不可达生产者只留一处适配层。
- **日期**：2026-10-23（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：T-97-8 真机 bug：消费侧把 Promise 当对象用，分支恒为 none
- **执行方式**：本 ADR 的判据由 `npm run lint` 的受限语法规则执行（原先的独立断言脚本与基线文件已删）；结论本身不变。

## 背景

T-97-8 是一个真机 bug：消费侧把一个 Promise 当对象用，分支恒为「无」，**点了没反应、不报错、测试全绿**。修法是改生产者签名，不是改断言。

根因不是某一处写错，是**消费侧被允许补东西**：补字段、补默认值、补转型 —— 于是编译通过、运行出错、错误归因不到任何人。

## 判据

1. **发现类型 / 字段 / 返回值 / 契约缺了，去补生产者**（改签名、改类型、改实现、改契约），**不改消费者的断言**。
2. **消费侧禁止三件事**：双转型；用默认值补缺字段；按形状猜字段。
3. **唯一例外是第三方边界**（宿主注入对象、环境变量、注入的 require）：先写类型声明 / 全局声明让类型存在，实在补不了才在调用处转型，且必须写明断言理由。
4. **生产者物理上不可达时**（原厂脚本），归一收口在**单一适配层**，只许一处，并标注未验证；不许在每个消费点各补一份。
5. **读原语本身就是一类生产者**：它交出的形状决定消费侧有没有「补」的机会。交两态时，消费侧除了补默认值无路可走 —— 这不是消费侧的错，是生产者没给足（读层的形态见 ADR-0026）。

**唯一入口**：适配层 = `src/domain/font-normalize.ts`（字体归一）与 `src/utils/jsx-result.ts`（原厂脚本结果判定）。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 消费侧双转型（两次类型断言） | 两次撒谎，形状错也能过编译（T-97-8 原案） |
| 转型 + 默认值叠用 | 两层捏造 |
| 按形状猜字段再补默认值 | 猜 + 兜底 |
| 消费侧给生产者没保证的字段补空值 | 缺字段该让类型保证有 |
| 为绕开类型去抑制检查 / 放宽严格模式 | 比转型更坏：全局失效且不会红 |
| 每个消费点各写一份归一 | 归一散开就无法统一 |

**合规做法**：写类型声明 / 全局声明把第三方类型补进去；用数组判定、属性判定、判别联合、类型守卫（这些是证明，不是断言）；在适配层归一一次。

**与既有 ADR 的关系**：ADR-0014 是本条的上游之一（仓库读结果的形状就是「让生产者把坏带出来」，消费侧才不用猜）；ADR-0016 让本条的修复路径成立（命令层是唯一写入口，补生产者签名只需改一处契约）；本条不推翻任何既有 ADR。

**与 ADR-0001 / ADR-0005 的边界**：那两条判据要求原厂脚本不可改、字体两套键名并存，而本条要求「缺了就补生产者」—— 原厂脚本这个生产者**物理上改不了**，两条撞死。解法：对不可达生产者退到「补适配层」，且只许一处；那两条的理由仍然成立，边界只写在本条。

**什么时候推翻**：拿到可改的脚本生产者时，「不可达生产者」这条例外消失，归一只留类型、不留适配层。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：`src/` 里新增双转型命中；或消费侧出现用默认值补字段。
