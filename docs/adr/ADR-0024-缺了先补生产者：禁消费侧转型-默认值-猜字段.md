# ADR-0024 · 缺了先补生产者：禁消费侧转型 / 默认值 / 猜字段

- **状态**：生效
- **结论**：缺了先补生产者：禁消费侧双转型/默认值/猜字段，第三方边界先写 .d.ts，不可达生产者只留一处适配层。
- **日期**：2026-10-23（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：T-97-8 真机 bug：消费侧把 Promise 当对象用，分支恒为 none
- **执行方式（2026-10-25 更新）**：原 `npm run assert:guard` 与 `断言基线.json` 已删，本 ADR 的判据改由 `npm run lint` 的 `no-restricted-syntax` 执行；结论本身不变（仍禁双转型，仍要求先补生产者）

源文档（`docs/架构/决策记录.md`）本条未单列「背景」段：旧约定与原因写在「决定 / 原因 / 由来」字段里，已随「判据」段逐字搬来。

## 判据（它凭什么成立 / 为什么不成立）

- **决定（判据）**：
  - 发现类型 / 字段 / 返回值 / 契约缺了，**去补生产者**（改签名、改类型、改实现、改契约），**不改消费者的断言**。
  - 消费侧禁止三件事：`as any` / `as unknown as`（双转型）、`?? 默认` / `|| 默认` 补缺字段、按形状猜字段（`(x as { id?: string }).id`）。
  - **唯一例外是第三方边界**（`window.__adobe_cep__`、`process.env`、CE 注入的 `require`）：先写 `.d.ts` / `declare global` 让类型存在，实在补不了才在调用处转型，且必须写 `// 断言理由：…`（守卫 `npm run assert:guard` 认这个标记）。
  - **生产者物理上不可达时（原厂 jsxbin）**，归一收口在**单一适配层**：`domain/font-normalize.ts`（jsx 返回值 → `FontItem`）、`utils/jsx-result.ts`（`res.err === 1` 之类）、`domain/free-panel.ts` 的读边界。**只许一处**，且标 `UNVERIFIED`；不许在每个消费点各补一份。
  - **读原语本身就是一类生产者（ADR-26）**：它交出的形状决定消费侧有没有"补"的机会。交 `string | null` 时，消费侧除了补默认值无路可走——这不是消费侧的错，是生产者没给足（本条的判据落在读层时的形态见 ADR-26）。
- **由来（实证）**：
  - `src/commands/commonUse.ts:547-553`（T-97-8 真机 bug 的现场记录）：数据层 `readCommonUseOptions()` 是 `async` 且返回 `{ value, degraded }`，消费侧写成 `as unknown as Record<string, unknown>` 把 Promise 当对象用，分支恒为 `'none'`——**点了没反应、不报错、测试全绿**。修法是改生产者签名（这里写成 `readOptions: () => Promise<...>`），不是改断言。
  - 现存存量两处（`docs/生成/断言基线.json` 各记 1，只许减不许增）：`src/cep/data/common-use.ts:102` 的 `(file as unknown as { info?: unknown })`、`src/cep/transport.ts:118` 的 `return raw as unknown as T`。
  - 净减实证：`src/cep/data/free-panel.ts:89-92`——`normalize` 接到读边界后，注释直接写"下面每处都可以直接 `value.obj.list`，不再需要 `?./??`"；同一轮 commit `c41cab8` 拆掉 `file-repo` 的 `as T`、删自由面板 7 处 `?./??`，断言基线从 10 处降到 2 处（`f36714b`）。
- **什么算违规**：

  | 写法 | 判定 | 为什么 |
  |---|---|---|
  | `readOptions() as unknown as Record<string, unknown>` | 违规 | 两次撒谎，形状错也能过编译（T-97-8 原案） |
  | `(res as any).data ?? []` | 违规 | 转型 + 默认值，两层捏造 |
  | `(payload as { id?: string }).id ?? ''` | 违规 | 猜字段 + 兜底值 |
  | 消费侧 `item.icon ?? ''` 补一个生产者没保证的字段 | 违规 | 缺字段该让类型保证有 |
  | 为绕开类型去 `@ts-ignore` / `eslint-disable` / 放宽 `strict` | 违规 | 比转型更坏：全局失效且不会红 |
  | 写 `.d.ts` / `declare global` 把第三方类型补进去 | 合规 | 让类型存在，比转型根本 |
  | `(window as unknown as { require?: ... })` + `// 断言理由：…` | 合规 | 第三方边界，已登记 |
  | `Array.isArray` / `in` / 判别联合 / 类型守卫 | 合规 | 这些是证明，不是断言 |
  | jsx 返回值在 `domain/font-normalize.ts` 归一一次 | 合规 | 生产者不可达时的唯一适配层 |

- **与既有 ADR 的关系（真冲突，解法写在本条）**：
  - **与 ADR-01 / ADR-05 判据互斥**：ADR-01 决定"PS 能力继续用原厂 jsxbin、不逆向不重写"，ADR-05 决定"两套键名并存、靠 `normalizeFont()` 转换"——按本条字面要求"缺了就补生产者"，jsxbin 这个生产者**物理上改不了**，两条判据撞死。解法：本条对**不可达生产者**退到"补适配层"，且只许一处（`domain/font-normalize.ts` / `utils/jsx-result.ts`）。**ADR-01 / ADR-05 正文不改**，它们的理由仍然成立；边界只写在本条，避免同一件事在两处各长一份。
  - **ADR-14 是本条的上游之一**：`RepoRead` 的 `{ value, degraded? }` 形状就是"让生产者把坏带出来"，消费侧才不用猜。
  - **ADR-16 让本条的修复路径成立**：命令层是唯一写入口，补生产者签名只需改一处契约。
  - 本条不推翻任何既有 ADR。
- **与硬规则 20 的关系**：本条是判据面（判据顺序：先补生产者 → 第三方写 `.d.ts` → 才允许带理由转型），硬规则 20「规矩一：禁双转型」与 (a) 条是执行面；基线文件 `docs/生成/断言基线.json` 是执行面的度量，只许减。
- **什么时候推翻**：拿到可改的 jsx 生产者（与 ADR-01 的推翻条件同一个），届时"不可达生产者"这条例外消失，归一只留类型、不留适配层。
