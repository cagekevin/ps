# ADR-0006 · 不引入 CSInterface.js

- **状态**：生效
- **结论**：不引入官方 CSInterface 库：自写薄封装，官方库千行级且脚本执行没有 Promise 化与超时。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：只需要脚本执行 / 取系统路径 / 事件三样

## 背景

实际只需要三样能力。官方库千行级，而它的脚本执行接口既没有 Promise 化也没有超时 —— 这两条恰好是我们最需要的。

## 判据

1. **自己写薄封装，不用官方 CSInterface 库**。
2. 只实现需要的三样：脚本执行 / 取系统路径 / 事件。

**唯一入口**：薄封装 = `src/cep/transport.ts`（判据见 ADR-0002）。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| `src/` 下出现官方 CSInterface 的 import | 千行级依赖，换不到 Promise 化与超时 |
| 以「官方库更省事」为由引入它 | 需要它独有能力时先回来改本条 |

**代价**：宿主事件（选区变化、宿主消息）以后要自己实现。

**什么时候推翻**：需要大量宿主事件时，可以引官方库只取事件部分。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：`src/` 下出现官方 CSInterface 的 import。
