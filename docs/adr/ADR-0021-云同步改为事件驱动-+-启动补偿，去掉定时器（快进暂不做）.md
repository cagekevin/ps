# ADR-0021 · 云同步改为事件驱动 + 启动补偿，去掉定时器（快进暂不做）

- **状态**：生效
- **结论**：云同步改为事件驱动 + 启动补偿，去掉定时器；触发点只改队列状态，请求由队列统一调度。
- **日期**：2026-10-23（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：长周期自链定时器不是同步机制，且被页面隐藏拦掉一半

## 背景

本项目的通道是**自建整包快照上传**，不是原版的分片按文件上传 —— 原版 3 秒防抖成立的前提是「每次只传一个变更文件」，在整包上传下 3 秒会把服务端和 JSON 打爆，所以 60 秒是通道决定的，不是偏好。

宿主面板是寄生在 PS 进程里的页面，**PS 一关整个脚本上下文就没了**，不存在「关掉之后还继续同步」的物理可能。因此「每 2 小时同步一次」从来不是同步机制，而是「面板活着时的自链定时器」，且被页面隐藏拦掉一半。

真正决定可靠性的不是频率，而是**启动补偿**：面板打开后做一次全量扫描，由按单元的三方比较决定推哪些。**它不读「推送失败留下的痕迹」** —— 那是痕迹，不是触发源。

## 判据

1. **同步不再由定时器驱动**；去掉长周期自链定时器。
2. **触发点统一为五个，且它们不是同一种意图**：
   - 各仓库的变更回调 → 入队等待（防抖 60 秒，最大等待 5 分钟）；
   - 面板启动、页面变可见 → 全量扫描意图（所有单元过一遍，逐个做拉取 → 三方比较 → 推送）；
   - 页面变隐藏 → 有脏才推，没脏一个请求都不发；
   - 手动上传 / 下载 → 立即执行，不防抖、不退避、不被丢，与自动那一轮共用同一条串行链。
3. **五个触发点自身都不发请求，只改队列状态**；请求一律由队列统一调度发出。
4. **判定是按单元的三方比较**（基线 / 本地 / 云端）。单机是主场景，比较自然退化为「本地对基线」。
5. **不加「推送后回读校验」**；**双方都改 = 冲突，永不自动合并**（单元内部从无字段级合并，强行合并就是静默丢数据）。
6. **页面可见性当信号用，不当禁止用**。
7. **自动快进（本地干净就拉云端）不做**。

**唯一入口**：队列与意图 = `src/cloud/change-sync.ts`；接线 = `src/cep/cloud/setup.ts`；比较与推送 = `src/cloud/engine.ts`。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 出现定时自链的周期同步 | 不是同步机制，且会被页面隐藏拦掉一半 |
| 触发点直接发请求而不入队 | 请求频率不可控，且失去防抖与最大等待 |
| 推送、拉取、手动三条路径各有一套比较判据 | 同一「双方都改」在三条路径口径不同 |
| 双方都改时自动合并 | 静默丢数据 |
| 把「推送失败留下的痕迹」当触发源 | 痕迹不是触发源 |

**代价**：PS 关闭期间不同步，且无法解决 —— 除非将来有后台执行能力。拉取后再推送的窗口里多机并发仍可能互相覆盖（服务端不做租约），**接受这个风险**，靠「冲突可见」兜底，不靠回读校验。

**什么时候推翻**：拿到可入库的后台执行能力时，「关闭期间不同步」这条代价消失；若通道换成按文件分片上传，防抖可下调。

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：出现定时自链的周期同步；或触发点直接发请求而没有入队；或同一种比较在多条路径各写一套。
