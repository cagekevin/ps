# ADR-0014 · 读可降级但必须标记，写不可降级

- **状态**：生效
- **结论**：读可降级但必须标记让坏可见，写不可降级必须抛；默认不兜底，兜底只许落渲染层。
- **日期**：2026-10-22（取自源文档状态索引「定于」列，未逐条 git log -S 复核）
- **裁定人**：UNVERIFIED（源文档未记每条裁定人）
- **触发**：两处原始事故：读失败拿假数据顶上、写失败被吞

## 背景

面板里没有「刷新页面」，读失败用兜底能保住可用性；但兜底一旦不可见，用户会照着错数据做决定。写的是用户资产（收藏、标签、动作库、样式库），静默失败等于丢失，且无法事后补。

## 判据

1. **读可降级，但必须标记。** 读失败可回退默认值，但降级信号必须回到调用方，界面要显示「数据不可用」，**不许用假数据冒充真数据**。
2. **写不可降级。** 写失败必须抛，必须被反馈通道看见，必须进日志。宿主里没有 Node 时：读可以走原厂脚本，**写必须抛「没有 Node」，不许退回内存态**。
3. **默认不写异常捕获。** 异常往上走：命令层由命令注册表统一归一，渲染期由错误边界接。必须捕获时只有三条出口，至少命中一条：① 记日志后继续抛；② 降级并返回带可显示的降级标记；③ 转成带原因的领域错误重抛。**禁止静默吞**：错误消失，用户与日志都不知道。
4. **默认不兜底。** 缺文件就报缺文件，解析失败就报解析失败，字段没有就让生产者保证有。确需兜底的只有一种前提：不兜底就白屏或崩溃；此时必须同时带可见失败信号，并把降级写进返回结构或界面（空态文案 + 重试）。
5. **兜底只许落在渲染层**（空态 + 说明 + 重试），**不许落在数据层与语义层**（假数据、默认值、猜的字段让流程继续走）。
6. **捕获只包会抛的那一行**（解析 / IO / 第三方调用），不包整段流程 —— 包大了会把无关错误并进同一条分支。

**边界**：「显示还没有…」只在**能区分「读不到」与「没有这份数据」**时合规 —— 把坏了说成空的是谎；首次使用显示空态是真话。判别手段见 ADR-0026。

**禁止清单**

| 禁止 | 为什么 |
|---|---|
| 读失败处没有降级标记 | 用户会照着错数据继续操作 |
| 写失败被捕获后吞掉 | 写的是用户资产，静默失败等于丢失 |
| 静默捕获后返回默认值（无日志、无降级标记） | 错误变成「看起来能用」 |
| 读坏时用假数据或示例数据顶上 | 用户照着假数据做决定（原始事故） |
| 页面捕获后置空值再照常渲染 | 页面替数据层决定「没有就算了」 |
| 写失败退回内存态 | 写不许降级 |
| 用捕获包住整个函数体 | 分支过宽，无关错误被并进来 |
| 消费侧补默认值补生产者没保证的字段 | 缺字段该让类型保证有（判据见 ADR-0024） |

## 决议

决议即「判据」段各条判据本身；本条无独立例外或指向性补充。

## 后果

- 📌 **违反时的判据**：读失败处没有降级标记；写失败被捕获后吞掉；出现静默捕获后返回默认值；兜底落在数据层。
