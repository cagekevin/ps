# 视觉规范

> 字号、图标、图标与文字的组合方式。**写页面之前先查这张表，不要自己定。**
>
> 强制方式：`npm run check` 会拦「裸色值 / 裸字号 / 裸圆角 / 图标裸尺寸」。
> 依据来自原版 CSS 和模板的真实使用频率，不是拍脑袋（见每节的数据来源）。

## 二、图标阶梯

| token | 值 | 场景 | 原版使用次数 |
|---|---|---|---|
| `--icon-2xs` | 9px | 辅助小标、chip 内的勾 | 8 |

| `--icon-2xl` | 24px | 空态、大图标 | 1 |

### 原版有两套图标系统，其中一套是坏的

| 系统 | 用法 | 实现 | 状态 |
|---|---|---|---|
| SVG sprite | `<baseIcon name="#iconchuangjian">` | `<svg><use href="#id">` | ✅ 189 个，已全部抽出 |
| gdaicon 字体 | `<Icon type="Tags">` | `<i class="gdaicon gdaicon-Tags">` | ❌ **原版里就是坏的** |

证据：`Icon` 组件是 Ant Design 的 Icon（源码里 `"gdaicon-" + type` 拼类名），
但原版 CSS 里 `@font-face` 出现 **0 次**、扩展目录里也没有任何 woff/ttf 文件
—— 字体从来没被加载，那些字体图标在原版里应该显示成空白。

**所以：遇到 `<Icon type="xxx">` 的地方，不要照抄，改用 sprite 里对应的图标。**
字体页的打标签图标我们用的是 `iconbiaoqian`，比原版正确。

### 默认规则：1em，跟随字号

原版 `.icon` 的定义是：

```css
.icon { width: 1em; height: 1em; fill: currentColor; color: #c3c3c3 }
```

**图标默认 `1em`，跟着字号走。** 12px 的文字配 12px 图标，16px 配 16px。

所以绝大多数地方**不要传 size**：

```vue
<Icon name="iconbiaoqian" />            <!-- 继承父级 font-size -->
```

只有原版显式用 `class="svg-14"` 覆盖过的地方，才用上表的预设名：

```vue
<Icon name="iconguolv" size="lg" />     <!-- 原版 .gdaicon:nth-of-type(2){font-size:18px} -->
```

> **之前的错误**：我把默认写成了固定 16px，还断言「图标尺寸不跟字号绑定」，然后发明了一套七档阶梯去强行统一。
> 结果是每处尺寸都是我拍脑袋定的，出现「有大有小」。真正的规则是 1em。

用法：

```vue
<Icon name="iconbiaoqian" size="xs" />   <!-- 推荐：预设名 -->
<GIcon name="iconbiaoqian" size="xs" />  <!-- 同上，语义更明确 -->
```

**不要写 `:size="12"`**，`npm run check` 会拦（能自动映射成预设名的会由 `npm run style:fix` 改掉）。

## 三、图标 + 文字

原版的答案是 **flex 容器 + `align-items: center`**（`.f-baseX`），不用 `vertical-align`，不用 `line-height` 硬凑。

### 四种结构

**① 前缀图标**（图标在文字前）

```html
<div class="u-row u-gap-3">
  <Icon name="iconbiaoqian" size="xs" />
  <span>我的标签</span>
</div>
```

**② 后缀图标**（图标在文字后，如下拉箭头）

```html
<div class="u-row u-gap-2">
  <span>全部语言</span>
  <Icon name="iconxiala" size="xs" />
</div>
```

**③ 纯图标按钮**（固定盒子居中）

```css
.icon-btn {
  width: var(--h-control-sm);
  height: var(--h-control-sm);
  display: inline-flex;
  align-items: center;
  justify-content: center;
}
```

**④ 三段式**（图标 | 文字伸缩 | 尾部元素）

```html
<div class="u-row u-gap-2">
  <span class="a-mark">A</span>
  <span class="list-count">全部(259)</span>   <!-- flex: 1; min-width: 0 -->
  <button class="clear-tag">取消筛选</button>  <!-- flex: 0 0 auto -->
</div>
```

### 四条硬规则

| 规则 | 原因 |
|---|---|
| 图标和文字**必须在 flex 容器里** | `<svg>` 是 inline 元素，和文字混排会按基线对齐，底部多出 3~4px 空隙 |
| 图标 `flex: 0 0 auto` | 否则容器变窄时图标被压扁（`Icon.vue` 已内置） |
| 文字 `min-width: 0` + `text-overflow: ellipsis` | 否则长文本撑破容器 |
| 间距用 `gap`，不用 `margin` | 见下节 |

### 图标着色

`fill: currentColor`，跟着父级 `color` 走，hover 自动变色。**不要**引入原版的 `.svgfill` / `.svgColor0-7` 预设色类。

## 四、间距：gap 还是 padding

### 三条规则

| 要解决什么 | 用什么 | 例 |
|---|---|---|
| **兄弟元素之间**的距离 | 父容器 `gap` | 图标与文字、标签之间、工具条按钮之间 |
| **元素自身**的内留白 | `padding` | 列表项左右留白、header 内边距 |
| 把元素推到一边 | `margin: auto` | 只有这一种 margin 合法 |

**禁止用 `margin` 做间距**，三个原因：

1. 相邻元素的 margin 会**折叠**，实际间距不等于写的值
2. 和父容器的 `gap` **叠加**，变成双重间距
3. 最后一个元素会多出空白，得写 `:last-child { margin: 0 }` 收尾

### 场景对照表（右侧是原版真实值）

| 场景 | 属性 | 我们的 token | 原版 | 是否一致 |
|---|---|---|---|---|
| 列表项上留白 | `padding-top` | `--sp-3` 6px | 6px | ✅ |
| 列表项左右 | `padding` | `--sp-4` 8px | 8px | ✅ |
| 列表项名称行 | `padding` | `0 var(--sp-4)` | `0 8px` | ✅ |
| 预览区 | `padding` | `--sp-3 --sp-4` | `6px 8px` | ✅ |
| 页面 header | `padding` | `--sp-4` 8px | 8px | ✅ |
| 图标与文字 | `gap` | `--sp-2` 4px | `margin-right: 4px` | ✅ |
| 标签之间 | `gap` | `--sp-2` 4px | `margin: 4px 4px 0 0` | ✅ |
| 标签 chip 内 | `padding` | `--sp-2 --sp-exact-7` | `4px 7px` | ✅ |
| tab 导航条 | `padding` | `0 var(--sp-exact-10)` | `0 10px` | ✅ |
| 底部工具条 | `padding` | `--sp-exact-3` | 3px | ✅ |

### 三个「精确值」token 的由来

原版的间距不是栅格，高频值里有 5、7、10、15 这些不在 4/6/8 阶梯上的数。
为了不把阶梯撑成十几档，只挑出**有明确还原需求**的三个：

```css
--sp-exact-3: 3px;    /* .hcf__footer padding:3px */
--sp-exact-7: 7px;    /* .tag__content>div padding:4px 7px */
--sp-exact-10: 10px;  /* .tabs__nav padding:0 10px */
```

**规则：优先用 `--sp-1..7`；只有原版有明确像素值且需要还原时，才用 `--sp-exact-*`，并在注释里写来源。**

### 页面左右留白：只有一处来源

```css
--page-pad-x: 8px;   /* = --sp-4 */
```

**规则**：

1. `PageShell` 的 header / toolbar / footer 统一 `padding: 0 var(--page-pad-x)`
2. 页面内的区块（搜索行、标签行、列表头）**不再写 `padding-left/right`**，只写上下
3. 列表项因为要全宽 hover 背景，所以**它自己**用 `padding: var(--sp-3) var(--page-pad-x)` 对齐内容
4. 组件内部禁止用 `margin-left/right` 做间距，兄弟元素一律 `gap`

**反例（改之前的字体页）**：

```css
/* 4 个区块各写一遍 8px，列表项左侧还是 0 —— 内容直接贴边 */
.search-row { padding: 8px; }
.tags       { padding: 0 8px 8px; }
.list-head  { padding: 0 8px; }
.font-item  { padding: 6px 8px 6px 0; }   /* ← 左边 0 */
```

改成：

```css
/* PageShell 给 8px；区块只管上下 */
.search-row { padding: 8px 0; }
.tags       { padding-bottom: 8px; }
.list-head  { /* 什么都不用写 */ }
.font-item  { padding: 6px var(--page-pad-x); }
```

判断方法：**如果某个区块的左右 padding 值和其他区块一样，那它就不该自己写。**

### 间距阶梯（token 表）

| token | 值 | 用途 |
|---|---|---|
| `--sp-1` | 2px | 极紧（图标与徽标） |
| `--sp-2` | 4px | 图标与文字、chip 之间 |
| `--sp-3` | 6px | 分组标题、菜单项内 |
| `--sp-4` | 8px | 区块内边距、工具条 |
| `--sp-5` | 12px | 区块间距 |
| `--sp-6` | 16px | 大区块 |
| `--sp-7` | 24px | 空态、页面级留白 |

> 原版**没有栅格系统**：padding/margin 的高频值是 5px(37次)、10px(37次)、4px(34次)、15px(24次)、6px(21次)、8px(18次)，
> 4 的倍数只占 29%。我们收成 4/6/8 是为了节奏统一，代价是与原版差 1~2px。

布局用 `u-gap-1..6` utility，不要写 `margin-right`。

## 四点五、状态规范

**这套设计没有统一 hover 色。** 每类元素在原版里规则都不同，必须逐类查 `app.bf68b505.css`。

### 逐元素对照（原版实测值）

| 元素 | 状态 | 原版 CSS | 表现形式 |
|---|---|---|---|
| 左侧导航 | hover / active | `background:#4b4b4b; border:1px solid #6e6e6e; border-radius:4px` | 背景 + 边框 |
| 左侧导航 | active 图标 | `color:#fff` | 图标变白 |
| 列表行 | hover / 选中 | `background:#424242` | 背景 |
| 列表行 | hover 操作区 | `display:flex` | 显示 |
| 标签 chip | hover / 选中 | `border:1px solid #759fff` | **只变边框** |
| 字重 chip | 选中 | `border:1px solid #6e6e6e` | 只变边框 |
| 星级 | 选中 | `color:#b3b3b3` | 只变图标色 |
| 预览档位卡 | hover / 选中 | `color:#fff; background:#3565ff` | 背景 + 文字 |
| 底部图标按钮 | hover / active | `background:rgba(0,0,0,.25); border:1px solid hsla(0,0%,100%,.2); border-radius:4px` | 背景 + 边框 |

### 四条规则

1. **写状态前先搜原版选择器**：`:hover` / `:active` / `--active` 三种都要搜，别只搜一个。
2. **原版没有的不要加**。例如星级只有选中变色、没有 hover；筛选按钮原版无 hover 规则。自己加就是"和原版不一样"。
3. **active 与 hover 常是同一条规则**（导航、底部图标、标签都是），写在一起。
4. **布局不能因状态变化而抖动**。原版靠 `max-width: calc(100% - 60px)` 给操作区预留位置，不是靠常显。

> 反例（都犯过）：导航 active 写成 `#222` 底 + 蓝色图标；标签选中额外改文字色；操作区改成常显 opacity；底部图标 hover 用了 45% 黑底 + 10% 白边。

## 五、三处故意不照抄原版

| 原版做法 | 我们 | 理由 |
|---|---|---|
| `margin-right: 5px` 出间距（`gap` 用了 0 次） | `gap: var(--sp-3)` | ① 原版连 `var(--)` 都是 **0 次**，属当年写法习惯（具体原因无法从代码证明）② margin 会在最后一个元素留空白，还得 `:last-child` 清零 |
| 间距 5/10/4/15/6/8 混用 | 4/6/8 三种 | 统一节奏；代价是与原版有 1~2px 差异（原版 5px 用了 37 次、10px 37 次，我们对应 4 和 8） |
| `.svgfill` + `.svgColor0-7` 八个预设色类 | `fill: currentColor` | 预设色类只能用在固定场景；`currentColor` 跟着文字色走，hover 自动变 |

这三条已记入 `docs/架构决策.md` ADR-13。

## 六、常见错误

```vue
<!-- ✗ 图标裸尺寸 -->
<Icon name="iconbiaoqian" :size="12" />

<!-- ✗ 用 vertical-align 对齐图标和文字 -->
<span style="vertical-align: middle">文字</span>

<!-- ✗ 用 margin 做图标间距，最后一个会多出空白 -->
<Icon style="margin-right: 6px" />

<!-- ✓ -->
<div class="u-row u-gap-3">
  <Icon name="iconbiaoqian" size="xs" />
  <span>文字</span>
</div>
```
