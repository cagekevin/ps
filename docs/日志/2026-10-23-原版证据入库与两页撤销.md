# 2026-10-23 · 原版证据入库与两页撤销

> 原版源码搬进 `docs/原版/`；`/custom`、`/commonUse` 撤销回占位，按一手源码重做

## 背景

`/custom` 与 `/commonUse` 落地后发现与官方偏差很大。诊断时暴露出真正的问题不在 UI：
**原版源码一直在仓库目录外**（`../reference/`），而仓库里只有二手调查结论，
于是这两页的 PS 能力层是**按文档猜出来的**——

- 四个 `zdy_*` 全被塞成「一个 request 对象」入参；官方实际是
  `zdy_checkStatus` / `zdy_checkMergeRectangles` **无参**、`zdy_mergeRectangles` 传 `[]`、
  `zdy_generate` 传 `[n]`（`app.v4.js:35281,17066,17076,35292`）。
- 九个 `cy_*` 里至少四个名字是错的：`cy_customTransform`→`cy_customBuildTransform`、
  `cy_referenceLine`→官方无此名、`cy_distribute`→`cy_distributedByPitch`、`cy_flipLayer`→派发表里没有。
  权威名单就在 `app.v4.js:17058` 一行 switch + `17061-17184` 的调用封装里。
- `/commonUse` 唯一属于自己的数据 `sj_commonFunction.json` **从未实现**（`目标架构.md` 写归属 `data/commonUse.ts`）。

结论：**没看到一手源码就动手，等于把猜测当事实**。这条已经在本仓库返工过多次（`AGENTS.md` 第 14 / 19 条就是为此写的），
上一次的规避方式是「标 `UNVERIFIED`」，但它只让错误可被发现，不阻止错误发生。

## 为什么

- **搬而不是引用**：引用仓外路径意味着结论的有效性取决于"手上有没有那份资料"，
  这正是这两页猜错的直接原因。搬进来后任何"官方是怎么做的"都能当场 `Select-String` 复核。
- **不全删**：`/freePanel` 已冻结且在跑，它的执行链依赖 `commonUse.*` 命令 id。
  撤销页面 UI 与撤销能力层是两件事，混在一起会顺手打断一个正常页面。
- **代价**：仓库多约 22 MB，且多了一份"不许改"的目录（已写进 `docs/原版/README.md`）。

## 这次为什么没一次对（只在返工时填）

**搜索那一条没做**（AGENTS「写代码前三个动作」动作 1）：动手前没有先确认「原版源码在不在仓库里」，
