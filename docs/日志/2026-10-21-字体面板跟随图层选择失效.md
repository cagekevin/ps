# 2026-10-21 · 字体面板跟随图层选择失效

> 根因不是事件 ID、不是读取函数，是 `callbackInstalled` 先置位后安装，第一次失败后永久不再挂监听。

## 背景

字体面板打开时能读到当前文字图层的家族/字号/字重，但在 PS 里用鼠标切换文字图层，面板不跟随。原版行为是：`slct` 等四个 PS 事件 → `selectLayer()` → `zt_getFontSimpleInfo`。

现象很容易被误判成“读取函数有问题”，因为打开面板那一次读是成功的。

## 最终根因

`src/cep/events.ts` 的 `ensureCallback()`：

```ts
if (callbackInstalled) return
callbackInstalled = true          // ← 先置位
onPhotoshopCallback(...)          // ← 后安装
```

第一次调用如果 `window.__adobe_cep__` 的监听条件还没就绪，`onPhotoshopCallback` 内部返回 no-op，但 `callbackInstalled` 已经是 `true`。后面 `startTextInfoWatch` 再注册四个事件，全部走“已安装”分支，**回调监听永远不会再挂**。

表现：

- 事件注册日志“注册完成”；
- 打开面板时手动 `zt_getFontSimpleInfo` 成功；
- 鼠标切换图层没有任何 `收到 PS 回调`；
- 没有任何报错，因为注册本身是成功的。

修法：先检查 bridge / extensionId，真正安装监听成功后再置 `callbackInstalled = true`，并打 `回调监听已安装`。

## 两小时里走过的弯路（按顺序）

### 1. 先怀疑读取链路

改了：

- `refreshTextInfo` 前 `await initJsx()`；
- `size` 数字 → 字符串；
- `asJsxResult` 拆双层 JSON；
- `normalizeTextInfo` 兼容嵌套 `fontInfo`、数组颜色、带单位字符串。

这些修的是**打开面板首次读取失败**的真实问题，但与“切换图层不跟随”无关。因为首次读已经成功，问题在事件触发，不在这条链路。

### 2. 怀疑事件 ID

把 `charIDToTypeID("slct")` 改成原版写死的十进制：

```
1936483188 / 1416785510 / 1298866208 / 1936028772
```

注册日志正常，仍然没有回调。

### 3. 怀疑 dispatchEvent 参数形态

查了 `CSInterface.dispatchEvent`：它把 `CSEvent` **对象**直接传给 `window.__adobe_cep__.dispatchEvent`，不是 JSON 字符串。于是从 `JSON.stringify(event)` 改成对象。

同时试了 `appId` 空串、`addEventListener` 第三参 `false` 等差异。都没有解决。

### 4. 怀疑注册时机

原版在 `created` 里 `openPsEvent()`，`mounted` 里延迟 600ms 读属性。我们原来把 `startTextInfoWatch()` 放在 `await store.load()` 之后，于是改成 `onMounted` 第一步先订阅。

这是正确的顺序修正，但不是本次根因。

### 5. 删除兜底，让失败可见

删掉了：

- `getExtensionID` 大小写兜底；
- `parseEventData` 的 `indexOf('{')` / 解析失败返回 null；
- 双层 JSON 拆包；
- 嵌套 `fontInfo` / 数组颜色 / 带单位数字的归一化；
- `inflight` 合并与尾随刷新；
- 注册失败返回 no-op。

这一步让“注册失败”和“读取失败”不再被吞掉，但仍然看不到“监听没挂上”。

### 6. 加日志 + 面板内日志查看器

在 `ps-event` 和 `selection` 两个 scope 加了：

- `订阅宿主事件`
- `开始注册 PS 事件`
- `PS 事件注册完成`
- `收到 PS 回调`
- `分发宿主事件`
- `开始读取文字属性`
- `文字属性已更新`

因为 CEP 里用户打不开 devtools，又加了 `DebugLog.vue`：右下角“日志”按钮 / `Ctrl+Shift+L`，带复制。

日志一出来就清楚了：

```
selection 文字属性已更新 {"family":"思源黑体 CN","size":"38.77","weight":"Medium"}
ps-event 订阅宿主事件 {"name":"selection",...}
```

**读取成功，但没有任何 `收到 PS 回调`**。于是从“事件有没有到”倒推到“监听有没有挂”，才看到 `callbackInstalled` 的顺序问题。

## 为什么绕了这么久

1. **没有先拿运行时事实**：一直在读源码、改静态形状，没有先确认“回调有没有到”。
2. **“注册成功”被当成“监听已安装”**：日志只打注册，不打监听安装，误导了判断。
3. **no-op 兜底掩盖失败**：注册失败、监听不可用都静默返回，看起来一切正常。
4. **首次读成功把注意力引向读取链路**：实际上首次读和事件读是两条路径。
5. **一次改多个假设**：事件 ID、dispatchEvent、时机、兜底一起动，无法区分哪一处有效。

## 下次的正确顺序

1. 先加**三段日志**：注册成功 / 监听已安装 / 收到回调。
2. 没有“收到回调”时，先查监听是否真的挂上，再查注册对象。
3. 初始化标志一律**成功之后**再置位；失败不要 no-op。
4. 一次只改一个假设，改完必须有日志或测试能证伪。
5. 打开面板能读到值 ≠ 事件链路通。

## 影响 / 后续

- `src/cep/events.ts`：`ensureCallback` 顺序修正；`dispatchEvent` 对象形态；`addEventListener` 不传第三参。
- `src/components/DebugLog.vue`：面板内日志查看器保留，后续排查可直接用。
- `src/selection/current-text.ts`：事件日志、读取日志；去掉了多层兜底，字段按原版 `fontInfo` 形状取。
- `src/pages/fontSet/index.vue`：事件注册提前到 `store.load()` 之前。

`npm run build` 已通过；用户真机验证“切换图层后属性跟随”成功。

## 同页其它弯路（不属于本次事件链路）

这两小时不只查了事件，字体面板本身还返工了下面这些。它们各自有独立的原版依据，不能混进“事件不跟随”的根因里。

### A. 旧包误判

- 多次拿旧产物截图对比：源码已经改了，扩展目录还是上一次 build。
- 后来固定先比 `src` 与 `%APPDATA%\...\index.html` 的 mtime，再谈现象。

### B. padding / margin

- 误以为原版 `.app-padding` 只有左 padding；实际是 `box-sizing:border-box;padding:0 10px`。
- 根节点 10 + 子节点 10 = 20；原版是各区块自己 10，根 0。
- 6 列预设 `calc(16.66667% - 6px)` + `gap:6px` → 总宽少 6px，右边多空 6px；原版是 `-5px` + `margin-right:6px`。
- 预设底部只写 `padding-bottom:3px`，漏了按钮 `mb8`；原版是 3+8=11。
- 字号/行距两栏之间是 `.setNbsp{width:30px}`，不是 6px gap。
- 样式行是 `f-baseX + f-alignNone`（`space-between`），分隔线 `.verline` 可见，不是 `opacity:0`。

### C. 颜色

- 输入/下拉用了 `--c-input:#2c2c2c`；原版 `base-input/base-dropdown` 是 `#222`。
- 预设/层级按钮用了 `#2c2c2c`；原版 `btn-small/btn-2` 走全局 `button`，是 `#535353`，hover `#444`。
- 层级数字输入用了 `#2c2c2c`；原版 `hierarchy-layout-input` 是 `#111`。
- 快选字体行做成深色下拉；原版是透明居中的 `baseOpen`（22px、14px、9px 箭头）。
- 家族输入高度 24；原版 `base-input normal` 是 30。

### D. 图标 / 角标 / 状态

- 自创蓝色选中态；原版 `baseIcon` 选中是 `#222 + #444`，hover 是 `rgba(0,0,0,.2) + #444`。
- 把 `div-vision` 的 `.hover{padding:2px}` 错套到 `baseIcon`。
- 把 `svgWidth 20` 当成按钮尺寸，写成 20×20；按钮默认 26×26。
- 给 `baseIcon` 加 `border-radius` / `transition`；原版没有。
- 角标放右上角、蓝色、9px、旋转 180°；原版是右下角、跟随图标灰、4px（`svg-4`）、不旋转，且是第二个 flex 子项 + `margin-top:12px`，不是绝对定位。

### E. 预设面板开合

- 以为点预设按钮会关闭面板；原版只调 `setFontSize/Leading/Tracking`，不碰 `fontSpacingIstrueArr`，所以不关。
- 以为三个预设互斥；`ztExpandMultiple` 默认 true，三个各自开合、互不影响。
- `ctrlClickFun` 只把 `fontSpacingIstrue = -1`，不清空 `fontSpacingIstrueArr`。

### F. 同页审计修掉的其它问题

- `ErrorBoundary` 没有按路由重置，某页崩过之后切页仍显示旧报错。
- CEP 桥方法名大小写：`getExtensionID` 不存在，实际是 `getExtensionId`。
- MD5 不处理 UTF-16 代理对，带 emoji 的翻译签名与服务器不一致。
- `stores/font-set` 浅拷贝默认值，多个 store 共享嵌套 `ztPasteFont`。
- `FontSetNumber` 拖拽中途卸载，`document` 监听泄漏。
- 字体列表读取失败静默无日志。
- 旧版 `ztOldVersion` 的 ±1/±2、1.1~1.6、-25~100 快捷档漏写。
- 底部第 4 个对齐图标错映射到 `fontAlignHorizontal`。
- 智能排版“对齐”选完不立即应用。
- 预设保存/新建/重命名的成功文案错用“层级预设”。

### G. 排查工具本身的弯路

- 先让用户开 devtools；CEP 里用户根本打不开。
- 加了内存日志但只在 DEV 打 console；生产里看不到。
- 最后才加面板内 `DebugLog.vue` 和复制按钮。
- 复制按钮一开始只走 `navigator.clipboard`，CEP 拒绝后没有 fallback；后来补了 `execCommand('copy')`。

## 这次为什么没一次对

AGENTS「写代码前三个动作」里，**“先取事实”**没做到：没有先确认回调是否到达，就连续改了事件 ID、dispatchEvent 形态、注册时机和解析逻辑。真正缺的事实只有一个——**监听有没有装上**，而这个事实被 `callbackInstalled` 的 no-op 兜底藏住了。
