# 2026-10-21 · 引入 lint

> 官方风格指南 Priority A 原来只靠人记，现在变成 `npm run check` 的一部分。

## 背景

对照 Vue 官方风格指南（Priority A 五条）和性能页做了一次体检。结论：
`v-for` 都有 key、没有 `v-if` + `v-for` 同元素、样式都 scoped、props 都带类型——这些是对的。
真正缺的是**没有任何自动检查**，规则全靠记忆，记忆一定会漏。

顺带发现三个真问题：`mock.ts` / `MainLayout` 绕过 logger 直接 `console`、
`IconFont` 的默认值与联合类型不匹配（规则报，行为没问题）、两处 `any` 没有理由。

## 做了什么

- 装 `eslint` + `eslint-plugin-vue` + `typescript-eslint` + `globals`，写 `eslint.config.js`
- 只开 `flat/essential` + TS recommended；**不引 prettier**（格式已统一，收益低于噪音）
- 基线 10 errors / 3 warnings，全部处理：
  - `console` 改走 `log.*`；logger 自己是唯一出口，加了一行带理由的豁免
  - `no-control-regex`：style-guard 用 `\u0000` 做占位符，注释说明后豁免
  - `require-valid-default-prop`：`IconSize | number` 联合类型推断不出字符串分支，豁免
  - `any`：CEP 的 `require` 桥接层补豁免理由；`globalThis.process` 改成结构化断言
- `Icon` / `Rating` 单单词名、`pages/**/index.vue` 三处豁免，理由写在配置里
- `npm run lint`（`--max-warnings 0`）并入 `npm run check`

## 为什么

规则不落成命令，就等于没有。这次基线只有 13 个问题，说明代码本身是干净的——
但也说明：**如果没有 lint，这 13 个只会慢慢变多，而且没人知道从什么时候开始变多。**

不引 prettier 的理由：格式已经一致，引入会产生一次全仓 diff、持续和 lint 抢格式权，
收益是零。格式化不该和正确性混在一个门禁里。

## 更正：Prettier 也引入了

上文写的"不引 prettier，格式已统一，只会产生一次全仓 diff 和持续噪音"——**这个判断是错的，没测就下了结论**。

实测：按现有风格配置（无分号、单引号、100 列），只有 27 个文件需要改动，
单文件 10-30 行，总量约 300 行。这是**一次提交**的量，不是"全仓重写"。

更关键的是噪音方向说反了：没有格式化器时，每次改动都可能顺手带进空格、换行、引号的漂移；
这些混在逻辑 diff 里的格式改动，才是真正难 review 的噪音。一次性归一化之后，改哪行只动哪行。

已落地：

- `.prettierrc.json`：`semi:false` / `singleQuote:true` / `printWidth:100` / `trailingComma:all`
- `.prettierignore`：排除 `docs/`（中文表格会被重排，改一次覆盖一次，没有收益）、`public/`、产物
- `npm run format` / `format:check`，后者进 `npm run check`
- 已执行一次全量 `--write`，当前 `format:check` 通过

教训和前面几次一样：**结论要先量再下。** 我当时连 27 个文件都没数。

## 影响 / 后续

- 新增代码自动受 Priority A 约束；`Icon` 之类的豁免是有记录的，不是静默通过
- 类型从 `as any` 变成结构化断言后，`fs.ts` 的 Node 边界仍然宽松，但意图可见
- 下一步：T-26（把页面里的筛选管线抽成纯函数）→ T-25（P0 测试）
