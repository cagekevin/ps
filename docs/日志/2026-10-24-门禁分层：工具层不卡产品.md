# 2026-10-24 · 门禁分层：工具层不卡产品

> 门禁拆成产品层与工具层两条：搬一个脚本进来，不再让面板构建变红。

## 背景

从 maomao 仓搬 `scripts/probe.mjs` 进本仓，**产品代码一行没动**，`npm run check` 却红了：
prettier 1 处 + eslint 7 条（`no-control-regex`、两个未用 import、四处 `no-useless-assignment`）。

根因不在搬来的脚本，在**门禁只有一条链**：`lint` = `eslint .`（扫到 `scripts/**`）、
`format:check` = `prettier --check "scripts/!(adr).mjs"`（也扫 `scripts/**`）。
⇒ **往 `scripts/` 放一个文件＝往产品闸里塞一个检查点** —— 工具层有了否决面板交付的权力。

同一轮还暴露一条失效判据：`eslint.config.js` 给 `adr.mjs` / `debt.mjs` / `arch-index.mjs` 的豁免理由写着
「原样拷自 maomao，**下次上游更新就合不回来**」。作者裁定（本仓没有上游，我就是作者）⇒ **这理由不成立**。

## 为什么

**为什么拆两条而不是把 `scripts/` 整个排除**：排除 = 工具层从此无人管（改坏了没人知道）。
拆两条 = **功能坏照样红**（node 非零退出即中断），只是**风格脏不卡交付**。

**为什么判据落点是"功能坏 vs 风格脏"**：门禁的价值 = 拦住会伤到用户的东西。
工具脚本的缩进/引号对用户零影响；它的语法错、逻辑错会让闸失效或误判 —— 那必须拦。

**为什么 `deploy` 不带工具闸**：交付链只回答"面板能不能发"。工具层干净是写脚本的人自己的纪律，
不是发版的前置条件。

**为什么三个历史脚本先豁免不立刻整理**：`adr.mjs` 一次格式化就动 608 行，
混进本次机制改动会让 diff 没法读。**先登记、后整理** —— 但豁免理由必须是真的（"整理中"），不能是假的（"等上游"）。
