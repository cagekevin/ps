# 2026-10-22 · 拖拽机制统一

> 全项目拖拽统一到指针事件 + 300ms 长按，HTML5 DnD 全部废弃（ADR-19 / 台账 T-67）

## 背景

同一个拖拽在项目里有三份实现：

- `/action`：`components/ActionGrid.vue` 提供 `draggable` + `dragstart`/`dragover`/`drop`，页面自己接线（最早，`ed0a94c`）
- `/rename`：照抄动作页那一套（`1c5804c`）
- `/style`：按原版 `am()` 复刻的指针事件版（`a362c76`）

排序数学同样三份：`domain/reorder.ts`、`domain/rename.ts` 的 `reorderGroup`/`reorderItem`、`commands/action.ts` 里的内联 splice（还带同组下标补偿）。

根因不是"没抽组件"——`ActionGrid` 一直是共享组件，但它装的是**错的机制**。动作页最初用 HTML5 DnD 时**没有做过方案权衡**，之后重命名页按「复用第一页已有实现」的规则照抄，错误被正确传播了两次。

## 做了什么

- 三页（`/action` `/rename` `/freePanel`）改用 `composables/useLongPressDrag.ts`，`ActionGrid.vue` 删除 `draggable` 与四个 DnD 事件
- 落点计算三份合一，只剩 `domain/reorder.ts`（`isSameSlot` / `dropInsertIndex` / `applyListDrop` / `applyItemDrop`）
- 动作页项拖拽补 `offsetX: -40`；重命名页保留「第 0 组不可拖」
- 旧 DnD 代码删除约 110 行；整体 288 删 / 504 增
- 新增 9 条测试，删 3 条随旧函数废弃的用例

## 为什么

选指针事件而不是 HTML5 DnD，六维权衡写在 `docs/架构/决策记录.md` ADR-19。核心三条：

1. **拖动中的视觉**：DnD 的拖影是浏览器截的静态图，改不了；指针事件可以克隆 `opacity:0` 占位 + 浮层跟手
2. **长按门槛**：`dragstart` 立刻触发，做不出 300ms；指针事件自己控时机
3. **精确落点**：`drop` 只给目标元素，插前/插后只能靠 class 猜；指针事件自己算布尔

代价：自动滚动容器要自己写（本次未补），边界处理代码量更大。

**"原版这么做"只是候选方案之一的论据，不是决定本身。** 这条已写进 `AGENTS.md` 第 18 条。

## 影响 / 后续

- 手感变化是**行为变化**，不是纯重构：真机上要实际拖一次才算验完，代码层只证明了事件链与数据结果
- 拖拽自动滚动未实现，`useLongPressDrag` 目前只把 `scrollTop` 计入坐标
- `/action` 与 `/freePanel` 在「已完成页面冻结」名单里，本次按**修 bug**（行为不符原版）处理，非视觉迁移——争议记录在台账 T-67

## 这次为什么没一次对（只在返工时填）

三个动作里**「动作 1：先搜一次」做了，但搜到的是错的**：复用前没有确认那份实现本身是否经过选型。已把这条补进 `AGENTS.md` 第 18 条末句——「复用已有实现之前，先确认那份实现本身是否经过选型」。
