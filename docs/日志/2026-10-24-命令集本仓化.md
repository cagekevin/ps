## 背景

`.codebuddy/commands/` 下 23 个 md + 1 个 cjs 是从另一个仓（React 画布项目）搬过来的**工序命令集**：
写码、排查、架构、审计、治理各一套。搬过来时**只搬了文件，没搬口径** —— 于是每篇命令里的
层名（`src/core` / `src/adapters` / `src/ui`）、门禁命令（`lint:boundaries` / `test:affected`）、
工具脚本（`mv-sync-refs.mjs` / `probe.mjs`）、文档真源（`docs/11-架构与契约定稿.md` /
`docs/DATAFLOW.md` / `docs/判据登记表.md`）**全部指向本仓不存在的东西**。

这些命令是"下一轮开工入口"级别的资产（写码 / 排查 / 审计都从它们起步），照着不存在的路径查，
等于让下一个 AI 在门口就开始扑空 —— 与 2026-10-24 那次「账本迁移漏改 `AGENTS.md`」是同一类病：
**搬了内容，没搬口径**。

## 为什么

**为什么整体重写而不是逐句替换**：外仓命令里的判据、案例、门禁**是成套的** —— 只换路径会留下
"用本仓的门禁命令去查外仓的问题"，读起来更糊涂（能跑、但查不到东西）。
按"**保留方法骨架、替换判据来源与证据**"处理：七步 / 六闸 / 四零一毁 / 十问 / 速查表 / 自检清单
一条没删，删的只有外仓案例与失效路径。

**为什么案例要换成本仓真实债号**：案例是命令的**证据层**。外仓的 `TD-16-108` 在本仓查不到，
读者无法复算；本仓的 `TD-08-12`（一行小图标按钮两份）、`TD-09-3`（读盘失败被当成没有）
都能在 `daily/架构日志/债务.md` 里查到原文。

**为什么"本仓没有 X"要显式写出来**：删掉旧工具名而不给替代，命令会变成"少了点什么但说不清"；
写明**没有 + 替代口径**，下一轮才不会去找那个不存在的脚本。
