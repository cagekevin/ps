# 2026-10-21 · 工作流收敛

> 一份状态只写一处：进度管现状、台账管待办、对齐清单管验收。

## 背景

同一件事在四个文件里各写一份：`状态/进度.md` 的页面表与「下一步」、`状态/台账.md` 的条目、
`字体管理页-对齐清单.md` 的待办、`log/index.md` 的摘要。结果是：

- `状态/进度.md` 里 `/fontManage` 出现两次，一次「可用」一次「占位」；「下一步」还停在 T-01/T-02
- `状态/台账.md` 的 T-03 是 `doing`，但它拆出来的 T-10/11/12 全部 done
- `对齐清单.md` 自带的 7 条待办没有 id、不在台账里，其中 4 条其实已经改完（计数行独立、导航底色、激活白图标、去 PS 徽标），
  还有 1 条（家族名 `#ccc`）与源码 `#f5f5f5` 相反——都是当初截图目测的结论
- `AGENTS.md` 的必读顺序编号到 6 之后又回到 4，两个「14」条；自检命令和 `package.json` 对不上

## 做了什么

- **文档分工表**进 `AGENTS.md`：规范 / 进度 / 台账 / 验收清单 / 横切能力 / 日志，各写什么、不写什么
- `状态/进度.md` 重写：只保留页面状态（占位 / 可用 / 验收完成）+ 基础设施；「下一步」改成挑选规则，不写死任务 id
- `状态/台账.md` 重排为三段：可开工（按推荐顺序）/ 已完成归档；T-03 改 done；新增 T-23 承接对齐清单遗留
- `对齐清单.md` 降级为验收记录：待办章节改成「遗留 → T-23」，并列出 4 条作废旧待办及原因
- `AGENTS.md` 修编号、补「收工三件事」、自检改成 `npm run check` + `npm run deploy`
- `README.md` 补全命令表和「先看哪份文档」

## 为什么

不是文档写得少，是**同一事实有多个副本**。副本之间没有同步机制，靠人记，必然漂移；
漂移之后又没人敢信文档，于是每轮都重新翻代码、重新问一遍已经查过的事——
这就是「工作乱七八糟」的实际成本。

选「职责切分 + 单一副本」而不是「加一个自动同步脚本」：同步只能同步格式，
判断不了哪边是对的；而切分之后，每份文档只有一种内容，过期也只会局部过期。

代价：改完一条活要手动搬行（台账可开工 → 已完成）。这个动作有 `npm run ledger` 兜底。

## 影响 / 后续

- 新增页面时，`状态/进度.md` 加一行即可；验收清单按页建，且**只能指向台账 id**
- 台账的「可开工」排序是手动的：依赖完成后需要把行往上搬，别只改状态
- 对齐清单里仍有待定案项（数量徽标、筛选角标、家族名色值），归在 T-23

## 更正（同日，核准原版后）

上面「背景」和手写的对齐清单里有三处结论是错的，已改：

1. **搜索框**：原版 Search 内部是 G-UI `Input`（`.base-input` 30px / 5px），30/5 本来就是对的；`tokens.css` 里那条 `--h-search: 28px` 是废弃值，已删

教训：清单里的「原版」如果没写选择器，就等于没依据。这条已写进 `AGENTS.md` 第 16 条。
