# 测试规范

> 目的：把"能不能用"拆成**能机器判定的部分**，不追覆盖率，不写无信号测试。
> 前提：禁止 e2e（不开浏览器、不点真实面板、不做像素 diff）；用户不参与验证。
> 手段：`vitest` + `@vue/test-utils` + `jsdom`，全部在 Node 里跑。

## 一、测试点从哪来（不是拍脑袋）

每个待测对象只问四个问题，答案就是测试点：

| 对象 | 四问 |
|---|---|
| 纯函数 | ①空 / 异常输入 ②两套键名或两种形状 ③边界（0、1、上限、超长） ④错误文案/回退值 |
| 组件 | ①三态（加载 / 空 / 错误） ②用户每个操作 emit 什么 ③数量边界 ④失败或禁用路径 |
| 组合式函数 | ①首次加载 ②追加加载 ③出错与重试 ④销毁/重复调用 |
| store | ①成功路径 ②失败回滚 ③校验（空/重名） ④并发或重复点击 |

**来源必须是既有文档**，不是"想到哪测哪"：

- 组件清单 → `docs/页面/0N-<页面>.md` 的「组件展开」
- 值与原版 → 同文件的「已定案值」
- 交互 → 原版 render 里的 `on:`（`08-模板` 的 render 源码，注意文件名错位，见 D-10）
- 状态分支 → 页面里的 `v-if` / `v-else-if` 链

## 二、三层，做什么、不做什么

| 层 | 工具 | 测什么 | 明确不测 |
|---|---|---|---|
| 静态 | `vue-tsc`、`check`、`ledger` | 类型、样式硬编码、账本依赖 | 行为 |
| 组件（本规范主体） | vitest + jsdom | 纯函数、组件 props/emit/DOM 语义、store 逻辑、`cep/` 边界 | 布局、滚动、坐标、CSS 生效、字体渲染 |


### jsdom 的硬边界（拿它测这些 = 假测试）

- 没有布局：`offsetWidth`、`getBoundingClientRect`、`scrollTop`、绝对定位坐标全是 0
- 没有样式：`getComputedStyle` 不解析 `tokens.css` 的变量继承
- 没有 IntersectionObserver / ResizeObserver 的真实触发（只能手动 stub 回调）
- 没有字体：中英文字形差异测不出来
- 路由 `push` 只验证路由表，不验证真实导航

所以**不要**写"看起来在左边""高度 24px""滚动到底加载"这类断言。

## 三、优先级（按后果排，不按代码量）

| 级别 | 判据 | 范围 |
|---|---|---|
| **P0** | 出错 = 白屏 / 丢数据 / 静默失败 | `normalizeFont`、`evalScript` 超时与错误码、`describeCepError`、`jsonFile` 读写与备份、`usePagedList` 加载/错误、标签 CRUD 回滚 |
| **P1** | 出错 = 用户看到的结果不对 | 筛选管线（搜索 + 标签 + 面板）、TagMenu 提交语义、PreviewSetting/PreviewText 的 emit、FontWeight（已测）、Rating（已测） |
| **P2** | 出错 = 细节不像 | 关键语义类（`is-active` / `is-disabled`）、契约文案 |

**不做**：覆盖率百分比、全量快照、装饰性 class、动画。

## 四、什么算无意义测试（命中任一条就删）

1. 测的是别人的代码：Vue 的响应式、Pinia 的 store 机制、jsdom 的 DOM 实现
2. 只断言"渲染成功 / 元素存在 / 不为 null"，红了也说不出坏在哪
3. 改内部实现但行为不变就会红（耦合了私有函数名、内部 state、装饰 class）
4. 红了也没有用户可见后果（既不影响结果，也不影响数据）
5. 与另一条用例重复保护同一逻辑（同一个分支测三遍）——**跨层的重复也在此列**，认法见下

### 跨层重复：唯一判据

> **把被测实现改坏一行，红的是几个文件？**
> 两个文件同时红 = 重复；各自因为不同的行红 = 分层。

本仓一个业务横跨 5–7 个测试文件是**正常**的（`.kux` 格式 / 原子写 / 仓库归一 / 命令路由 / 页面接线，各守一种失败模式），**不要按文件数判冗余**。

**页面测试只许断两类东西**：

| 允许 | 例子 |
| --- | --- |
| 页面**产生的输入** | 读到的 `e.ctrlKey` / `e.altKey`、输入框文本、点的是第几个色板 |
| 页面**状态** | 三态（加载 / 空 / 失败）、`is-disabled`、该渲染的项渲染了 |

**一旦断言到下面这些，就是替命令层守门**——删掉这条断言，或把它上移到 `tests/commands/`：

- **payload 的形状 / 编码**（页面拿不到：`useFont.mock.calls[0][0]` 是命令层把磁盘原件编码后的结果）
- **调用次数**（`toHaveBeenCalledTimes(1)`）
- **命令内部步骤顺序**（`checkXxx` 先于 `useXxx`）
- **某个分支被命令层拦下**（`check` 返回 `err=1` → 不再调下一步；`fonts` 为空 → 不入库）

**这个代价必须认**：页面测试 mock 了 jsx、命令走真代码时，「页面 → 命令 → jsx」构成整链验证，命令层改动会让页面测试假红。本仓禁 e2e（`AGENTS.md` A13），这条链只有它能验，**假红接受**。判定它该不该被削，看的是**断言有没有落进上面四个禁区**，不是"它会不会跟着红"。

**实证（2026-10-24）**：`tests/pages/style.test.ts` 里 5 处断言落在禁区（payload 编码 / `useFont` 次数 / `check`→`use` 顺序 / check 失败中止 / fonts 为空不入库），对应分支在 `tests/commands/style.test.ts` 的「style.applyFont」「style.addFont」里已各有一份 → 删掉，73 例 → 69 例。同一轮把「精确 class 列表」`toEqual([...])` 改成逐个 `find('.style-lib--<库名>')`——前者加任何状态类就误红，命中第 3 条。

反过来，**好测试**只满足三点：

- 断言**可观察结果**：返回值 / emit 载荷 / 语义类 / 对外部依赖的调用
- 名字是一句**行为**："点第二颗星 emit 2 且不冒泡"，不是"test rating 2"
- 失败时能直接指出**坏在哪一步**

## 五、文件与命名

```
tests/<源模块>.test.ts        # 一一对应，不嵌套 __tests__
tests/font-weight.test.ts     # 组件：组件名 kebab
tests/classification.test.ts  # 逻辑：模块名
```

- `describe` 用组件/函数名，`it` 用行为句（中文，和项目文档一致）
- 一个 `it` 只验一件事；参数化用 `it.each`，不要在一个用例里塞五组断言
- 需要外部依赖时**显式注入**：`vi.mock('@/cep/ps')`、假 fetcher、`vi.useFakeTimers()`；不读真实文件、不连网络

## 六、完整流程（一条活从进入到结束）

```
1. 台账挑一条（依赖已 done，状态 todo）
2. 事实定案：值 + 出处 → 对齐清单「已定案值」
3. 列测试点：在台账该条的说明里写 3-6 条「要验什么」	← 这一步不写代码
4. 实现
5. 按清单写测试，一条不多写
6. 门禁：vue-tsc + npm run check + npm test
7. 回填证据：测试文件 + 用例名写进台账，然后才允许 done
8. commit：一个 T-id 一次提交
```

**第 3 步是防返工的关键。** 先写"怎么证明它对"，再动手；写不出测试点的需求，说明还没想清楚。

## 八、不做的事（写下来免得又跑偏）

- 不装 e2e、不启浏览器、不点 PS、不做截图对比
- 不追覆盖率数字；P0 全有、P1 主路径全有就够
- 不为"以后可能用"写测试；删代码时同步删测试
- 不用测试代替事实核对：值对不对看 CSS，不看断言
