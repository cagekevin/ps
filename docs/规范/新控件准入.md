# 新控件准入规则

> **这是硬门槛，不是建议。**  
> 没有证据、没有 ASCII、没有用户明确批准，**不准新增控件**。  
> 只写方案，不写代码。
>
> **适用范围：只约束后面的新页面。**  
> 已完成页面冻结，不再为了“统一”回头迁移控件或布局；  
> 已完成页面只修 bug / 数据错误 / 安全问题。

## 最高 ROI：页面契约，不是逐控件审批

逐控件审批成本太高，用户会疲劳，AI 也会拆小绕过。  
ROI 最高的是**每个页面开工前只审一次页面契约**：

```text
页面：/set
参考：官方设置页手风琴
ASCII：
  SettingsPage
  └─ 折叠行 × 7
      └─ 云同步设置
          ├─ 最新更新
          └─ CheckBox

组件清单：
  PageShell
  SettingsSection（缺，需单独批准）
  CheckBox

页面 CSS：
  无。只允许布局 token；不允许按钮/输入框/颜色/字号。

批准：
  USER APPROVED PAGE: /set
```

规则：

1. 一个页面只审一次；
2. 契约里列出的组件才能用；
3. 需要新组件 → 在契约里单列一行，单独批准；
4. 页面 CSS 写“无”，就不能出现页面级颜色、字号、按钮样式；
5. 改结构 = 重新审契约。

这比“每加一个按钮申请一次”有效，因为大多数问题不是单个按钮，而是**整页结构自己发明**。

## 0. 什么叫“新控件”

任一情况都算：

- 新按钮、勾选框、输入框、下拉、菜单、弹窗、折叠行；
- 新的页面级 Section / Row / Toolbar；
- 现有组件无法表达，需要加 `variant` / `size` / 插槽；
- 页面自己写 `.xxx__title`、`.xxx__row`、`.xxx__actions` 这种结构类；
- 页面自己写颜色、字号、圆角、间距。

以下不算新增控件，但仍受 `视觉规范.md` 约束：

- 只改文案；
- 只调已有 token 的间距；
- 只修已有控件的 bug。

## 1. 开工前必须提交的 5 样东西

缺任何一项，任务状态只能是 `blocked`，不能进入编码。

### 证据 1：原版出处

必须给出可核对的路径和行号，或选择器：

```text
文件：docs/原版/01-原版源码/panel/js/app.v4.js
行号：61156-61180
组件：Set / open / baseCheck
选择器：.setTitle / .use-setting-item / .list-hidden
```

不能只写：

```text
“官方大概是这样的”
“看起来像”
“和字体面板差不多”
```

### 证据 2：现有控件排查

必须列出搜过的现有实现：

```powershell
rg "PageShell|SettingsSection|GButton|CheckBox" src
rg "cloud-sync__|setTitle|use-setting-item" src
```

并回答：

- 哪些现成控件可以用？
- 为什么不够用？
- 是缺功能，还是只是“我想换个样子”？

**“只是我觉得这样更好看”不是新增理由。**

### 证据 3：ASCII 结构图

必须画出来，包含层级、间距来源、折叠状态：

```text
SettingsPage
└─ SettingsSection（标题 + 右侧箭头）
   ├─ 收起
   │   云同步设置                              >
   └─ 展开
       云同步设置                              ∨
       ├─ 最新更新：2026-08-04 14:32:01
       └─ [✓] 开启云同步预设
```

页面级布局还要标：

```text
宽：跟随 PageShell
左/右 padding：复用 --sp-exact-10
行高：复用 --h-control-sm
按钮：复用 GButton，不新增
```

### 证据 4：数据流和状态

```text
入口：
状态：
写入：
失败：
空态：
加载态：
```

不能只画静态图。

### 证据 5：用户明确批准

必须是用户原话，且包含控件名或页面名：

```text
同意新增 SettingsSection
同意设置页使用折叠行
```

以下不算批准：

- “好”
- “继续”
- “可以”
- 沉默
- AI 自己推断“用户应该会同意”

没有明确批准 → 不写代码。

## 2. 申请模板

复制到任务或 PR 描述里：

```md
## 新控件申请

### 名称
SettingsSection

### 用途
设置页的可折叠行容器

### 为什么现有不能用
现有 PageShell 只有页面骨架；
现有 GButton/CheckBox 是控件，不是折叠容器；
没有现成的 Section/Row。

### 原版证据
- 文件：docs/原版/01-原版源码/panel/js/app.v4.js
- 行号：61156-61180
- 选择器：.setTitle / .use-setting-item / .list-hidden

### 现有实现排查
- `rg "Section|Accordion|Collapse" src`：
  - 无
- `rg "setTitle|use-setting-item" src`：
  - 无

### ASCII
SettingsPage
└─ SettingsSection
   ├─ 标题 + 箭头
   └─ 内容槽

### 数据流
open: boolean
title: string
slot: content
无网络、无持久化

### 状态
展开 / 收起 / 禁用

### 测试点
1. 点击标题切换展开；
2. 收起时内容不渲染或 v-show；
3. 键盘 Enter/Space 可切换。

### 批准
待用户明确批准。
```

## 3. 批准记录

每次新增控件必须在本文档追加一行：

| 日期 | 控件 | 用户原话 | 结论 |
|---|---|---|---|
| 待填 | 待填 | 待填 | 待批准 |

没有记录 = 没有批准。

## 4. 编码后的验收

- 新控件只在 `src/components/` 或 `src/composables/`；
- 页面不能复制控件样式；
- 页面 CSS 不出现新的颜色、字号、圆角；
- 至少一个页面真实使用，不能先建“以后可能用”；
- 新增控件当次替换旧实现，不能只加不删；
- 测试覆盖用户可观察行为，不测坐标。

## 5. 违规处理

出现以下任一情况，代码不算完成：

- 页面自写按钮/勾选框/输入框；
- 页面自写 `__title` / `__row` / `__actions` 结构；
- 新增控件没有原版证据；
- 新增控件没有 ASCII；
- 新增控件没有用户明确批准；
- 用“视觉统一”当理由，但没有复用现有 primitive。

## 6. 当前设置页的结论

设置页要改成官方手风琴结构，但必须先走本流程：

1. 申请 `SettingsSection`；
2. 证明现有 `PageShell` / `GButton` / `CheckBox` 不能替代；
3. 画 ASCII；
4. 用户明确批准；
5. 才允许写组件和改 `/set`。

在此之前，`/set` 保持现状，不再自行加样式。
