# 2026-10-20 · 横切抽象首次接入

> 字体管理页改用 PageShell + useListPage + usePagedView + useInfiniteScroll，抽象从"未验证"变成"可用"

## 背景

之前建了 5 个 composable / 组件，但字体管理页一个都没用——等于 5 笔未验证的负债。
设计上看着合理不代表能跑，`usePagedView` 缺滚动触发就是典型：写完觉得没问题，接入才发现缺一块。

## 做了什么

- 页面改用 `PageShell`（header / toolbar / body / footer 四段）
- 列表数据改用 `useListPage`，筛选/分页改用 `usePagedView` + 新增的 `useInfiniteScroll`
- `previewMode` 改用 `usePersistedRef` 持久化
- **store 瘦身**：列表、loading、error、keyword、筛选全部移出 store，只在页面里
- 首屏渲染 60 条，滚到底自动加载（原来 259 条一次全渲染）

## 为什么

列表数据是**页面私有**的。放在 store 里，等常用页、字体管理页都要列表时，会互相覆盖状态。

store 只留跨页面真正共享的东西：标签、预览档位、最近应用的字体。

## 影响 / 后续

- 验证方式变了：headless 渲染现在只看到 60 行 + 计数「全部(259)」，不是 259 行
- 三个 composable 组合使用（`useListPage` + `usePagedView` + `useInfiniteScroll`）心智负担偏高，
  下次可以考虑合成一个 `usePagedList`
- `useElementWidth` 仍未使用，等 T-03 双列布局
- 顺手加了 `scripts/verify-dist.mjs`：构建后断言"无 type=module / 有 defer / jsxbin 就位"
