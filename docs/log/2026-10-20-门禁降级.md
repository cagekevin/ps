# 2026-10-20 · 门禁降级

> registry 从门禁改成生成器，style-guard 升级成自动修复，只留 deploy 一个强制点

## 背景

建了三道门禁（registry 校验、style-guard、tsc），但复盘时发现：

- `registry` 防的是"漏登记导致重复造轮子"，这件事**一次都没发生过**
- 它躺在 `npm run check` 里，而没人规定必须跑 check，等于可以被绕过
- `style-guard` 只报错不修复，33 处硬编码要人肉改

## 做了什么

- `style-guard` 增加 `--fix`：从 tokens.css 反查字面值 → 变量名，自动替换。实际清掉 74 处
- `registry` 改成纯生成器：扫描 + 自动补骨架 + 重写文档，不阻塞任何东西
- `build` 只保留 style-guard（99ms），`deploy` = check + build
- 不做 git pre-commit hook

## 为什么

门禁净收益 = `p×L×n×(k−b) − c×n − m`。能被绕过的门禁（`b` 高）净收益接近 0，成本照付。

更关键：同一件事做成「自动修复 / 自动生成」比「报错阻止」便宜一个数量级——前者机器干活，后者人肉改。

还有一条判断：门禁应该**事后建**（基于真实事故）。颜色散落真实发生过一次（30 分钟返工），所以 style-guard 值得留；漏登记没发生过，所以 registry 降级。

## 影响 / 后续

- `npm run style:fix` 之后仍剩 2 处（`_atoms` 演示页），不值得为它加 token
- 修的过程中发现两个映射 bug：`#fff` 和 `#ffffff` 归一化不一致、`--preview-*` 字号没被识别，已修
- 结论写进了 `docs/架构决策.md` ADR-10
