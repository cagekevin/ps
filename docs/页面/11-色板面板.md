> **本文件是施工计划，不是验收记录。** 面板还不存在，所以没有「原版 vs 我方」逐项可比。
> 开工后每完成一刀，把该刀的「验」改成实测结论；全部刀完成后，本文件才升级为验收记录。
>
> **目标（用户口径）**：复刻官方「稿定-PS设计助理-色板工具」面板。**判据只有一条：用户使用结果不变**——

## 一、契约（磁盘）

三个文件，全部在 `%APPDATA%/FengZiSeBan/`：

| 文件 | 形状 | 生产者 | 排序 / 去重 | 上限 |
|---|---|---|---|---|
| `userColor.ini` | `[{name, color:{hex,c,m,y,k,isFill?}}]` | jsx `sb_ZhuanHuanYanSeDuiXiang`（`main.jsx:287-298`） | 命中 `hex` → **不添加**（`sf.js:346-364`）；**不重排** | 无 |
| `vecently.ini` | 同上 | 同上 | 命中 `hex` → **先删再 push 末尾**（`sf.js:196-201`）；超限删最前（`:202-204`） | `g_ShuLiang`，默认 10，**0–15** |
| `zuiJinShuLiang.txt` | 纯数字字符串 | 设置弹层（`sf.js:398-423`） | — | — |

**项形状的四条硬约束**（抄错一条，面板显示或写盘就错）：

1. `hex` **无 `#` 前缀、大写**（`obj.hex = c.rgb.hexValue`，`main.jsx:290`）。
2. `c/m/y/k` 各自 `Math.round`（`main.jsx:291-294`），是 0–100 的整数，不是 0–1。
3. `name` 恒为 `"未命名"`（`main.jsx:296`）；面板不提供改名。
4. `isFill` **不是 jsx 加的**，是主面板 `cyAutoFillColor` 分支补的（`app.v4.js:17896`）。读的时候当可选字段，写的时候不许自己造。

**两个易错点**（已实测确认）：

- 设置的上限判断是 `ls < 0 || ls > 15`（`sf.js:408`），**`0` 合法**，含义是"不保留最近色"。
- 自定义色与最近色**都有去重**，但语义不同：自定义色是"命中就不加"，最近色是"命中就移到末尾"。

## 二、数据流（4 条链路，单向）

```
① 读   pages/seBan → stores/swatch(只读投影) → cep/data/swatch-repo → cep/fs:readTextOutcome → 盘
② 写   pages/seBan → useCommand → commands/swatch → swatch-repo(enqueue) → fs:writeTextFileAtomic + .bak
③ 收   cep/events:onAppEvent(APP_EVENT_SEBAN) → stores/swatch 重读    ← 唯一订阅点在 store
④ 发   commands/swatch → sendAppEvent(APP_EVENT_SEBAN, {type, data})
```

**四条约束**：

- **唯一入口**：三个色板文件只经 `cep/data/swatch-repo.ts` 读写。它从 `style-library-repo.ts:836-883`（`swatchFilePath` / `readSwatchItems` / `writeSwatchItems`）与 `:206`（`enqueue`）**整体提出来**，`style-library-repo` 的四条色板命令改为 import 它并**删除私有实现**（一次替换，有删有加）。
- **一个写队列**：队列跟着搬到 `swatch-repo`。两套队列并存会交叉覆盖——`style-library-repo:201-203` 的注释就是为这件事写的。
- **依赖单向**：`commands/swatch → data/swatch-repo`；`data/style-library-repo → data/swatch-repo`。**反向禁止**，否则成环。
- **去重下沉**：页面不判重、不排序，只 `v-for` 渲染 repo 给的数组。

## 五·二、不复刻的官方 bug（逐条表态，不许含糊）

官方这两处**是 bug，不复刻**；但每一处都要写清"我们改成什么、用户可见差异是什么"。

### bug 1：`JianTingYanSe:186` 硬编码字符串下标

```js
var qjs = event.data.indexOf("foregroundColor");
if (qjs == 65)   // 65 是硬编码下标
```

PS 事件 payload 里 `foregroundColor` 的起始位置一旦变化（PS 版本、图层类型、多选区），`== 65` 就静默不成立 → **改前景色后面板不刷新，且没有任何报错**。

**我们改成**：判"包不包含"而不是"在第几位"——`event.data.includes('foregroundColor')`（或解析成结构化 payload 后判 `null._property === 'foregroundColor'`，后者更好，与 `cep/events.ts` 的 `SETD_ROUTES` 同一套判据）。
**用户可见差异**：无（正常时行为一致）；异常时我们从"静默不刷新"变成"正常刷新"。
**守卫**：单测钉一条——payload 里 `foregroundColor` 不在第 65 位时仍然触发。

### bug 2：两处超限裁剪方向相反

| 位置 | 写法 | 效果 |
|---|---|---|
| `JianTingYanSe:202-204` | `arr.splice(0, 1)` | 删**最前**（保最新） |
| `SheZhi:416-418` | `arr.splice(arr.length - i, i)` | 删**最后**（保最旧） |

数组语义是"旧在前、新在后"（`push` 到末尾）。所以**把数量调小的时候，`SheZhi` 删掉的是最新的颜色**，保留的反而是最旧的——与 `JianTingYanSe` 的裁剪方向相反。

**我们改成**：两处统一为**删最前、保最新**（即 `SheZhi` 也改成 `arr.splice(0, arr.length - ls)`）。
**用户可见差异**：只有"调小最近色数量"这一个动作——官方留下最旧的 N 个，我们留下最新的 N 个。**这是有意偏离**，理由是"最近使用"的语义应该保新。
**守卫**：单测两条——① `JianTingYanSe` 路径超限删最前；② `SheZhi` 路径调小数量后剩的是最新的 N 个。
**如果用户要求完全照抄**：那就两处都保留官方方向，但必须在注释里写明"此处故意保留官方 bug"，否则下一个人会当成我们写错。
