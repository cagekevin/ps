# docs 目录说明

> **这里不是开工入口。** 该读什么、按什么顺序读，只看根目录的 `AGENTS.md`。
> 本页只回答两件事：目录怎么分、新东西放哪。

## 一、目录结构

```
docs/
  README.md                 本页
  架构/                     目标架构（结论）/ jsx契约 / dataflow
   adr/                     ADR（**一条一文件**，走 node scripts/adr.mjs）
  规范/                     视觉规范 / 测试规范 / 原版缺陷
  页面/0N-<页面>.md         单页验收清单（01–08 已建；含「结构对照（逐项）」章，一 class 一行带状态）
  状态/                     进度（页面档位）
  原版/                     原版一手证据（源码 / 组件文档 / CSS / 抽取脚本），**只读**
  生成/                     脚本产物，别手改
  日志/                     YYYY-MM-DD-主题.md，平铺
  归档/                     作废/过期（暂空）
../daily/架构日志/           技术债账本（债务.md = 待办 + 债务-归档.md = 已结 + 区域轮次 + 任务索引），走 node scripts/debt.mjs（6 命令）
```

> **待办与债务不在 `docs/` 下**：2026-10-24 起搬到 `daily/架构日志/`
> （`债务.md` = 待办债、`债务-归档.md` = 已结债，读写入口 `node scripts/debt.mjs`，校验 `debt.mjs check`；`00-任务-总索引.md` = 任务 `T-xx`）。
> 原 `docs/状态/台账.md` 已删除。

## 二、为什么这么分

| 域 | 现在 | 一年后估 | 边界 |
|---|---|---|---|
| `架构/` | 9 | 10–20 | 结论 / 契约 / 复盘 三份分开；复盘是一次性文档 |
| `adr/` | 27 | 60–150 | **一条 ADR 一个文件**（`ADR-NNNN-<标题>.md`），读与索引一律走 `node scripts/adr.mjs` |
| `规范/` | 5 | 5–10 | 规范类，很少新增 |
| `页面/` | 12 | 12 | 一页一份，文件名带页面名，`Ctrl+P` 直接命中 |
| `状态/` | 1 | 1 | 只有进度（待办与债务已搬到 `../daily/架构日志/`） |
| `生成/` | 12 | 12–14 | 脚本产物（其中 2 份是**手写调查结论**：库文件格式契约 / jsx 返回结构复原） |
| `日志/` | 15 | 60–120 | 文件名带日期；集中开发一个月，之后基本不再增 |

两条规则：

1. **不线性增长的，不拆文件**：jsx 契约、版本记录都追加在同一份里。
   **例外**：ADR 是**一条一文件**（`adr/`）—— 因为它要按编号被引用、按状态退出，一份长文件做不到。
2. **会增长的，文件名要能区分**：页面清单带页面名（`03-动作.md`），日志带日期，ADR 文件带四位编号。
   **不要给 8 个页面各建一个目录**——那会让搜索出现 8 个同名 `清单.md`。

## 三、新增一份文件该放哪

按顺序问，第一个"是"就停：

1. 是脚本生成的吗 → `生成/`（并且**不要手改**）
2. 是待办/债务吗 → `../daily/架构日志/`（债走 `node scripts/debt.mjs add`，任务手改 `00-任务-总索引.md`）；结账 `resolve --cmd "…" --claim "…"（闸：真跑命令、claim 必须命中）
   是页面状态档位吗 → `状态/进度.md`
3. 是某一页的验收或备注吗 → `页面/0N-<页面>.md`
4. 是架构决策吗 → **`node scripts/adr.mjs add`**（落 `adr/`，不手写、不追加到别的文件）
5. 是规范吗 → `规范/`
6. 是过程记录吗 → `日志/YYYY-MM-DD-<主题>.md`
7. 都不属于 → 先别建，说明它要解决什么问题

## 四、命名

- 目录与文件名用**中文**
- 页面清单：`页面/0N-<页面名>.md`（`页面/03-动作.md` 对应 `/action`）。
  **序号是 ID，不是排序**：01 字体管理、02 字体面板、03 动作是先后建的，之后按导航补齐
  （04 自定义 / 05 常用 / 06 样式 / 07 重命名 / 08 设置）。**不要重排**，重排会让所有引用失效。
- 日志：`YYYY-MM-DD-<主题>.md`，平铺在 `日志/`

## 五、生成物（别手改）

| 产物 | 命令 | 注意 |
|---|---|---|
| `生成/页面规格/0N-*.md` | `npm run spec`（读 `docs/原版/01-原版源码/`，写本目录） | 每页根组件 + 全部子组件的**结构树 + 全量 class + CSS 实测值**，带源码行号 |
| `日志/index.md` | `npm run log:index` | 别手改 |
| **`adr/README.md` 的索引块** | **`node scripts/adr.mjs index --write`** | 真源 = 各 ADR 文件的头部字段；**索引表禁手改** |

> **生成脚本为什么是副本**：原版抽取脚本在 `docs/原版/tools/15-page-spec.cjs`（证据原件，只读），
> 里面的输入路径按仓外 `../reference` 写死，在仓内跑不通。所以 `scripts/page-spec.mjs` 是它的可运行副本，
> 只改输入/输出路径，解析逻辑与页面映射没动。**`docs/原版/README.md` 里「跑之前先确认或就地改路径」那句已过期**——
> 证据目录不许改，重跑一律用 `npm run spec`。

**页面清单不自动生成**：组件树有 31% 未解析且名字错位（D-19），生成出来的骨架比没有更糟。
按 `AGENTS.md`「一次改对」第 1 条，从 `02-组件/<组件>.md` 的「子组件」小节人工抄。

## 七、文档坏了怎么修

- 数字对不上（测试数、组件行数）：先跑命令确认真值，再改文档，**不凭记忆填**
- 出现两份说法：留一份，另一份改成指针（“见 XXX”）
- 生成物被手改：删掉重跑命令，不 merge
- 需要新目录：先回答“它靠什么切片”，答不出来就不要建
