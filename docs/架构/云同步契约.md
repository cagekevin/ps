# 云同步契约 · Dataflow / Types / Tests

> **这不是开发日志。**  
> 本文是云同步的实现契约：类型、GAS 协议、数据流、错误码和关键测试。  
> 与 `云同步底层设施.md` 配套；实现以本文为准。

## 0. 固定前提

- 后端：GAS
- 账号：GAS URL 就是账号
- 不做登录、加密、syncKey、设备管理
- 传输：`push_data / pull_data`
- 云端：整包 `CloudSnapshot`
- 冲突：整包 `rev` + `localHash`
- 不做服务端 CAS
- 主设备自动同步；临时设备只下载
- 自动同步：首次 30s，间隔 2h

## 1. 版本

```ts
const CLOUD_SCHEMA = 1
const CLOUD_TYPE = 'psz_sync'
```

`CloudSnapshot.schema` 不是包内格式版本以外的业务版本；每个 unit 另带 `schema`。

## 2. 云端类型

```ts
type FileEncoding = 'json' | 'text' | 'base64'

type FileContent =
  | {
      kind: 'inline'
      data: string
      encoding: FileEncoding
    }
  // 第一版只定义、不实现
  | {
      kind: 'remote'
      sha: string
      size: number
      encoding: FileEncoding
    }

interface SyncFile {
  path: string
  size: number
  content: FileContent
}

interface SyncUnit {
  /** unit 数据结构版本，用于迁移 */
  schema: number
  /** 该 unit 内容的稳定指纹 */
  hash: string
  files: SyncFile[]
}

interface CloudSnapshot {
  type: 'psz_sync'
  schema: 1
  /** 云端整包修订号，正整数 */
  rev: number
  /** 上传者本地时间，仅展示 */
  updatedAt: number
  units: Record<string, SyncUnit>
  /** GAS 只回 data 时用于恢复 rev/updatedAt */
  __meta?: {
    rev: number
    updatedAt: number
    schema: 1
  }
}
```

### Unit id

第一批固定：

```text
font.stars
font.tags
font.settings
```

不提供 per-unit 开关。  
设置页只有总开关，避免“关闭某个 unit 后整包上传把它删掉”。

### 文件路径

- `path` 必须是相对用户目录的路径；
- 禁止 `..`、绝对路径、反斜杠；
- 多文件 unit 的 `files` 按 `path` 稳定排序；
- `size` 是字节数。

### Hash

`hash` 不是安全哈希，只用于比较。

```
hash = md5(stableStringify(payload))
```

`stableStringify`：

- 对象 key 排序；
- 数组顺序保留；
- 不包含 `hash` 自身；
- 不包含 `rev` / `updatedAt`。

`unit.hash` 计算范围：

```ts
{ schema, files }
```

不含 `hash` 自身。

`localHash` 计算范围：

```ts
{ units }
```

不含整包 `rev` / `updatedAt` / `__meta`。

## 3. GAS 协议

### push_data

请求：

```json
{
  "action": "push_data",
  "data": {
    "type": "psz_sync",
    "schema": 1,
    "rev": 4,
    "updatedAt": 1760000000000,
    "units": {},
    "__meta": {
      "rev": 4,
      "updatedAt": 1760000000000,
      "schema": 1
    }
  }
}
```

成功响应：

```json
{ "ok": true, "msg": "同步成功" }
```

失败响应：

```json
{ "error": "错误原因" }
```

### pull_data

请求：

```json
{ "action": "pull_data" }
```

响应：

```json
{ "data": { ...CloudSnapshot... } }
```

兼容两种形态：

```
A: { data: CloudSnapshot, rev, updatedAt }
B: CloudSnapshot 本身，__meta 提供 rev/updatedAt
```

归一化后只暴露：

```ts
interface CloudSnapshotView {
  rev: number
  updatedAt: number
  units: Record<string, SyncUnit>
  raw: CloudSnapshot
}
```

### transport 规则

- `Content-Type: text/plain;charset=utf-8`
- `redirect: 'follow'`
- 响应文本包含 `<html` → `CLOUD_PERMISSION_HTML`
- JSON 解析失败 → `CLOUD_BAD_RESPONSE`
- `error` 字段 → 原始错误
- 同一进程 `isSyncing` 单飞
- 超时：建议 20s

## 4. 本地台账

文件：

```text
sj_v5_cloud_sync.json
```

结构：

```ts
interface CloudLedger {
  rev: number
  syncedAt: number
  localHash: string
}
```

规则：

- 只在**完整成功**后写；
- 下载部分失败不写；
- 上传失败不写；
- 台账不存在 = 新设备。

## 5. 同步项接口

```ts
interface SyncUnitAdapter {
  id: string
  schema: number

  /** 读取本地完整 unit；失败必须 throw */
  read(): Promise<UnitPayload>

  /** 写回；必须自己保证单 unit 事务 */
  write(payload: UnitPayload): Promise<WriteOutcome>
}

interface UnitPayload {
  schema: number
  files: SyncFile[]
}
```

约束：

- `read()` 失败 → 整个上传中止，不能少一个 unit 就 push；
- `write()` 单 unit 内要么成功，要么返回失败；
- 多文件 unit 由 adapter 负责事务；
- adapter 不拼 `userDir`，走数据层 helper。

## 7. 上传数据流

```
isConfigured?
  → false: CLOUD_NOT_CONFIGURED，停止

collect all adapters
  → 任一 read() throw:
      CLOUD_COLLECT_FAILED
      不上传
      （整包替换时，少一个 unit 等于删除云端数据）

units = 所有 adapter 的 UnitPayload
localHash = md5(stableStringify({ units }))
ledger = readLedger()

cloud = pull + normalize
  → 失败:
      ledger 存在 ? 失败，不上传
      ledger 不存在 ? 失败，不上传（新设备不能盲推）

if cloud == null:
  push rev=1
else if cloudHash === localHash:
  skipped
else if !ledger:
  cloud-newer：必须用户确认
else if cloud.rev > ledger.rev:
  both-changed / cloud-newer：必须确认
else:
  push rev = cloud.rev + 1

push 成功:
  writeLedger({ rev, syncedAt, localHash })
push 失败:
  不写台账
```

### 新设备保护

```
无 ledger && cloud 有数据
→ 自动同步禁止 push
→ 手动上传必须二次确认“覆盖云端”
→ 首选引导下载
```

## 8. 下载数据流

```
pull + normalize
  → null: 云端无数据
  → 失败: 返回错误

local = collect all adapters
diff = diffUnits(cloud.units, local.units)

有冲突:
  → onConfirm 列出将被覆盖的 unit
  → 取消: cancelled，不写任何东西

逐 unit:
  → adapter.write()
  → 成功记录
  → 失败记录 failed

if failed.length:
  → 不写 ledger
  → 返回 partial.failed
else:
  → writeLedger({rev, syncedAt, localHash: cloudHash})
  → 重新水合 store
  → ok
```

## 9. diff 契约

```ts
interface SyncDiff {
  conflicts: string[]  // 双方都有且不同
  cloudOnly: string[]
  localOnly: string[]
}
```

比较单位：`unit.hash`。

- `cloudOnly`：云端有、本地没有 → 新增；
- `localOnly`：本地有、云端没有 → 下载时保留本地，不删除；
- `conflicts`：双方都有且 hash 不同 → 覆盖前必须确认。

## 10. 自动同步

```
首次 30s
间隔 2h
navigator.onLine === false → skip
document.hidden → skip
!ledger && cloud 有数据 → skip，不 push
isSyncing → skip
连续 3 次“稍后” → 次日 00:00 前退避
只自动上传，不自动下载
只有主面板启动
```

## 12. 关键测试

### hash / snapshot

1. `stableStringify` 对象 key 顺序无关；
2. 数组顺序保留；
3. 同内容不同 key 顺序 → 同 hash；
4. 不同内容 → 不同 hash；
5. `normalize` 支持外层 `{data}`；
6. `normalize` 支持裸包 + `__meta`；
7. `normalize` 无数据 → null；
8. `buildSnapshot` 写入 `__meta`；
9. `__meta` 不参与 `localHash`。

### 冲突判定

10. 云端空 → 首次上传；
11. 云端 hash == localHash → skipped；
12. 云端有数据 + 无 ledger → 必须确认；
13. cloud.rev > ledger.rev + 本地 dirty → both-changed；
14. cloud.rev > ledger.rev + 本地未改 → cloud-newer；
15. 云端读取失败 + ledger 存在 → 不上传；
16. 云端读取失败 + 无 ledger → 不上传。

### 上传

17. 任一 adapter read 失败 → 整次上传中止；
18. push 失败不写 ledger；
19. push 成功写 ledger；
20. rev = cloud.rev + 1；
21. 新设备不自动 push；
22. 手动覆盖云端必须二次确认。

### 下载

23. 有冲突 + 取消 → 不写任何 unit；
24. 无冲突 → 逐 unit 写；
25. 部分写失败 → 不写 ledger，返回 partial；
26. 全部成功 → 写 ledger；
27. `cloudOnly` 新增；
28. `localOnly` 不被删除。

### 字体设置 adapter

30. `sj_set.json` 只 patch 登记字段；
31. 未知键保留；
32. 文件不存在时不写默认配置；
33. 写失败返回 `WriteOutcome` 失败。

### 新设备

34. 无 ledger + 云端有数据 → 自动同步跳过；
35. 手动下载后建立 ledger；
36. 下载后本地修改可手动上传。

### 自动同步

37. 首次 30s；
38. 间隔 2h；
39. 离线跳过；
40. hidden 跳过；
41. 内容一致跳过；
42. 3 次“稍后”退避；
43. 进程内不重入。

### transport

44. HTML 权限页 → `CLOUD_PERMISSION_HTML`；
45. 非 JSON → `CLOUD_BAD_RESPONSE`；
46. `error` 字段原样上抛；
47. 超时 → `CLOUD_NETWORK`。

## 13. 验收

- GAS 只用 `push_data / pull_data`；
- 云端包是 `CloudSnapshot`；
- 上传前任一 entry 读取失败会中止；
- 下载部分失败不写 ledger；
- 新设备不会自动覆盖云端；
- 自动同步 2h；
- 设置页只有总开关 + 上传/下载 + 上次同步。
