## 一、诊断

> 根因一句话：**同一个事实有多份副本，而副本之间的同步点不可枚举。**
> 第二个根因：**现有架构是从 1 个面板（字体管理）反推的，而 8 个面板有 6 种不同形态。**

不是代码不整洁，是两件事没定义：**谁拥有真相、谁能写**；以及**"页面"之外还有别的承载单位**（命令、选区状态、导航数据）。

### 1.1 现状的 5 处多副本（已核）

| 事实 | 副本 | 证据 |
|---|---|---|
| 字体星级 | `store.stars` / `FontItem.star` / `sj_ztglStar.ini` / `mock.mockStars` | `stores/font.ts:47`、`cep/types.ts:24`、`cep/ps.ts:113`、`cep/mock.ts:35` |
| 字体标签 | `store.tags` / `tagFile` 内存 / `mocks/font-tags.json`（被直接 mutate）/ 页面 `tagMap` | `stores/font.ts:45`、`cep/ps.ts:115`、`cep/mock.ts:50`、`pages/fontManage/index.vue:156` |
| 界面偏好 | `usePersistedRef` 的 ref / `prefs.cache` / `sj_v5_ui.json` / `localStorage` | `composables/usePersisted.ts:9`、`cep/prefs.ts:12,23,51` |

两个数据文件的读写实现也是两套：`cep/json-file.ts`（异步读 + 备份 + 原子写）与 `cep/prefs.ts`（同步读 + 无备份 + 普通写）。

### 1.2 配套结论：现在的"容错"在编造数据

`cep/classification.ts:95-118`：读 `classification.json` 失败 → 直接 `return MOCK`，
而 `MOCK.commercials` 只有 `['MiSans', 'OPPOSans']`（`classification.ts:92`）。
用户点"免费商用"，得到的是**错误结果且无任何提示**——比崩溃更坏。

| 操作 | 允许降级 | 失败表现 |
|---|---|---|
| 读 | 允许，但必须标记 | 返回 `{ value, degraded: string[] }`；`degraded` 非空时界面挂一条"数据不可用"，**不许用假数据充当真数据** |
| 写 | **不允许** | 必须抛，必须被 `feedback.error` 看见，必须进日志 |

### 1.3 更严重的一层：架构只覆盖了 1/6 种页面形态

现有骨架 = `PageShell` + `usePagedList` + `bind(filtered)`，它假设了四件事，而这四件事在终态只有第一件部分成立：

| 隐含假设 | 终态是否成立 | 反例 |
|---|---|---|
| 页面 = 列表 | 2/8 成立 | 常用页是命令网格、设置页是配置台、自定义页是参数生成器、字体面板是按钮矩阵 |
| 数据 = 单文件一维数组 | 3/8 成立 | 动作是"多仓库 × 动作项"，样式是"4 类库 × 仓库 × 目录" |
| 操作 = 点一下 → 一个 toast | 2/8 成立 | 批量重命名、批量导出、播放动作、优化文档都是长任务 |
| 导航 = 静态路由表 | **不成立** | 设置页直接编辑导航项与常用功能列表（见第四节） |

第三节给每个面板的结构事实；第五节给修正后的目标架构。

- `Action.md:54` `addGroupName: "动作分组"`；方法里有 `addWarehouseGroup` / `renameWarehouse` / `delWarehouseGroup` / `selectWarehouse` / `addGroup` / `showGroupMenu` → **仓库级 + 组级两层 CRUD**。

### 3.3 样式页：4 类库，每类一套仓库 + 目录

- `Style.md:87` `jsxNoCheck("exportCurrentLayerToImage")` + `$load.show("正在解析图片颜色")` → **拖入图片取色**，是长任务 + 视觉提取。

### 3.9 归纳：核心元素是命令

8 个面板的形态差异，收敛到同一个执行单位：

> **命令是插件的最小可执行单位。页面是命令的编排，库是命令的参数，选区是命令的上下文，设置是命令的元数据。**

| 面板 | 在命令生命周期里的位置 |
|---|---|
| 字体面板 | resolve（能否执行）+ 命令按钮组 |
| 常用 | 命令网格（多数无参数，直接 execute） |
| 字体管理 / 动作 / 样式 | collect（从库取参数）+ execute |
| 重命名 | collect（规则编辑器，可 dry-run）+ 批量 execute |
| 自定义 | collect（表单）+ execute |
| 设置 | 编辑**所有**命令的元数据：显隐 / 顺序 / 快捷键 / 默认参数 |

所以下面这些不是五件独立的事，是同一件事的五个面：

| 缺口 | 本质 | 被几个面板需要 |
|---|---|---|
| 命令注册表 | 命令的定义与发现 | 5 处入口 |
| 选区状态源 | 命令的隐式第一参数 | 4 个面板 |
| 长任务 | 命令的 `kind: 'long'` 执行态 | 5 个面板 |
| 批量结果汇总 | 命令的 `kind: 'batch'` 返回值 | 3 个面板 |
| 文件对话框 / 目录 | 某类命令的参数与产物 | 5 个面板 |

**唯一验收判据**：新功能只写「1 个命令定义 + 1 个参数类型」，就能在字体面板、常用页、快捷键三处同时出现，且不改这三个页面。做不到，说明还有一条隐式耦合没抽出来。

### P2 数据仓库（1.5 天；先定两个接口，否则执行时会自由发挥）

**接口一，仓库：**

```ts
interface Repo<T> {
  read(): Promise<{ value: T; degraded?: string }>  // 读失败 → fallback + degraded，不抛
  update(fn: (v: T) => T | void): Promise<T>         // per-file 串行；写失败必抛
  write(v: T): Promise<void>
  onChange(cb: (v: T) => void): () => void           // store 靠它保持同步
}
```

**接口二，data 层双实现（上一版漏掉的，不补会崩）：**

P3 把 `ps.ts` 的 `if (!hasCep()) return mock` 拿掉后，浏览器里没有 Node，`writeTextFile` 会抛 `NO_NODE`，标签/星级就没人兜底。所以 data 层必须和 jsx 一样双实现：

```
data/index.ts   三选一（不能只看 hasNode）
data/memory.ts  内存实现，onChange 同步触发（仅浏览器 dev）
data/real.ts    文件实现：fs + 队列 + 备份 + 原子写
```

选实现的规则（**写失败不许静默降级**，这是 W1 的直接落地）：

| 环境 | 读 | 写 |
|---|---|---|
| 浏览器（无 CEP） | memory | memory（dev 允许） |
| CEP + Node | real | real |
| CEP 但无 Node | real 的读走 jsx `File` | **抛 `NO_NODE`**，不许退回 memory |

第三种最容易被忽略：manifest 少了 `--enable-nodejs` 时，如果写退回内存，用户会以为保存成功，下次开面板全丢。宁可报错。

**同步/异步矛盾（必须按这个解）：**

`usePersistedRef` 现在是同步 `getPref`，改异步会让所有调用点变 `await`。做法：

- `settings.snapshot()` 同步返回内存缓存；启动时 `await settings.ready()` 预热一次
- 写入走异步队列 + 防抖
- `usePersistedRef` 保持同步签名，内部读 snapshot、写队列

其余：

- `json-file.ts` → `data/real.ts`（子目录 root、`list` / `remove`）
- `prefs.ts` 合并进 `data/settings.ts`
- `classification.ts` 拆：读取 → `data/classification.ts`；规则 → `domain/filter.ts`

判据：


## 四、风险

| 风险 | 应对 |
|---|---|
| 重构期间字体页回退 | 每阶段跑 `npm test` + `npm run check`；字体页只换底层，不加功能 |
| 命令层过度设计 | P5 只注册 6 个命令、只接 2 个入口；第三个入口出现前不扩字段 |
| 设置页要改导航，牵动外壳 | 放到 P11；之前 `MainLayout` 保持静态，避免外壳反复改 |
| 原面板同时写同一批文件 | 仓库不做长期缓存；每次读走文件；写前备份 `.bak`（ADR-12） |
| 阶段间不可构建 | P1-P3 保持可构建；接口化先并行落地，最后一次性切 import |
