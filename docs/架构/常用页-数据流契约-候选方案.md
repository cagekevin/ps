# /commonUse 底层数据流契约 —— 4 个互斥候选方案

> 只出方案，未改 `src/`、未提交。行号均为美化版坐标 `docs/原版/01-原版源码/panel/js/app.v4.js`。
> 落点文件建议 `src/cep/data/commonUse.ts`（`docs/架构/目标架构.md:248` 已把该事实预留给 `data/commonUse.ts`）。

## 一、结论：横向对比与推荐

| 维度 | A 照抄官方平铺 + 原位 splice | B 归一化视图 + 只写 diff | C 文件即真相 + 不可变快照 | D 双写：官方文件 + 我方扩展块 |
|---|---|---|---|---|
| 单一真相强度 | **强**（一份 raw，一处写入） | 中（raw + view 两个形状，靠白名单 patch 防漂） | **强**（快照唯一，写全量） | 弱（两文件两 repo，顺序真相在官方、UI 偏好在我方，需额外仲裁） |
| 与官方兼容度 | **最高**（文件形状逐键一致，设置页可继续写） | 高（落盘同形，但多一层 diff 代码要维护） | 高（同形，但每次写全量，覆盖别人的并发写） | 中（官方文件干净，但我方键在 `sj_v5_ui.json` 要新定 schema） |
| 改动面 | 小：1 个 repo + 1 个 domain + 5 条命令 + 1 个 store | 中：repo 双 API + diff/normalize 两个纯函数 + 测试面翻倍 | 中：repo 语义改写、排序纯函数改签名、所有调用点避开 mutation | 中大：两个 repo + 事务规则 + 迁移脚本 |
| 可测性（jsdom） | **高**（读-改-写一轮、落点、未知键、失败路径全可断） | 最高（diff 与 normalize 均可纯函数断言） | 高（快照相等即断言） | 中（要造两个内存 repo 并测失败组合） |
| 风险 | 会话态与落盘态混用要划清；显示/隐藏 UI 无处放（我方 `/set` 已冻结） | diff 成为第二真相，白名单外字段静默不写 | 验收线 4 字面冲突（"全量覆盖数组"）；并发 last-write-wins 更狠 | 双写不一致，最坏是"顺序存了、参数丢了"且用户看不出 |
| 人日估算 | 3–4 | 5–6 | 3 | 4–5 |

**推荐 A。** 判据：验收线 1/2/4 三条同时满足，且**唯一写入口**能直接用 eslint + `Repo<T>` 的 `update` 串行队列守住；官方结构零翻译，未知字段靠"整份对象当仓库类型"天然保住（先例 `src/cep/data/legacy-settings.ts:20-27` 就是为同一理由这么写的）。

**为什么不是 B**：`diff` 一旦存在，就多一份"什么算变了"的判断权，与验收线 1「禁止第二真相」是同一种病，只是藏得更深；白名单漏一个键 = 静默不落盘，且这种漏没有编译期信号。
**为什么不是 C**：验收线 4 明写"不许用全量覆盖数组糊过去"。C 能让语义仍然正确，但写盘必然全量（单 JSON 文件无 append），评审时无法与"糊过去"区分，等于给下一轮留一个说不清的争点。
**为什么不是 D**：现在**没有**真实消费方要求把扩展字段落盘——7 个子面板参数官方从不持久化（见 §三），会话态够用。为一个不存在的需求引入双写事务，违反"抽象只发生在第二处真要用"。

## 三、方案 A（推荐）：照抄官方单文件平铺 + 原位 splice

- **定性**：官方 `info[]` 原样当唯一真相；repo 只做"读原始对象 → 补缺省 → 整份写回"，排序用 `domain/reorder` 的原位 `splice` 落点。不做视图模型层。
- **数据归属**：`src/cep/data/commonUse.ts`，唯一入口（首行五段注释 + `目标架构.md` §4.7 表加行）。`Repo<CommonUseFile>`，复用 `pick()` 与 `requireExisting: true`：
  `read(): Promise<RepoRead<CommonUseFile>>` / `write(v)` / `update(mut)` / `onChange(cb)`，另加语义方法
  `move(from: number, to: number, pos: DropPosition)`、`remove(id: string)`、`setShow(id: string, show: boolean)`、`reset(): Promise<void>`（种子来自 `:11111`）。
  store：`src/stores/common-use.ts`（只读投影，`bindCommonUseData()` 照 `stores/free-panel.ts:29-40` 的写法）。
- **类型契约**：**一份落盘类型 + 一份纯派生视图**。
  `CommonUseFile = { info?: CommonUseItem[]; [k: string]: unknown }`；
  `CommonUseItem = { id, isMore, ismark, isShow, title, svg, fillSvg, moreId, name, comName?, [k: string]: unknown }`（10 键全 optional，索引签名保未知键；`created` 不进类型）。
  转换 `domain/common-use.ts: toTiles(items): CommonUseTile[]`（补 `index`、`visible`），**单向**；回写只经 `update` 里对 `item[已知键]` 赋值，绝不整体替换 item。
- **命令清单**：新增 `commonUse.move` / `.remove` / `.setShow` / `.resetOrder` / `.addToFreePanel`；复用现有 11 条执行命令（其中 `flip/transform/distribute/referenceLines/embedImage/optimizeDoc` 改 jsx 名，见 §二表）。`payloads.ts:725-735` 同步加 5 条。
- **子面板状态归属**：7 个子面板的参数（变换 7 参、分布 3 参、导出格式/位深/品质、优化三开关、参考线动作、嵌入选项、导入路径）**不落盘**，放 `stores/common-use.ts` 的 `draft`（会话态，页面可写 —— 这是唯一允许页面写 store 的字段，写进注释）；「添加到自由面板」时由 `commonUse.addToFreePanel` 转成 `freePanel.add` 的 `option`（快照）。失败表现：命令抛 → `useCommand` 统一 toast；子面板草稿不受影响（不连带清空）。
- **事件接线**：`commonUse.setHostWatch({ key: 'dragIn'|'paste'|'clipMask'|'linkObject', on: boolean })` → 命令内 `settings` 落盘 + `cep/events.subscribeHostEvent` 解/绑；页面零 import `cep/events`。智能填色复用 `setd`，不新增语义名。
- **复用点**：`domain/reorder.applyListDrop`（落点四分支）、`domain/free-panel-legacy` 的 7 条 `commonUse.*` 映射（key 需改官方名，见迁移）、`useLongPressDrag`（Ctrl/⌘ + 300ms，`:37418` 闸门）、`GButton width="quarter|fifth"`（官方 `.btn-small-4/5`）、`PageShell`。
- **迁移**：①文件存在 → 直读，未知键原样保留；②不存在 → 以 `configReset()` 种子首写，并提示"已生成默认常用功能"；③半坏（JSON 坏 / `info` 非数组）→ `requireExisting` 语义下 `update` 抛 `IO`、`read` 返 `degraded` 并在页内联"配置损坏 + 重置"按钮（重置 = 备份 `sj_commonFunction.bak.json` 后写种子）。另：我方 `free-panel-legacy` 的 `commonUse.embed` 等**私有 key** 与官方（`item.key` 就是 jsx 名，`:37724`）不兼容，需一次性兼容读取（旧 key 仍认，新 key 用官方名），否则原面板添加过的项在我方全变"未知 key"。
- **代价**：3–4 人日（repo 1、domain 0.5、命令 1、页面接线 1）。风险：显示/隐藏 UI 官方在设置页（`:61464`），我方 `/set` 已冻结，只能把"显示/隐藏功能"放到本页的管理态 —— 这与官方位置不同，须在页面契约里写明「有意偏离 + 原因」。最坏情况：与原面板同时改显隐 → last-write-wins 丢一次勾选（`dataflow.md:175` 已登记该机制，不是本页新债）。
- **官方对齐证据**：`:5218`、`:11088-11108`、`:11111-11122`、`:37786-37796`、`:38209`、`:16887-16891`、`:64456`。

## 四、方案 B：归一化视图模型 + 只写 diff

- **定性**：内存里一份强类型 `CommonUseState` 当读模型，写只在 `commonUse.*` 里对落盘原文做**定点 patch + 原位 splice**，落盘永远是官方形状。
- **数据归属**：`cep/data/commonUse.ts` 暴露 `readRaw(): Promise<RepoRead<CommonUseFile>>` 与 `patch(fn: (raw: CommonUseFile) => void)`；`domain/common-use.ts` 给 `normalize(raw): CommonUseState` 与 `diff(state, raw): CommonUsePatch[]`。store 持有 `state`。
- **类型契约**：**两份**：`CommonUseItemRaw`（全可选 + 未知键索引）与 `CommonUseTile`（全必填，含派生 `index/visible`）。`raw → tile` 单向；`tile → raw` 只走 `applyPatch(raw, patches)`，白名单 = 官方 10 键 + 顺序。
- **命令清单**：与 A 同 5 条，payload 改用 `patch` 形状（`{ id, fields: Partial<...> }`、`{ id, to, pos }`），执行命令复用 11 条。
- **子面板状态**：同 A 的定论（两套、不落盘），但草稿放在 `state.sub`，由 `normalize` 建默认值 —— 好处是默认值只有一处。
- **事件接线**：新增横切 `composables/useHostWatch.ts`（开关 + stringID + 解绑统一），因为 A 里这段只服务本页；一旦第 2 页要用就上提。**须先落 ADR**（`AGENTS.md` 第 18 条）。
- **复用点**：同 A；额外复用 `legacy-settings` 的"整份对象 + 未知键"先例保证 `diff` 不碰白名单外字段。
- **迁移**：三态同 A；半坏时 `normalize` 不抛、把丢掉的字段列进 `degraded` 文案（比 A 更友好，也更危险：用户可能带着坏数据继续用）。
- **代价**：5–6 人日。风险：diff 是第二真相来源；白名单漏键 = 静默不落盘，无编译期信号。最坏情况：用户改了标题，界面显示已改、文件里没改，重开面板回滚。
- **官方对齐证据**：`:11113-11122`（字段集即白名单）、`:37770-37796`、`:38209`、`:64329-64333`（`created` 必须不进落盘）。

## 五、方案 C：文件即真相 + 内存不可变快照

- **定性**：repo 是"快照源"，任何改动产出新 `CommonUseSnapshot { rev, items }`，写盘全量；禁止 mutation、禁止原位 splice，排序由纯函数 `moveItem(items, from, to, pos): items` 返回新数组。
- **数据归属**：`cep/data/commonUse.ts` 只暴露 `snapshot()` / `commit(next: CommonUseSnapshot)` / `onChange`；store 持 `rev` 做失效判断。
- **类型契约**：`CommonUseItem` 加 `readonly` + `readonly [k: string]: unknown`；未知键靠 `deepClone` 逐项保留（与 A 同效，但每次全量克隆）。
- **命令清单**：同 A 5 条，语义改为"提交快照"，`payload` 带 `expectedRev` 做乐观并发。
- **子面板状态**：同 A（会话态 + `option` 快照）。
- **事件接线**：同 A（`setHostWatch` 命令）。
- **复用点**：`domain/reorder` 的**落点表**（`dropInsertIndex` 可复用），但 `applyListDrop` 的 inline splice 不可用，要新写 `moveItem` —— 这就是"同一落点计算出现第二份"的风险点，必须写在 ADR 里。
- **迁移**：三态同 A；半坏时整份快照不成立 → 只能重置（比 A 更硬）。
- **代价**：3 人日。风险：与验收线 4 字面冲突（写盘必全量）；与原面板并发时覆盖面最大；`expectedRev` 在跨进程下无意义。
- **官方对齐证据**：`:16887-16891`（官方本身就是深度 watch → 整份 `JSON.stringify` 写，C 是它的"正规化"版本）、`:11101-11107`（`resetConfig` 是 `splice(0,len)` + 重新 push + 整份 `updata`）、`:37786-37796`（语义仍是删-插）。

## 六、方案 D：双写 —— 官方文件 + 我方扩展字段

- **定性**：官方 10 键与顺序进 `sj_commonFunction.json`（保原面板/设置页兼容）；我方需要的一切（子面板参数、折叠态、`schemaVersion`、迁移标记）进 `sj_v5_ui.json` 的 `commonUse` 命名空间。
- **数据归属**：两个 repo：`cep/data/commonUse.ts`（官方，只写 10 键）+ `cep/data/settings.ts`（`sj_v5_ui.json`，新增 `commonUse` 块）。**顺序与显隐只存官方文件**（因为原面板也写它）；子面板参数与大数字段存我方。
- **类型契约**：三份：`CommonUseItem`（官方）、`CommonUseUiPrefs`（我方，`{ sub: {...}, collapsed: string[], schemaVersion: number }`）、`CommonUseTile`（合并投影）。合并方向单向，冲突时官方赢（注释写死这条规则）。
- **命令清单**：A 的 5 条 + `commonUse.setSubParams`（写我方）、`commonUse.migrate`（`schemaVersion` 升级）。
- **子面板状态**：**这一方案与 A/B/C 唯一实质分歧** —— 参数真正落盘到 `sj_v5_ui.json`，重启面板后保留。代价是"面板草稿"与"`freePanel.item.option` 快照"变成三种状态，用户会困惑"为什么自由面板里的按钮用旧参数"。
- **事件接线**：同 A；开关状态继续存 `sj_set.json`（原面板也认），不搬到我方文件。
- **复用点**：`cep/data/free-panel.ts:5,15` 的 `showText` 先例（我方 UI 字段剥键不落官方文件，D-35）是这一方案的方法论来源。
- **迁移**：三态同 A，另加 `schemaVersion` 缺省 = 0 → 视为"没有我方扩展"，就地补空块不报错。
- **代价**：4–5 人日。风险：双写不一致（先官方后我方，后者失败只 toast 不阻断 → 最坏"顺序对了、参数回默认"）。最坏情况：用户以为存了参数，重启丢，且没有任何报错。
- **官方对齐证据**：`:37724`（`option` 是快照）、`:11111-11122`（官方只持久化这 10 键）、`:61464-61479` + `:64456`（设置页只碰 `isShow` 与重置）。

## 七、验收线 8 条逐项落地（4 案共有 / 各自缺口）
