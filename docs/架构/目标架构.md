## 改代码前只读这段

1. **唯一写入口是 `commands/`**。页面只调 `useCommand`，不 import `cep/jsx`、`cep/data`、`cep/events`（eslint 会拦）。
2. **四层单向**：视图 → 命令 → 适配（jsx / data / env / selection）→ 传输。**没有"用例层"**，命令就是用例的注册形态。
3. **三个契约**：`CommandResult`（`ok` / `failed` / `cancelled`）、`Repo<T>`（读可降级但必须带 `degraded`，写失败必抛）、宿主事件（语义名 → stringID）。
4. **新增一条命令**只改 `commands/<域>.ts` + `payloads.ts` 一行，页面自动出现。
5. **状态只写一处**：待办 → `状态/台账.md`，页面档位 → `状态/进度.md`，逐项 → `页面/0N-*.md`。
6. **返回结构**：从原版使用侧反推，防御性解析，不猜字段。

下面是要落地时才查的细节，不必一次读完。

## 一、四条硬约束

面板不持有领域数据。真相只在三处：PS 文档/应用状态、`%APPDATA%\SheJiZhuLi\` 下的文件、当前会话的瞬时 UI 状态。
所以它是**两个外部系统的投影 + 一个命令发送器**。

| 约束 | 内容 | 现状 |
|---|---|---|
| W1 写比读可靠 | 写的是用户资产（收藏/标签/库），写坏没有第二份 | ❌ 反了：读有 Node→jsx 降级，写只有一条路且失败被吞（`fs.ts:66`、`json-file.ts:49`） |
| W2 命令串行且可归因 | ExtendScript 单线程，一次 evalScript 是一个事务 | ⚠️ 队列已对，但错误码与产品文案混在传输层（`eval-script.ts:26`） |
| W3 数据契约来自外部 | 20 个文件、4 种形态、原面板同时在读写 | ❌ 只支持"平铺 JSON + 写入成功"一种 |
| **W4 同一操作有多个入口** | 原版用 `$appBus` 把一批操作同时暴露给：页面按钮、常用页/自定义面板、全局快捷键 | ❌ 没有"命令"这个单位，操作只能挂在组件方法上（见 3.7） |

## 二、目标架构

四层，依赖严格单向。**L3 是唯一能被多个入口调用的地方；L2 是唯一接触外部系统的地方。**

```
L4 视图    pages/ components/        渲染 + 收集输入，不碰外部系统
L3 命令    commands/                 元数据 + 编排：读 data → 调 jsx → 写 data → 出结果
L2 适配    cep/jsx · cep/data · cep/env · selection/
L1 传输    cep/transport
```

**没有"用例层"**：命令就是用例的注册形态。多一层会变成"命令 → 用例 → jsx"三跳，边界立刻模糊。
连带结论：**`stores/` 降级为只读投影**，所有写操作只在命令里发生。

**为什么命令必须是独立一层**：`anon_56d7_L34996` 用 `$appBus` 让 10 个操作被至少 4 个入口触发（`anon_56d7_L34996.md:70-90`）。
没有这一层，同样的功能要在字体面板、常用页、自定义面板、设置页各写一遍——原版 1.5MB 单包就是这么形成的。

### 4.1 三条机制（比目录重要）

| 机制 | 规则 | 现在反例 |
|---|---|---|
| M1 单一写入点 | 每个事实只有一个导出函数能写，页面/store 不得直改 | `store.rate` 乐观改 `stars` 再写文件（`font.ts:66-81`） |
| M2 写入串行化 | 每个数据文件一条 Promise 队列 + 原子写；jsx 一条队列 | `jsonFile.update` 是裸的 `await read → write`（`json-file.ts:59-65`），连点星级丢更新 |
| M3 结果唯一表示 | 命令内一律 throw，`execute` 统一归一；UI 只有一个 `useCommand.run` | 三种并存：throw / 返回 `string \| null` / 写 `xxxError` ref |

M3 现存故障：`pages/fontManage/index.vue:451` `@create="(text) => store.createTag(text)"` —— 失败文案被丢弃，静默失败。
（`rate()` 的回滚与 `tagsError` 错位已在 T-30 修掉，判据里不再列。）

### 4.2 命令的形状：四个类型 + 一个入口

```ts
interface Command<P = void> {
  id: string        // 'font.apply'，稳定标识：快捷键 / 设置 / 日志 / 错误归因共用
  title: string
  group: 'font' | 'layer' | 'style' | 'action' | 'file' | 'system'
  icon?: string
  requires: 'none' | 'layer' | 'textLayer' | 'document'  // 无默认值
  kind: 'instant' | 'form' | 'batch' | 'long'            // 无默认值
  run(ctx: CommandContext, payload: P): Promise<void>     // 成功不返回值，失败直接 throw
}

interface CommandContext {
  selection: SelectionSnapshot
  settings: SettingsSnapshot
  data: DataPort      // 只给这个命令需要的仓库
  jsx: JsxPort        // 已按 hasCep() 选好实现
}

type CommandResult =
  | { ok: true; message?: string; detail?: unknown }
  | { ok: false; reason: string; code?: CepErrorCode }
  | { ok: 'cancelled' }
```

对外只有四个函数：

```ts
commands.register(command)
commands.get(id)                  // 元数据：设置页 / 快捷键用
commands.list({ group, view })     // 元数据列表：页面渲染用
commands.execute(id, payload)      // 唯一执行入口
```

`execute` 的职责固定：`requires` 检查 → `run` → catch 归一 → 日志 + 耗时 → `CommandResult`。
**命令作者允许 throw，页面只能拿 Result**：原始异常在 registry 归一。

### 4.3 页面怎么消费：两种形状，没有第三种

单命令（按钮类）：

```ts
const applyFont = useCommand('font.apply')

applyFont.run({ family, variantIndex })  // 失败自动 toast；返回 boolean
applyFont.disabled                        // 由 requires + selection 算出
applyFont.running                         // kind = 'long' 时有意义
```

命令列表（按钮矩阵 / 命令网格 / 设置页）：

```ts
const buttons = commands.list({ group: 'font', view: 'fontPanel' })
// [{ id, title, icon, requires, kind }]，页面只按形状渲染
```

`view` 指向设置数据里的 `view → commandIds[]`（显隐 + 顺序 + 快捷键），缺省回退注册表顺序。
**设置页因此不需要知道任何具体命令**，它只编辑这份映射。

一条链路（应用字体）：

```
点击 → useCommand.run
      → requires 检查（无选区则直接 failed，不调 jsx）
      → commands.execute → font.apply.run
         → jsx.font.setFont(...)        [transport：串行队列]
         → data.fontExtra.bumpUsage()   [data：per-file 串行队列]
      → 失败归一 → feedback.error；成功 → log + toast
      → data 变更通知 → store（只读投影）→ 视图更新
```

### 4.4 目标目录

```
src/
  commands/
    types.ts        Command / Context / Result / Requirement / Kind
    registry.ts     register / get / list / execute（唯一执行入口）
    font.ts layer.ts action.ts style.ts common.ts custom.ts system.ts
    index.ts        聚合注册，全项目唯一 import 点
  selection/        SelectionSnapshot + 订阅（CEP 事件）、无 CEP 时 mock 快照
  cep/
    transport.ts    evalScript 队列 / 超时 / ERR: 协议 / CepError（无文案、无业务）
    env.ts          hasCep / hasNode / userDir / extensionDir（唯一环境出口）
    jsx/font.ts layer.ts action.ts style.ts common.ts custom.ts index.ts
    data/<文件>.ts  每个数据文件一个仓库（真相）
  domain/           纯业务规则（无 IO）：筛选、语言判定、归一化、改名计算
  stores/           只读投影（订阅 data 变更）
  components/command/useCommand.ts
  utils/error.ts    describeCepError / run() / runBatch()
```

`commands/<域>.ts` 与 `cep/jsx/<域>.ts` **一一对应**："某命令用了哪些 PS 能力"局部可读，不用全局搜。

### 4.5 五条护栏

只有目录和类型，三个月后照样会散。让退化**编译不过或 grep 得到**：

| # | 规则 | 落地方式 |
|---|---|---|
| 1 | `commands/**` 只能 import `cep/**`、`selection/**`、`utils/**` | eslint `no-restricted-imports` |
| 2 | `pages/**` 禁止 import `cep/jsx/**`、`cep/data/**` | 同上 |
| 3 | `stores/**` 禁止调用 `data.*.update/write`（只读投影） | 评审 + grep 判据 |
| 4 | `requires` / `kind` 无默认值 | 类型系统：不写就编译失败 |
| 5 | 页面里 `.run(` 只能来自 `useCommand` 的返回值 | `grep -rn "\.run(" src/pages` |

### 4.6 架构完整性：四个方向

判断一个需求该不该做、放在哪，先问它属于哪个方向：

| 方向 | 实现 | 状态 |
|---|---|---|
| 应用 → PS（命令） | `commands` → `cep/jsx` → `cep/transport` | ✅ |
| 应用 → 文件（持久化） | `cep/data/repo` | ✅ |
| **PS → 应用（宿主状态）** | `cep/events`（语义名 → stringID、共享回调、独立去抖、幂等注册） | ✅ P5 |
| 文件 → 应用（外部变更） | **不监听**：原面板同时写文件，我们只在切页/操作时重读 | ⚠️ 明确取舍 |

三条规则：

1. **四个方向装不下 = 架构缺一条通道**，先补通道，不要在页面里开私有路径。
2. 新增宿主事件只改 `EVENT_IDS` 一行 + 一个消费者；新增数据文件只加一行仓库定义。
3. "文件 → 应用"不监听是**有意的**：`fs.watch` 在 CEP 里不可靠，而这批文件变更频率低；代价是"原面板改了标签，我们切页才看到"，可接受。

> 这条判断顺序比任何单点优化都重要：先看方向，再看成本。
> 上一版计划把"宿主事件"当成选区的体验优化来算 ROI，方向就错了。

### 4.7 契约与唯一入口（验收清单）

每个关注点只能有一个入口，且要**有东西兜底**（靠自觉的规则等于没有）：

| 契约 | 唯一入口 | 怎么防止绕过 | 状态 |
|---|---|---|---|
| PS 调用 | `cep/jsx` | eslint：`pages/**` 禁止 import | ✅ |
| PS 事件 | `cep/events` | eslint：`pages/**` 禁止 import | ✅ |
| 数据读写 | `cep/data` | eslint：`pages/**` 禁止 import | ✅ |
| 命令执行 | `registry.execute` | 页面只拿 `useCommand`；eslint：`commands/**` 禁止依赖 views/stores | ✅ |
| 命令 payload | `commands/payloads.ts` | `defineCommand` 强制 id 在映射表；`execute`/`useCommand` 由 id 推断 payload，传错字段编译失败 | ✅ |
| 写用户资产 | `commands/*` | store 无写方法（`grep` 判据） | ✅ |
| 写 PS 文档 | `commands/*`（直接调 `ctx.jsx`） | `ps.ts` **不保留写函数**：页面即使 import 也拿不到写入口 | ✅ |
| 选区快照 | `selection/` | `grep -c getLayerState src/commands` 为 0 | ✅ |
| 错误类型 | `utils/errors.ts`（零依赖） | transport 与文案层都从这里取 | ✅ |
| 错误文案 | `utils/error-text.ts` | `grep describeCepError src/cep` 为 0 | ✅ |
| 存量偏好 | `cep/data/settings.ts` | 唯一读写入口 | ⚠️ **key schema 未定**，见下 |
| 列表读模型 | 页面自己的 `usePagedList` | 无统一入口 | ⚠️ **未统一**，见下 |
| 反馈 | 命令结果走 `useCommand.run`；前置校验（空名/重名）走 `feedback` | 语义区分，非重复 | ⚠️ 约定，未强制 |
| 常用项（项 / 顺序 / 显隐） | `cep/data/common-use.ts` | 命令层；页面只读 `stores/common-use.ts` | 页面不 import `cep/data`；`grep -rn "DATA_FILES.cyCommonFunction" src` 只命中 repo 与 `env.ts` | 计划中（ADR-22） |

**两处故意不定，写清理由与时间点**：

1. **偏好 key schema（P11 再做）**。现在只有 `font.previewMode` / `font.previewText` 两个 key，
   40+ 个设置项是设置页的事；提前编 key 名等于猜。到 P11 时按 `sj_set.json` 的真实字段建 `UiPrefs` 映射，
   签名保持 `getPref<K extends keyof UiPrefs>(key, fallback)`，调用点不用改。
2. **列表读模型（P13 再抽）**。现在只有一个列表样本，`useLibrary` 抽出来一定是字体页的形状；
   动作页落地后再抽，判据是"两页共用同一个 composable"。

> 判断标准：**能编译或 grep 拦住的才算"定了"；只有文档写了的算"约定了"，随时会散。**

## 四、刻意不做

| 不做 | 理由 |
|---|---|
| P5 之前抽列表骨架 | 只有一个样本，抽出来的是字体页形状 |
| 预先封装 64 个 jsx 函数 | 返回结构未知，封了就是用错误类型污染后续页面 |
| 分包 / 拆 chunk | IIFE 单包 + 直写扩展目录正确（ADR-03/04），2MB 前不动；只加产物体积记录 |
| 把 `router` 改造成动态 | 只在 P11 做"导航数据源"，之前保持静态 |
| 全量类名重命名（`.content` 等） | 收益低于风险；登记台账，随页面重构顺带改 |
| 清理 tokens 双变量 | 只规定"新代码用 `--c-*`，语义别名冻结" |
| 动 `v-html` 内联 sprite | CEP 99 下 `<use>` 会闪 |
| Command 的继承 / 插件化 / 命令组合（宏） | 8 个页面的量级用不上；`group` 用手写联合类型即可，不要做成数据驱动 |
