## 退出机制

ADR 不是只进不出的档案。**每条都有权作废**，但作废必须留痕，不能删。

### 三种退场

| 状态 | 什么情况 | 怎么处理 |
|---|---|---|
| **过期** | 决定描述的那个世界已经不存在了：代码改了、前提没了、推翻条件早过了 | 索引改状态 → 正文首行加 `> ⚠️ 已过期（YYYY-MM-DD）：<哪条前提没了>` → **正文保留** |
| **被取代** | 有新决定覆盖了它 | 索引改状态 → 正文首行加 `> 已被 ADR-NN 取代` → 新 ADR 里写明取代谁 → **正文保留** |
| **废除** | 决定本身被判定不该做（不是过时，是错） | 正文压成索引里的一行，正文删掉，理由留一句 |

### 两条硬规则

1. **正文不因「过时」而删，只加状态行。** 删掉等于丢掉「当时为什么这么想」，下次会重复踩同一个坑。
2. **索引必须是当前真相。** 允许正文有旧内容，不允许索引说谎 —— 状态算数与否，只看索引。

### 复核时机（不设定期巡检）

定期巡检会像定时器一样腐烂（ADR-21 就是在拆这类东西）。

- 注意到某条 ADR 的「什么时候推翻」条件**已成立** → 当场改索引，不攒
- 改了某条 ADR 涉及的代码 → 顺手看正文描述是否还对
- **没有自动校验**：`npm run check` 不查 ADR 状态，它只保证格式与类型。状态准确是人的责任，这里不写"已自动保证"。

### 新增 ADR 的格式

必须同时给三样，缺一条就不算写完：**决定 / 为什么 / 什么时候推翻**。
没写「什么时候推翻」的 ADR 无法退场 —— 它要么永远不会错（那就不是决策，是事实），要么会永远骗人。

## ADR-01 UI 全重写，PS 能力继续用原厂 jsxbin

- **决定**：Vue 3 重写全部界面和数据流；PS 操作继续 `$.evalFile` 原厂 jsxbin。
- **原因**：原面板 Vue 2 已 EOL、组件全塞在 1.5MB 单包里、无类型。但 jsxbin 是 68 个函数的行为黑盒，重写成本远超收益。
- **替代方案**：全量反编译 jsxbin（字节码，无可靠工具）、或自己用 ExtendScript 重写 PS 操作（68 个函数）。
- **什么时候推翻**：某个函数的行为必须改，且改不了——那时只针对**那一个函数**反编译。

## ADR-02 CEP 层是唯一 PS 出口

- **决定**：页面禁止出现 `window.__adobe_cep__` / `evalScript` / `$.evalFile`。PS 出口全部在 `src/cep/`：`transport.ts`（唯一 `evalScriptRaw` / `__adobe_cep__` 出口）、`jsx/<域>.ts`（7 个域文件：`action` / `commonUse` / `font` / `layer` / `legacy` / `rename` / `style`）、`events.ts`（宿主事件）、`fs.ts`（文件）、`ps.ts`（只剩初始化与读）；写操作在 `commands/<域>.ts`。
- **2026-10-23 修正**：原写「全部走 `src/cep/ps.ts`」、代价写「加一个新 PS 能力要改 3 个文件（ps/types/mock）」。实际已按 ADR-16 / ADR-17 拆开：`ps.ts` 只剩 5 处 `export`（`initJsx` / `getFontList` / 一处 re-export 标签与星级 / `getRawActionList` / `getLayerState`，`git grep -c '^export ' src/cep/ps.ts` = 5），新增能力的三个文件是 `jsx/<域>.ts` + `jsx/types.ts` + `jsx/mock.ts`。**判据（页面禁止裸调 CEP）未变。**
- **原因**：需要统一的超时、错误码、初始化顺序、mock 切换。散落在页面里就没法保证。
- **代价**：加一个新 PS 能力要改 3 个文件（ps/types/mock）。
- **什么时候推翻**：不推翻。但要注意别为了一个页面的一次性调用就加 cep 函数。

## ADR-03 产物是 IIFE 单包 + defer，放弃路由懒加载

- **决定**：`format: 'iife'` + `inlineDynamicImports: true`，HTML 里 `<script defer>`。
- **原因**：CEP 走 `file://`，模块脚本被 CORS 拦（origin 是 null）；chunk 按需加载在 file:// 下不可靠。
- **代价**：所有页面打进一个包（当前 **1.13 MB**，`verify-dist` 实测，见 ADR-18），"改一个组件要重编译全部"——这正是我们想摆脱的原面板问题。
- **2026-10-23 修正**：原写「当前 580KB」。实测值是 **1.13 MB**（ADR-18 记「产物 1.13 MB，`verify-dist` 通过」）。本轮没有重跑 `npm run build`（build 即部署，铁律不擅自部署），数字取自 ADR-18 的实测记录。**判据（2MB 阈值 / 冷启动）未变。**
- **注意**：`defer` 不能去掉。脚本在 head 里，去掉 `type="module"` 后是阻塞脚本，会在 `<body>` 前执行，`#app` 不存在 → 面板全黑。
- **什么时候推翻**：如果包超过 2MB 或者冷启动明显变慢，再考虑本地 http 服务 + 真分包。

## ADR-04 构建产物直接输出到 CEP 扩展目录

- **决定**：`outDir = %APPDATA%\Adobe\CEP\extensions\com.local.psz.panel.v5`，`public/` 放 manifest 和 lib。
- **原因**：省掉"构建 → 复制 → 忘复制某个文件"这类问题。`build` 即部署。
- **代价**：`emptyOutDir` 会清空目录，所以 `lib/all.decrypted.js` 必须来自 `public/`，不能手动放。
- **什么时候推翻**：需要同时维护多个扩展版本时（比如做灰度）。

## ADR-05 字体数据两套键名并存，不强行统一

- **决定**：`FontItem` 用 `family/weights/names/postScriptNames`（jsx 返回值），磁盘缓存 `SysFont2.json` 用 `name/zz/mz/hjm`，靠 `normalizeFont()` 转换。
- **原因**：两套都是外部既定格式（一套 jsx 给的，一套原面板写的），强行统一会导致要改写原面板的文件。
- **什么时候推翻**：如果我们自己接管了缓存文件格式（不再依赖原面板写入）。

## ADR-06 不引入 CSInterface.js

- **决定**：自己写 `eval-script.ts` 薄封装，不用 Adobe 官方的 CSInterface。
- **原因**：只需要 `evalScript` / `getSystemPath` / 事件三样；官方库 1000+ 行，且它的 `evalScript` 没有 Promise 化和超时。
- **代价**：CEP 事件（选区变化、宿主消息）以后要自己实现。
- **什么时候推翻**：需要大量 CEP 事件时，可以引官方库只取事件部分。

## ADR-07 mock 与真实实现是双路径（已知技术债）

> ⚠️ **已过期（2026-10-23）**：本条描述的代码已不存在。mock 统一到 `cep/jsx/mock.ts`（该文件第 7 行自述「替代了什么：旧 `ps.ts` 里的 `if (!hasCep())` 双路径」），`src/cep/ps.ts` 只剩 1 处 `hasCep()`（`:27`，初始化边界），对应债务条 D-01 已 done。本条自己的推翻条件是「第 3 个页面之前」，现在已有 12 个页面目录 —— 条件早过期而无人复核，这正是新增退出机制的直接原因。**正文保留**，因为它记录了当初为什么允许双路径。

- **决定**：`ps.ts` 每个函数里 `if (!hasCep()) return mock.xxx()`。
- **原因**：最快让 90% 的 UI 开发脱离 PS。
- **代价**：违反 DRY，新增函数容易漏 mock，漏了浏览器里直接崩。
- **什么时候推翻**：第 3 个页面之前，改成 adapter 接口 + 两个实现，或者在 registry 里加"每个导出函数必须有 mock 对应"的校验。

## ADR-08 样式数值只有一个来源

- **决定**：全部颜色/字号/间距/圆角/尺寸放 `src/styles/tokens.css`，组件里只引用变量，`style-guard` 强制。
- **原因**：原版 CSS 198KB 无作用域、色值散落，改一处要全局搜。
- **代价**：加新色值要走"先加 token 再用"两步。
- **什么时候推翻**：不推翻。需要主题切换时，加 `[data-theme]` 覆盖层即可，不用改组件。

## ADR-10 门禁只留一个强制点，其余升级成自动修复 / 自动生成

- **决定**：
  - `build` 就是 `vite build`，**不带任何检查**（`package.json:37`）；检查在 `check` 里（`package.json:21`，首条是 `style:guard`）
  - `registry` 改成**纯生成器**（扫描 + 自动补骨架 + 重写文档），不阻塞任何东西
  - 唯一强制点是 `npm run deploy`（= `check` + `typecheck` + `build` + `verify:dist`，`package.json:40`），部署前必跑
  - 不做 git pre-commit hook
- **2026-10-23 修正**：原写「`build` 里只跑 `style-guard`（99ms）」、「`deploy`（= check + build）」。实际 `build` 是 `vite build` 单条、不带检查；`style-guard` 在 `check` 链首（`package.json:21`）；`deploy` 实际四步（`package.json:40`）。**判据（门禁只留一个强制点，其余降级为自动生成 / 自动修复）未变。**
- **原因**：门禁净收益 = `p×L×n×(k−b) − c×n − m`。
  - 能被绕过的门禁（`b` 高）净收益接近 0，但成本照付 → 软门禁比没有门禁更差
  - 同一件事，做成「自动修复 / 自动生成」比「报错阻止」便宜一个数量级（前者机器干活，后者人肉改）
  - 门禁应该**事后建**（基于真实事故），不是事前建（基于想象）。`style-guard` 是颜色散落真实发生后才加的；`registry` 的"漏登记"一次都没发生过，所以降级
- **代价**：registry 不再强制，有人忘了跑，文档会过期。
- **什么时候推翻**：团队超过 2 人，或真的发生过"漏登记导致重复造轮子"。

## ADR-13 视觉规范：三处故意不照抄原版

- **决定**：
  1. 间距用 `gap`，不用原版的 `margin-right`
  2. 间距阶梯只有 4/6/8，不保留原版的 5 和 10
  3. 图标着色用 `fill: currentColor`，不引入原版的 `.svgfill` / `.svgColor0-7`
- **原因**：
  - 原版 CSS 里 `gap:` 出现 **0 次**，全用 `margin-right`（5px 用了 17 次、4px 16 次、6px 13 次）。那是 2019 年的浏览器限制，CEP 12 是 Chromium 99，`gap` 完全可用，且不会在最后一个元素留空白
  - 5px / 10px 不在 8px 栅格里，混用会让间距失去节奏
  - 预设色类只能覆盖固定场景；`currentColor` 跟着文字色走，hover 自动变，少一类样式
- **代价**：与原版像素级不完全一致（个别地方差 1~2px）
- **什么时候推翻**：要求像素级还原原版时，可以逐处改用 margin，但不要全局改回去
- **详细规范**：`docs/规范/视觉规范.md`

## ADR-12 写原面板数据文件前先备份，字段类型统一

- **决定**：改 `sj_ztglStar.ini` / `sj_ztglTags.ini` 之前，先把原文写到 `<文件>.bak`；星级统一写**数字**。
- **原因**：这两个文件是原面板的资产（用户攒的收藏和标签）。原文件里 `star` 有的写 `"3"` 有的写 `3`，
  混着写回去会让原面板读不出来；写坏了没有第二个副本。
- **代价**：每次写多一次 IO（几十字节，可忽略）；`.bak` 只保留最近一次。
- **什么时候推翻**：等我们完全接管这两个文件、原面板不再读它们时，可以去掉备份。

## ADR-11 CSS 全部内联进 JS，不产出独立 css 文件

- **决定**：产物只有 `index.js`（CSS 由 Vite 注入 `<style>`），没有 `assets/*.css`。
- **原因**：CEP 走 `file://`，少一次请求就少一个失败点（CSS 404 会导致裸 HTML）；也避免相对路径问题。
- **代价**：无法单独替换样式表；sourcemap 变大；单文件 638KB。
- **什么时候推翻**：需要“改样式不重新构建”的热替换能力时（那时连 JS 都要拆）。

## ADR-09 不做批量套版（原「叠印」页）

- **决定**：`/overprint` 路由和导航入口都删掉。
- **原因**：`Overprint.js` 实际是「变量设置 + 批量套版」（`switchdata: ["变量设置","批量套版"]`），跟印刷叠印无关；需求方明确不做。
- **代价**：如果以后要做，需要重新接 Excel 解析 + 批量导出 + PSD XMP 读写。
- **什么时候推翻**：需求方明确要。

## ADR-14 读可降级但必须标记，写不可降级（2026-10-23 扩展：拆 catch / 默认不兜底）

- **决定**：
  - 读：失败可回退默认值，但必须返回 `{ value, degraded }`；`degraded` 非空时界面显示"数据不可用"，**不许用假数据冒充真数据**。
  - 写：不允许降级。写失败必须抛，必须被 `feedback.error` 看见，必须进日志。
  - CEP 里没有 Node 时：读可以走 jsx `File`，**写必须抛 `NO_NODE`**，不许退回内存。
- **原因**：
  - 面板里没有"刷新页面"，读失败用 fallback 能保住可用性；但 fallback 一旦不可见，用户会照着错数据做决定。
  - 写的是用户资产（收藏、标签、动作库、样式库），静默失败等于丢失，且无法事后补。
- **实证**：两处原始事故是"读失败拿假数据顶上"与"写失败被吞"。**现存承接点**：`src/cep/data/classification-repo.ts:94`（读失败返回 `degraded: '分类数据读取失败'`，不再返回只有 2 条 `commercials` 的 MOCK，D-14）与 `src/cep/data/file-repo.ts:161-163`（读坏抛 `IO` 拒绝覆盖写、文件不存在拒绝写入，D-42；普通写在 `:134` 直接抛、不 catch）。
- **2026-10-23 修正**：原实证锚点 `classification.ts:95-118` / `json-file.ts:49` 指向的文件已不存在（改名为 `cep/data/classification-repo.ts` / `cep/data/file-repo.ts`，且两处缺陷已修）。换成上面对应的现存行号；**判据（读可降级但必须标记 / 写不可降级）未变。**
- **代价**：每个仓库多一条 `degraded` 分支；UI 需要一个位置显示"数据不可用"。
- **什么时候推翻**：不推翻。

### ADR-14 扩展一：拆 catch——默认不写，写就必须让坏可见

- **判据**：
  - **默认不写 catch。** 异常往上走：命令里的异常由 `execute` 统一归一（`src/commands/registry.ts:133-137`），渲染期的异常由 `ErrorBoundary` 接。
  - **必须 catch 时只有三条出口**，至少命中一条：① `log.error` / `log.warn` 后继续抛；② 降级并返回可显示的 `degraded`（本 ADR 正文）；③ 转成 `CepError` / `CloudError` **带原因**重抛。
  - **禁止静默吞**：`catch {}`、`catch { return 默认值 }` 且全程无信号，一律违规。
  - catch 只包**会抛的那一行**（解析 / IO / 第三方调用），不包整段流程——包大了会把无关错误并进同一条分支。
- **实证（本仓）**：
  - `src/cep/data/action-archive.ts:69-71`：`catch {}` 里只有一句注释"清理失败只留下孤儿文件，不回滚已成功的索引"。没有 `log`、没有返回值、没有界面信号——磁盘上多了孤儿文件，用户与日志都不知道。
  - `src/cep/transport.ts:115-119`：`JSON.parse` 失败被 `catch { return raw as unknown as T }` 变成"成功返回一个字符串"，还顺手用双转型骗过类型（同一条也是 ADR-24 的实证）。
  - `src/cep/data/sys-font.ts:21-26`：`catch { return [] }` 把"JSON 坏了"和"文件不存在"压成同一个结果，于是 `src/cep/ps.ts:79-81` 只能报「读不到 SysFont2.json」——**原因丢了**，排查时分不清解析失败还是文件没了。
  - 合规样板：`src/commands/registry.ts:133-137`（归一 + `log.warn` + 返回 `reason`）、`src/cep/data/legacy-settings.ts:112-116` 与 `src/cep/cloud/transport.ts:78-82`（转成带原因的 `CepError` / `CloudError` 重抛）、`src/pages/fontSet/index.vue:158-164`（`log.warn` + 空下拉 + 注释写明为什么不阻塞）。
- **什么算违规**：

  | 写法 | 判定 | 为什么 |
  |---|---|---|
  | `catch {}` / `catch { /* 只写注释 */ }` | 违规 | 错误消失，用户与日志都不知道 |
  | `catch { return [] }` / `return null` / `return ''` | 违规 | 把"坏了"伪装成"没有"，下游无法分辨 |
  | `catch { return 默认值 }` 且无 `log`、无 `degraded` | 违规 | 用户会照着错数据继续操作 |
  | catch 后 `as T` / `as unknown as T` 把原始值当解析结果 | 违规 | 解析失败被当成成功 |
  | `try` 包住整个函数体 | 违规 | 分支过宽，无关错误被并进来 |
  | `catch (e) { throw new CepError('IO', '读取失败：' + e.message) }` | 合规 | 重新抛，失败可见 |
  | `catch { log.warn(...); return [] }` | 合规 | 能在「打开日志」里查到 |
  | 降级并返回 `{ value, degraded }` | 合规 | 本 ADR 正文的口径 |

- **与本 ADR 正文的关系**：正文管"读/写各自能不能降级"，本扩展管 **catch 的存在方式**——同一件事的两种切面，不是两条规矩。

### ADR-14 扩展二：默认不兜底——兜底 = 掩盖

- **判据**：
  - **默认不写兜底。** 缺文件就报缺文件，解析失败就报解析失败，字段没有就让生产者保证有（ADR-24）。
  - **确需兜底的只有一种前提**：不兜底就白屏 / 崩溃（`AGENTS.md` 决策优先级第 1 条）。此时必须同时带**可见失败信号**，并把降级写进返回结构（`{ value, degraded }`）或界面（空态文案 + 重试）。
  - **验收看"兜底净减"，不看"症状消失"。** 症状消失可以是兜底把它盖住了；判据是这次 diff 里 `?? 默认` / `catch → 默认值` 在减，且被盖住的错误现在有信号。
  - 兜底不许落在**数据 / 语义层**（假数据、默认值、猜的字段让流程继续走），只许落在**渲染层**（空态 + 说明 + 重试）。
- **实证（本仓）**：
  - `src/cep/cloud/ledger.ts:42-43`：`catch { return null }` 让"台账读坏"与"从来没有台账"在类型上不可区分（都是 `null`），`src/cloud/engine.ts:113-116` 据此报 `hasLedger:false` / `rev:0` / `localHash:''`——三方比较的 base 直接变空，且没有一个字告诉用户台账坏了。
  - `src/pages/style/index.vue:282-288`：页面自己 `catch { cachedUserDir = '' }`，之后照常渲染；"没有 Node"与"读到了空目录"在页面里长得一样。
  - 净减实证：`src/cep/data/file-repo.ts:116-117` 写死"写失败必须抛：这里不做任何兜底（ADR-14）"；`src/cep/data/free-panel.ts:89-92` 把 `normalize` 接到**读边界**，消费点的 `?./??` 因此全删（commit `c41cab8`：拆 `file-repo` 的 `as T`、删自由面板 7 处 `?./??`）。
- **什么算违规**：

  | 写法 | 判定 | 为什么 |
  |---|---|---|
  | `const x = res.data ?? []` | 违规 | `data` 缺失该由生产者保证，消费侧补等于替它撒谎 |
  | `catch { return 默认值 }` 且无信号 | 违规 | 错误变成"看起来能用" |
  | 读坏时用 MOCK / 假数据顶上 | 违规 | 用户照着假数据做决定（本 ADR 实证里的原始事故） |
  | 页面 `catch { x = '' }` 后照常渲染 | 违规 | 页面替数据层决定"没有就算了" |
  | 写失败退回内存态 | 违规 | 本 ADR 正文：写不许降级 |
  | 空态 + `degraded` 文案 + 重试按钮 | 合规 | 降级喊出来了（`src/pages/freePanel/components/FreePanel.vue:28-34`） |
  | 读坏返回 `{ value: 种子, degraded }` | 合规 | 信号在返回值里，页面能显示 |

- **与"不白屏"的边界（表面冲突，判据不冲突）**：

  | 场景 | 允许 | 禁止 |
  |---|---|---|
  | 页面级读失败 | 空态 + `degraded` 文案 + 重试 | 渲染假列表让页面"看起来有数据" |
  | 列表为空 | 显示"还没有…" | 读坏时也显示"还没有…"（把坏了说成空的） |
  | 面板整体渲染 | `ErrorBoundary` 接住并显示原因 | 用 `try/catch` 包住 `render` 把白屏变成空白 |

  一句话：**渲染层可以保命，数据层不许造假**。判据是兜底之后**用户能不能知道"这是坏的"**——能，就是合规降级；不能，就是把错误变成"看起来能用"。

- **与本 ADR 正文的关系**：正文的"读可回退默认值，但必须返回 `degraded`"是本扩展"必要前提"的**唯一实例**；本扩展把正文里"必须标记"这个形容词收紧成判据——**用户必须能看见**。两条同时成立，谁也不推翻谁。

## ADR-15 数据文件四种形态，全部收口在 `data/`

- **决定**：持久化只允许出现在 `data/`，按四种形态处理：
  1. 平铺 JSON（`sj_dzStoreInfo.json`、`sj_set.json`）
  2. 子目录多文件（`kuStyle/`、`Gradient/`）
  3. 外部交换（`.dzx`、`.cmm`、样式预设：任意路径 + 文件对话框）
  4. 低容忍高频写（星级、标签、`sj_ztglFrequency.json`、`sj_ztglHistory.json`）
  每个文件一个 `Repo<T>`：per-file 串行队列 + 原子写 + `.bak` 备份 + `onChange` 订阅。
- **原因**：20 个数据文件全部来自原面板 `$config.path`（`app.v4.js:5208-5242`），**原面板会同时读写同一批文件**，所以读只能容错、写必须保守。四种形态的 IO 语义差别很大（目录枚举、任意路径、高频写），不集中收口就会各写一套。
- **实证**：`json-file.ts` 与 `prefs.ts` 是两套读改写实现（一个有备份/原子写，一个没有）；`jsonFile.update` 是裸的 `await read → write`（`json-file.ts:59-65`），连点星级丢更新。
- **代价**：新增数据文件必须先加一行仓库定义，不能"随手 readFileSync 就改"。
- **什么时候推翻**：我们完全接管这批文件、原面板不再共存时（可去掉 `.bak` 与部分容错）。

## ADR-16 有副作用的操作定义为命令，注册在 `commands/`

- **决定**：
  - 一切会改变 PS 文档、PS 应用状态或用户资产的操作，必须定义为 `Command`（`id / title / group / icon / requires / kind / run`），注册在 `commands/`。
  - 页面、常用页、自定义面板、快捷键**只消费注册表**（`commands.list` / `useCommand`），不各自实现操作。
  - `stores/` 降级为只读投影，不再导出写方法。
  - `commands.execute` 是唯一执行入口：`requires` 检查 → `run` → catch 归一 → 日志 + 耗时。
- **原因**：
  - 原版用 `$appBus` 让同一批操作被至少 4 个入口触发（`anon_56d7_L34996.md:70-90`）。没有命令这个单位，同一功能只能在每个入口各写一遍。
  - 设置页管理的正是"命令的显隐 / 顺序 / 快捷键"，即命令元数据；导航和常用功能列表都是它的投影。
  - 命令 id 是唯一能把 UI、设置、快捷键、日志、错误归因串起来的稳定标识。
- **代价**：新增功能至少两个文件（命令定义 + 实现），比"直接在组件里写方法"多一步；8 个页面的量级可接受。
- **什么时候推翻**：不推翻。命令总数长期少于 10 时不必引入注册表（现在已经超过）。

## ADR-17 与 PS 之间是双向的：命令下行，事件上行

- **决定**：
  - 应用 → PS 只有一条路：`commands` → `cep/jsx` → `cep/transport`。
  - PS → 应用也只有一条路：`cep/events`（`subscribeHostEvent`）。
  - 新增宿主事件只改 `EVENT_IDS` 一行 + 一个消费者，**不许为某个页面单开私有订阅**。
  - 文件 → 应用**不做监听**（外部变更靠切页重读），这是明确取舍，不是遗漏。
- **原因**：
  - 只有下行时，任何"跟随 PS 状态变化"的需求都会退化成"在页面里操作前查一次"。
    P8 字体面板要当前文字属性、P7 常用页要选区类型、P6 动作页要文档切换、P10 重命名要图层选择——
    四个页面四套查法，查询点散落，行为不可统一。原版就是这么散的。
  - 把宿主状态做成基础设施后，`selection` 只是第一个消费者，`fontInfo` / `document` 复用同一条通道。
- **机制依据**（不是猜）：原版 `app.v4.js:4985-4993` 用 `dispatchEvent` 注册 + 监听
  `com.adobe.PhotoshopJSONCallback<扩展ID>`；`69399-69407` 的回调解析是
  `JSON.parse(data.substring(5))`、按 `eventID` 分发、**100ms 去抖**。
  事件 ID 由 jsx `charIDToTypeID("slct")` 取，不硬编码。
- **代价**：事件注册与回调格式按源码契约实现，不在本轮做额外验证。
  注册失败/事件不来时自动退回"执行前查询"，功能不受影响；通道可用性由 `cep/events.ts` 的
  `hasCepEvents()` 提供（原 `ps.ts` 的 `runtimeInfo()` 已于 2026-10-22 作为零调用死代码删除）。
- **什么时候推翻**：CEP 版本不支持 `dispatchEvent`（旧版）时通道恒不可用，退化为纯查询；
  结构不变，只是 `events` 恒为 false。

## ADR-18 `build.target` 用 `esnext`，不用 chrome91

- **现象**：`npm run build` / `npm run deploy` 在 Windows 上必失败，报
  `remove ...\Temp\esbuild-<hash>: Access is denied`（esbuild 0.28.2）。构建产物没出来，
  `verify-dist` 也就跑不到。
- **根因**：不是项目代码的问题，是**esbuild 0.28.2 在 Windows 上删不掉自己的临时目录**。
  报错发生在 Vite 的**产物级** `vite:esbuild-transpile` 那一步（大输入整包转译之后清理临时目录）。
  该插件**只在 `build.target !== 'esnext'` 时运行**——目标里有需要降级的语法它才介入。
- **证据**：
  - 报错原文：`[vite:esbuild-transpile] remove ...\Temp\esbuild-<hash>: Access is denied`（exit 非 0）。
  - 三个反证（都试过、都还报同样的错）：换 TEMP 盘符、换短路径、设 `ESBUILD_TMPDIR`；
    以及脱离 shell 用独立进程跑构建 —— 与调用方式无关。
  - 对照实验：**模块级 transform 正常**（dev / vitest 里 esbuild 跑得好好的），
    只有产物级 transpile 崩 —— 说明不是"esbuild 完全不能用"，而是"这一步的临时目录清理"必挂。
  - 决定性验证：把 `build.target` 提到 `'esnext'` 后构建成功，产物 1.13 MB，`verify-dist` 通过。
- **决定**：`vite.config.ts` 的 `build.target` 改为 `'esnext'`，跳过产物级 transpile。
- **代价**：产物不再向 chrome91 降级语法，现代语法（`?.`、`??`、类字段等）原样保留。
  CEP 12 = **Chromium 99**，这些语法都支持，风险可接受；但"支持 chrome91"这条保证没了。
- **被放弃的方案**：
  - 改 esbuild 版本（升/降级）——本轮不许动依赖，且没验证过哪个版本不犯这个毛病；
  - 给 Defender 加排除 / 改系统清理策略——改的是开发机环境，换台机器就复现，等于把问题藏起来；
  - 给 `node_modules/esbuild` 打补丁——离线重建就失效，属于"补丁式绿灯"，不做。
- **什么时候推翻**：换机器、或 esbuild 升级后再验证一次 `Access is denied` 是否消失；
  只要它不再复现，就应把 `target` 回到 `'chrome91'`，并复核 `verify-dist` 与真机面板。
  另外：如果 CEP 目标运行时降到 Chromium 99 以下（换 PS 版本），这条必须重新评估。

## ADR-19 跨页拖拽统一走指针事件 + 长按门槛，不用 HTML5 DnD

- **决定**：
  - 全项目拖拽统一走指针/鼠标事件（`mousedown` / `mousemove` / `mouseup`）+ 300ms 长按门槛；实现收口在 `src/composables/useLongPressDrag.ts`，落点计算收口在 `src/domain/reorder.ts`（`DropPosition = 'before' | 'after'`）。
  - HTML5 DnD 全部废弃：`components/ActionGrid.vue` 不再提供 `draggable` 与 `dragstart` / `dragover` / `drop`；动作页 / 重命名页 / 自由面板的迁移见台账 T-67（**T-67 已 done：三页全部迁完，`git grep -n 'draggable' -- src/pages` 零命中**）。
  - 两套机制不许混用（`useLongPressDrag.ts:4` 已写死这条）。
- **2026-10-23 修正**：原写「当前三页仍是 DnD，属于待迁移状态，不是已完成」。T-67 已 done：`src/pages/action/index.vue:77` 与 `src/pages/freePanel/components/FreePanel.vue:172` 都留着"旧的 HTML5 DnD 已删，T-67"的注释，`src/pages` 下 `draggable` 零命中，`useLongPressDrag.ts:2` 自述"T-67 起三页已迁完"。**判据（拖拽统一走指针事件 + 不许混用）未变。**
- **原因**：
  - 动作页最初用 HTML5 DnD 是**没有经过方案权衡就直接实现的**；重命名页按「复用第一页已有实现」照抄，错误被复制了两次；直到样式页才按原版 `am()`（`app.v4.js:37402-37532`，全文件 15 处调用）复刻出正确机制。
  - **原版实现只是输入之一，不是结论**：选指针事件的真正理由是下表对比，不是"原版这么做"。

  | 维度 | HTML5 DnD | 指针事件 |
  |---|---|---|
  | 拖动中视觉可控性 | 拖影是浏览器截的静态图，改不了 | 可克隆 `opacity:0` 占位 + 浮层跟手 |
  | 长按门槛 | `dragstart` 立刻触发，做不出 300ms | 自己控时机（`mousedown` 起计时） |
  | 精确落点（插前 / 插后） | `drop` 只给目标元素，插前/插后要靠 class 猜 | 自己算布尔（`domain/reorder.ts` 的 `DropPosition`） |
  | 自动滚动容器 | 浏览器代劳 | 要自己写 |
  | 代码量与边界处理 | 少 | 多，要管指针捕获、清理、边界 |
  | CEP 内可用性 | `dataTransfer` 在 CEP 里未验 | 纯 DOM 事件，最稳 |

- **代价**：
  - 指针事件要自己处理滚动容器自动滚动与边界：`useLongPressDrag` 目前只把 `scrollRoot.scrollTop` 计入落点坐标，没有自动滚动，T-67 迁移时补。
  - `useLongPressDrag` 与 HTML5 DnD 绝不能混用（该文件 `:4` 的注释已写这条）；迁移期两套并存，必须按页切换，不能在同一页混用。
- **什么时候推翻**：出现触摸 / 手写笔等需要原生手势语义的场景，或 CEP 升级到支持 `PointerEvent.setPointerCapture` 更完整时再复核。
- **落地**：台账 T-67。

## ADR-20 原版源码不入库，锚点按美化版记

> ⚠️ **已被 ADR-25 取代（2026-10-23）**：源码已于 2026-10-23 入库（`docs/原版/`，commit `36472b3`，1472 文件），"不入库"的前提没了；"检索用字符串定位、不按行号"也随之作废——**行号现在就是可当场复核的锚点**。本条正文保留，因为它记录了"为什么当初只能靠字符串定位"（压缩版可读、美化版不入库）。仍成立的部分：别的插件安装副本不得据以核对（版本不一致）。

- **代价**：
  - 行号锚点在压缩版上失效，只能当"美化版的坐标"用；
  - 压缩版函数名被 mangle，函数级定位要靠调用处的字符串；
  - 文档里的行号一旦美化设置变了就会漂移。
- **复核方法**：
  - 前置条件：先取得**与文档调查同版本**的压缩源码；2022 安装版不可用（见上）。

    import re
    from pathlib import Path

    SRC = Path('<与文档同版本的压缩源码路径>')

    key = 'ys_getFontInfo'  # 换成要查的 class 名 / jsx 函数名 / stringID / 提示文案 / 后缀

        start, end = max(0, m.start() - 400), min(len(text), m.end() + 400)

  - 结论标注格式：`已核（<源文件名>，字符串定位：<关键字>）`，**不写行号**。
- **什么时候推翻**：拿到可入库的授权副本时；或取得与文档同版本的源码并把锚点重挂到它上面时。

## ADR-21 云同步改为事件驱动 + 启动补偿，去掉定时器（快进暂不做）

- **决定**：
  - 同步**不再由定时器驱动**。去掉 2 小时的 `setTimeout` 自链（`src/cloud/auto-sync.ts:20-23,25-39`）。
  - 触发点统一为 5 个：① 各 unit 的 repo `onChange` ② 面板启动 ③ 变可见 ④ 变隐藏 ⑤ 手动点同步。
    **所有触发点只做 `markDirty(unit)` 入队，一律不发请求**；请求只由队列统一发。
  - 频率：**60 秒防抖 + 5 分钟最大等待**（连续编辑时最多 5 分钟一定推一次）。
  - 判定仍是 **per-unit 三方比较**（base / mine / theirs），但**单机是主场景**（约 90%）：单机时 `theirs` 等于自己上次推的，判定自然退化为 `mine vs base`，不需要额外分支。
  - **不加"push 后回读校验"**。它是为 pull→push 窗口的并发设计的；单机基本不出现，代价是每次推送多一次往返。
  - **双方都改 = 冲突，永不自动合并**。unit 内部从无字段级 merge，强行合并就是静默丢数据。
  - `document.hidden` **当信号用，不当禁止用**：变隐藏 flush 一次、变可见 sweep 一次；删掉 `if (document.hidden) return`。
  - **自动快进（本地干净就拉云端）不做**：要 5 个前置条件同时成立，单机场景永不触发，`grep 快进 src/` 零命中。标题原先写了「+ 快进」，与实现不符，已改。
- **原因**：
  - 我们的通道是**自建 GAS 整包快照** POST（`src/cep/cloud/transport.ts:26`），不是原版 `sync/file-list/part/add` 的分片按文件上传。原版 3 秒防抖（`56d7.js:9562`）成立的前提是"每次只传一个变更文件"，在整包上传下 3 秒会把 GAS 和 JSON 打爆——**所以 60 秒是通道决定的，不是偏好**。
  - CEP 面板是寄生在 Photoshop 进程里的页面，**PS 一关整个 JS 上下文就没了**，不存在"关掉之后还继续同步"的物理可能。因此"每 2 小时同步一次"从来不是同步机制，而是"面板活着时的自链定时器"，且被 `document.hidden` 拦掉一半。
  - 真正决定可靠性的不是频率，而是**启动补偿**：面板打开时读 `cloud.pending`（已落盘但此前无人读）→ pull → 补推本地更新的 unit。没有这一步，"改完就关 PS"必然漏。
- **代价**：
  - **PS 关闭期间不同步**，且无法解决——除非将来有后台能力（见"什么时候推翻"）。
  - pull→push 窗口里的多机并发仍可能互相覆盖（服务端不做租约：`docs/架构/云同步底层设施.md:23-24` 明确"整包 rev；后写覆盖先写"）。**接受这个风险**，因为单机是主场景；靠"冲突可见"兜底，不靠回读校验。
  - 面板开着时若发生快进，列表会突然变（repo emit → store 刷新），用户可能觉得"我没动它怎么变了"——是解释成本，不是数据风险。
- **什么时候推翻**：
  - 拿到可入库的后台执行能力（独立进程 / 系统级定时任务）时，"关闭期间不同步"这条代价消失，频率可重新评估。
  - 若 GAS 换成按文件分片上传，"3 秒不行"的前提消失，防抖可下调。
  - 若实测发现 CEP 隐藏时 `fetch` 会被挂起（未在真实环境验证，标 `UNVERIFIED`），则退回"延迟到可见时再发"，但仍不丢弃。

## ADR-23 消费者只能转发，不能猜生产者

- **决定（判据）**：
  - 页面 / 组件 / store 对生产者的产出**只做转发**：拿到什么显示什么。
  - **不许自己拼文案**：失败文案由 `describeCepError` / `CommandResult.reason` 给，页面不另写一句"请检查…"。
  - **不许重分类**：不按错误文案、`code`、字段有无重新判断"这算什么错"；分类只在生产者或 `commands` 层做一次。
  - **不许下因果结论**：不知道原因就不写原因（"请检查导出目录与参数"这类）。
  - **不许替生产者决定可见性与频率**：提示一次还是两次、toast 还是内联、要不要防抖，都由产出失败的那一层决定；消费者只把已经决定的东西显示出来。
- **由来（实证）**：
  - `src/pages/commonUse/components/PanelExport.vue:85-86`：命令层失败时 `useCommand` 已经 `feedback.error(result.reason)`（`src/components/command/useCommand.ts:41-44`），页面又补一条自造文案「导出失败：请检查导出目录与参数后重试」——**同一个失败提示两次**，且"目录与参数"是页面猜的因果。
  - 同一个 `degraded` 被三页拼成三种后缀：`src/pages/action/index.vue:487`「动作库可能不完整」、`src/pages/commonUse/index.vue:330`「常用项可能不完整」、`src/pages/rename/index.vue:497`「预设可能不完整」。生产者只说了"哪份数据没读出来"，"可能不完整"是三页各自加的结论。
  - 合规样板：`src/components/command/useCommand.ts:21,41-44`（"失败自动 toast，调用方只拿 boolean"——页面拿不到文案，所以写不出第二条）；`src/pages/freePanel/components/FreePanel.vue:28-34`（整句用生产者给的 `degraded`，注释写明为什么不能显示"还没有自由面板区域"）。
- **什么算违规**：

  | 写法 | 判定 | 为什么 |
  |---|---|---|
  | 页面 `if (!ok) feedback.error('导出失败：请检查…')` | 违规 | 拼文案 + 猜因果 + 双提示 |
  | 页面按 `message.includes('超时')` 换一种提示 | 违规 | 重分类 |
  | 页面把 `degraded` 再加工成"可能不完整" | 违规 | 下因果结论（生产者只说"哪份没读出来"） |
  | 页面给同一个失败加防抖 / 去重 | 违规 | 替生产者决定频率 |
  | 页面 `try/catch` 包住 `run()` 自己 toast | 违规 | 绕开 `useCommand` 这个唯一消费点 |
  | 页面只渲染 `degraded` / `error` 原句 | 合规 | 转发 |
  | 前置校验直接 `feedback.error`（空名、重名） | 合规 | 硬规则 4 明确允许：这不是生产者产出 |

- **与既有 ADR 的关系**：
  - **ADR-16 是上游**：它规定"有副作用的操作定义为命令、`commands.execute` 是唯一执行入口、`stores/` 降级为只读投影"；本条接着规定"命令结果只能被转发"。同一条链的两段：**生产在命令层，消费只转发**。
  - **ADR-14 的 `degraded` 是本条的输入**：生产者给信号，消费者负责显示、不负责解释。ADR-14 没规定"显示成什么"，本条补上"原句显示"。
  - 本条不推翻任何既有 ADR。
- **与硬规则 20 的关系**：本条是判据面，硬规则 20「规矩二：消费者不许替生产者捏造信息」是执行面。规矩二管数据面（补字段、补默认值），本条管语义面（补文案、补分类、补因果），同一个根：消费者一旦开始补，生产者就永远不知道自己缺了东西。
- **什么时候推翻**：若命令层不再产出 `reason` / `degraded`（例如改成直接抛给页面），本条的"转发对象"消失，那时要重写而不是作废。

## ADR-24 缺了先补生产者：禁消费侧转型 / 默认值 / 猜字段

- **决定（判据）**：
  - 发现类型 / 字段 / 返回值 / 契约缺了，**去补生产者**（改签名、改类型、改实现、改契约），**不改消费者的断言**。
  - 消费侧禁止三件事：`as any` / `as unknown as`（双转型）、`?? 默认` / `|| 默认` 补缺字段、按形状猜字段（`(x as { id?: string }).id`）。
  - **唯一例外是第三方边界**（`window.__adobe_cep__`、`process.env`、CE 注入的 `require`）：先写 `.d.ts` / `declare global` 让类型存在，实在补不了才在调用处转型，且必须写 `// 断言理由：…`（守卫 `npm run assert:guard` 认这个标记）。
  - **生产者物理上不可达时（原厂 jsxbin）**，归一收口在**单一适配层**：`domain/font-normalize.ts`（jsx 返回值 → `FontItem`）、`utils/jsx-result.ts`（`res.err === 1` 之类）、`domain/free-panel.ts` 的读边界。**只许一处**，且标 `UNVERIFIED`；不许在每个消费点各补一份。
- **由来（实证）**：
  - `src/commands/commonUse.ts:547-553`（T-97-8 真机 bug 的现场记录）：数据层 `readCommonUseOptions()` 是 `async` 且返回 `{ value, degraded }`，消费侧写成 `as unknown as Record<string, unknown>` 把 Promise 当对象用，分支恒为 `'none'`——**点了没反应、不报错、测试全绿**。修法是改生产者签名（这里写成 `readOptions: () => Promise<...>`），不是改断言。
