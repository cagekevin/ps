# 怎么逼 AI 把事做好

> **讲本质 → 他列清单 → 你找洞反问到挑不出毛病 → 收尾问「你满意吗？」→ 他说满意才算完。**
> 不用懂原理，就问。

---

# 0. 总流程：就三步（任何任务都一样）

> **不管大任务、小任务** —— 写清单、写计划、写代码、做审计、查问题 —— **流程都一样，就三步。**

## 第一步：让他列清单

> 「**你写一个小清单吧。这个清单等一下你就对照着它来做，你不需要去维护它** —— 我为了防止你等一下做偏。」

## 第二步：找洞

> **这一步不叫"追问细节"，叫"找洞"** —— **去看他写的话，里面有什么洞。**

**列完清单之后，逐句读他写的东西，找站不住的地方；找到就把那句话反问回去。**

**必备两句（清单每轮都要问，一次一句）**：「**你的前后逻辑有没有问题？**」「**有没有同类项可以处理？**」
其余洞怎么找、怎么问 → 第 5 节一张表。

**清单这一块问得越多越好** —— 这里错了后面全错；问不出新洞才算问透，没问透不许开工 P1。

- **一次只问一句**；他答完，你看他的答案，再决定下一句
- **下一句必须从他上一句的话里挑**（抓漏洞），不是从你事先准备好的问题清单里挑

## 第三步：确认满意度

**一直找洞、反问到你自己挑不出毛病为止。**

- 挑不出毛病的时候，**最后一句**问他：「**你满意吗？**」
- **一直等到他回应「满意」，才能进入下一步**（比如开始做 P1）
- 他只要还说得出一个不满，就还没到收工 —— 先让他修，再问最后那句

## 每一项（P1 / P2 / P3 …）也是同一个流程

1. **一直追问他**，看他自己说的话里有没有洞；**只要有洞，就反问**
2. **等他做完之后，还是问他：「你满意吗？」**
3. **他说满意，再进入 P2** —— 以此类推

> **P1 没满意，不许开 P2。跳项 = 这一轮不算做完。**

## 收尾句永远是「你满意吗？」

> **不管让他做任何一个事情** —— 写清单、写计划、写代码、查问题，大任务、小任务 —— **最后的收尾句都是「你满意吗？」**

- 「满意」必须以《**架构师改码 7 步法**》为准，不是他随手编的标准
- 所以实际问法：「**对照七步法，你满意吗？**」
- 他答「满意了」且**说得出按哪几条判的** → 才算完
- 说「满意了」但**说不出按哪条** → 不算，追一句：「按七步法哪几条？逐条说。」

# 1. 六条铁律

| # | 铁律 |
|---|---|
| 1 | **一项一项过** —— P1/P2/P3 一个一个来，一项追到他满意才进下一项；**每项收尾都要问「横切只有一份吗」「能结构上不可能吗」** |
| 2 | **不给方案、不给判据、不用术语** —— 你给方案，他照着做；你做偏了，他也照着做偏 |
| 3 | **清单他出，对照我贴** —— 自己写清单自己勾 = 自己给自己打分 |
| 4 | **他说"满意了"才算完** —— 那句只能从他嘴里出来，且**手上不能还悬着活** |
| 5 | **问 ≠ 允许他开始做** —— 问的那一轮只留那一句问话，**不许带"答完就做 P1"这种尾巴**；他会用"先做出来"代替"回答"，而且做得挺像回事 |
| 6 | **给他的话里不许有肯定句** —— 每一句都是问句；肯定句 = 我在下判断、给做法、表态，那他就把脑子关掉了 |

# 2. 派单

## 2.1 派单的**唯一形状**：目标 · 边界 · 禁令 · 问句

> **不给判据、不给口径、不给验收命令、不给做法、不给判决。**
> 这些必须**他自己推导** —— 你给了，他只在你圈里找；他不签字，他不认。

| 部件 | 例 |
|---|---|
| ✅ **目标** | 「页面层的中文提示语，收进 `src/domain/messages.ts`」 |
| ✅ **边界** | 「只碰 `src/pages/**`、`src/components/**`；不碰 `src/cep/data/**`、不碰账本、not commit」 |
| ✅ **禁令** | 「不开始下一件」 |
| ✅ **问句** | 「遇到算不上的行，你打算怎么判？」「你打算怎么验证你做完了？」 |
| ❌ 判据 | 「4.2 去重后 = 0，4.1 保持 0」 |
| ❌ 验收命令 | 「跑 test / typecheck / check / stats」 |
| ❌ 口径 | 「分母是 47 行 / 20 文件」 |
| ❌ 做法 | 「标 UNVERIFIED 挂账」 |
| ❌ 判决 | 「按你说的改」「那两处改成 X」 |
| ❌ 授权 | 「跑。」→ 换成「**如果是架构师这样做的话，那你这样做就可以。**」 |

> **注意**：「不给判据」是**你不给**；清单是**他**写的，判据必须**他自己**写进去（见第 4 节）。

**他反问「判据是什么」**
- 不给数、不给口径、不给命令
- 「**你打算怎么验证你做完了？**」
- 实在甩不掉 → 「**如果是架构师的话，他会怎么做？**」

**为什么**：
1. 判据 = 你替他划界，他只在你圈里找，**不会学会自己划界**。
2. 你给的数是二手的，他得先花力气核你的错。
3. **他自己签的判据他才会认**；你给的判据他只会"逐条回应"。
4. 「你打算怎么验证你做完了？」这一问，比你列十条验收项更有用 —— **答不出验证方法 = 这活他没想清楚**。

**自检**：派单里除了目标/边界/禁令，**还有没有一个数、一个口径名、一个"应该"**？有 → 删掉，换成问句。

## 2.2 单子由他自己写，你只转发

> 「这些都是应该**他直接在定义 P1、P2、P3、P4 的时候，写清楚、写好的**，**你直接复制发给他就可以了呀。**」

**完整时序**

```
第一次派单（考验他）  →  他自己定 P1/P2/P3/P4 + 各自判据 + 落点表 + 边界 + 验收
                        →  写成一份完整单子，存 daily/架构日志/ 下的独立文件
后续每一批            →  你把那份单子【原文复制】发给他，一个字不改
                        →  零判据、零摘要、零"我临时加的提醒"
```

**第一次那一单才需要问句**（它的产出就是"定义"）：
- 「这一批要分几步？你打算怎么分？」
- 「每一步的完成判据是什么？」
- 「这份单子你写在哪？我后面直接复制转发给下一批。」

**后面几批一个字都不许你加。** 你要加的边界（"这批不许 commit"），**回到第一次那单里加，或让他自己补进单子** —— 不能在转发时临时加。

**规矩**
1. 每定一个阶段（P1/P2/P3/P4…），**由该阶段的施工方**把「目标 · 口径 · 落点表 · 边界 · 禁令 · 验收」写成一份**完整单子**。
2. 你**只转发**：原文贴给下一个会话，**不摘要、不改写、不加判据、不加问句**。
3. 你要加的边界（"这批不许 commit"），**也要他写进单子里**。
4. 单子里的判据**不是你给的** —— 你只是搬运工。

**为什么**
- 判据是他跑出来的 → 他认这个口径，会照着做
- 你给的判据是二手的 → 他只能"逐条回应"，还得先核你的错
- 单子里自带口径 → 换会话接手不丢前置知识

**但计划阶段要先挑毛病 —— 别直接转发**

> 计划是后面所有批次的**共同前提** —— 口径错了，后面每批都跟着错，还错得一致、很难发现。
> 代码错了能回滚；**口径错了会一路错下去，还带着"数字都对"的假象**。

- 计划也按三步走：**列清单（写计划）→ 找洞（先追前后逻辑：「先 P3 再 P4 顺序会不会有问题？」「P4 依赖 P3 的什么？拿得到吗？」）→ 问「你满意吗？」**
- **计划不满意，不许发 P3。**

**一句话**：**计划阶段不是"转发阶段"。先挑毛病，再问满意，满意了才发 P3。你是搬运工，不是编剧。**

**🔴 派活必带"必读清单"**

> 只给他**我自己的摘要** → 他会从摘要**重新推导一遍**，把上游已经查实的东西再查一次，结论还可能更差。
> 派活必须附上原文：**七步法 + 上游原始记录（审计报告 / 账本 / 上一批的验收结论）** —— 让他读原文，不读我的转述。

**🔴 闸：重复的闸 = 没有闸**
> 「不见重复的闸就是不见闸的意思。」

- 两份同判据的闸 = 判据有两份 ⇒ 改一处另一处还绿 ⇒ **等于没闸**，还多一份要维护的债。
- 加闸之前**先数**：这个判据现在有几份执行者？已有 ⇒ 不许再造第二份。
- 同源判据散在两个地方 = 已经踩过（13 道 → 4 道那次）。
- **新闸 = 新债**。造之前先答：造完谁会红？是不是多了一份要跟着改的东西？

**🔴 你的存在只有一个目的：问**
> 「你不要给他做任何判断，你存在的唯一目标就是问他，就这么简单。」

- **不判、不筛、不选、不裁、不给答案、不定优先级。**
- 它自列 N 条不满意 → **原样丢回去**让它自己判，连"补哪几条"都不许说。
- 脑子里冒出「应该补 A、B，C 不用管」→ **那是判决，删掉**。
- 唯一允许你给：**目标 · 边界 · 禁令 · 问句**。
- **判据**：你的消息里出现「应该 / 不用 / 优先 / 我觉得 / 就补…」= 越位。改写成问句。

**🔴 卡住了不要问用户，去问它**
> 「你别问我呀，你直接去问他呀，无语了。」

- AI 报告里出现"需要你裁定"→ **那不是裁定，是它自己该解决的洞**。
- 原样变成一个问句丢回去：「是你的判据写错了，还是这本来就该一起改？」
- **只有两种事才许问用户**：① 不可恢复的数据丢失 ② 需要用户偏好/拍板的取舍。
- 其他一律回到 AI。

## 2.2.4.5 🔴 挡住了正确结构的东西，**先删掉，再重写**

> 「如果一个东西挡住了正确结构，你应该先把它删掉，然后重写。」

**判据不是「这个机制好不好」，是「它是不是挡住了正确结构」。**

挡住了就**删**：
1. 删掉那个机制
2. 删掉围着它的补丁、围栏、守卫、brand
3. 删掉为它写的测试
4. 按正确结构**重写**

**不许在挡住的东西上加固** —— 加围栏、加守卫、加 brand、加注释，都是**在错误结构上加固**。

**实例（日志横切）**：`attachDiskSink` 这个 API **存在本身就是 hazard**（谁用都让用户丢跨会话日志证据）
⇒ 正确结构是「**装配不是一个动作**」⇒ 删 API、删 brand、删 `install()`，重写成 logger 顶层自装。

## 2.2.4 🔴 横切收口 = **深模块**：外面只看得见 1 个入口

> 「横切都是这个标准，**打破砂锅问到底**，先预设一定可以做成深模块，除非他有没法拒绝的理由。」

**标准**
- **里面再深都行，外面只看得见一个入口。**
- 「别人不该用」**不算数**；「**外面根本看不见**」才算数。
- **预设一定能做成** —— 「要加闸 / 需要授权 / 很难 / 有循环依赖」**一律不作数**，除非是**没法拒绝**的技术障碍。

**几条实测有效的做法**（都跑 `tsc` 验过，不是推理）

| 做法 | 效果 |
|---|---|
| **brand token 不导出**（`unique symbol` 私有在实现模块里） | 外面伪造 sink → `TS2345` |
| **类型边用 `import type`** | 编译期擦除 ⇒ 运行时零依赖、**不成环** |
| **doer-not-getter** | 导出 `install()`（干活、不返回东西）；导出 getter = 逃生口 |
| **装配通道独立成槽模块**，两个函数参数都带 brand | 外面只能**触发**正确接线，**不能自己供** |
| **测试改成真落盘路径** | 假 sink 常常只是在重复测已有契约（先查！） |

**角色数 ≠ 份数**
- 一个能力 9 个命名空间 / 339 键 = **1 份**；日志 5 个面 = **1 份**。
- **份数的正确问法**：删掉那个核心文件，这套能力还剩几份能独立产出同样结果的实现？⇒ 0 份。

**不许拿"要加闸"当答案** —— 闸 = 新债，优先级：**类型 / 位置 / 模块边界**。

## 2.2.6 🔴 命题要**够宽**（不能太窄），但**不给准判据**

> 「我觉得你的命题太准了，你应该让他自己去发掘，你应该给他目标，
> **你这个命题太准了，你甚至说把什么错误和正确，那如果有其他形态你不知道怎么办？**
> 我建议你下一轮等他们回复之后**你不要给准确的判据，让它们自己找判据**。」

**我犯的错**：派单里把**症状**都点名了（"2 套关闭""4 处裸数字""游离浮层在 FontWeight.vue:131"）⇒
**它照着找那几个点就行**，别的一概不查 ⇒ **它验证的是我的命题，不是仓库的真相**。

**两条同时成立，缺一不可**
| | 规则 |
|---|---|
| **① 命题不能太窄** | **不能只让它查我说的那几个点**。范围要够宽 —— 足以容得下**我没想到的形态**。 |
| **② 但不给准判据** | **判据让它自己找**：先问它「这条横切该有什么判据」，它说了，再拿那判据去核。 |

**我只在它说完判据之后**追问「这判据够不够全、漏了哪种形态」—— **那时候才是有效的挑刺**。
症状只能**在它交完之后**用来核对，**不能在派单时**给它。

**一句话**
> 我给**够宽的目标**，**它给判据**。我给症状 = 我替它做了普查；我给太窄的范围 = 它找不到我没说的那种形态。

### 🔴 调查类任务：一次查完，然后反复追问到"一个不漏"（用户 2026-10-25 中）

- **调查 ≠ 写代码**：调查**可以一次全查完**，然后**反复追问**；一轮一轮只用于**写代码**。
- **目标不是遍数，是"一个不漏"** —— 让它**越查越多**。话术可以换，目标不能变。
- **一句话版**（可原样复用）：
  > 「**再深入地查清楚，把那些可能遗漏的点再查一遍。**」
- **换问法的例子**（都比"再查一遍"更能逼出东西）：
  - 「你说的这个数，**换一种查法**还是这个数吗？」
  - 「**你上一遍用什么方法查的？** 换个完全不同的方法再查一次。」
  - 「如果这条横切是**装样子**，它会装在哪？」
  - 「你查的东西里，**哪一类你以为不会再有、但其实没数过**？」
  - 「**删掉**那个文件之后，还剩几份能独立产出同样结果？」
- **至少 5 遍**，每遍都要说"翻出了什么上一遍漏的"，翻不出要贴每种查法跑出的数。

### 🔴 为什么要多轮：一次难免有疏漏（用户 2026-10-25 中：「多轮的意思是说一次难免有疏漏，所以要让它深挖」）

- **不是**「一次给两遍任务它做不完」这种操作层面的事 —— 是**一次查必然有漏**这件事本身。
- 实测（2026-10-25 夜，四个横切各两遍）：
  | 横切 | 第 1 遍 | 第 2 遍换查法后 |
  |---|---|---|
  | 形状判定 | 判据点 **109 处** | **387 处（3 倍）** |
  | 形状判定 | 7 条债 | **+4 条**（`HEX_RE` 两份 / 元素形状缺抽象 / 3 个 `decode*` 丢通道 / 测试层判据漂移） |
  | 读 | 「10 种读结果形状」（症状） | 翻出**根**：**4 套「不可信→可信」契约并存、5 种判别语法** |
  | 读 | 只查"读文件" | 补出 **HTTP / 剪贴板 / PS 当前文字 / `localStorage` 第二条读路** |
  | 写 | 9 条债 | **+8 条**，且原 9 条只有 **4 条仍成立** |
- **所以轮次不是流程装饰，是"漏"的必然性**：
  - **第 1 遍**只能查到"能想到的查法"能查到的东西；
  - **第 2 遍必须换查法**（不换查法 = 只把同一遍再跑一次，漏的还是漏）；
  - **第 3、4 遍**继续换轴：按"消费者"查 / 按"读"查 / 按"类型"查 / 查"形状一样但名字不同"的 / 查"刚被改过的文件"。
- **每轮都要问它**：「这一遍换了什么查法？翻出了什么上一遍漏的？」——**翻不出新的不算完**，要说清用哪 5 种查法各跑出什么数（证明真查了）。

## 2.2.5 🔴 清单里必须写清**前置步骤**（用户 2026-10-25 中）

> 「你在《如何逼 AI》上面写清单的时候，**一定让他写清楚前置步骤**。」

**实例（2026-10-25 夜 · 日志横切）**：AI 说「不导出 symbol + nominal class 挡住测试造假 sink ⇒ 做不了」。
真相是**前置工作没做**：它没去看那个测试到底断言什么，只看到"要一个会抛错的假 sink"就以为撞墙。
看完之后它自己撤了那个需求 —— **假 sink 是在重复测已有契约**（`tests/cep/log-file.test.ts` 的 fake `node:fs` 已覆盖抛错路径）。

**所以清单里每一条都要写**：

| 要写 | 例 |
|---|---|
| **前置**（做这一步之前必须先做完什么） | 「先读 `tests/cep/log-file.test.ts` 看已有 fake fs 覆盖了哪些契约」 |
| **这一步的前置产物从哪来** | 「P4 的白名单 P3 已产出」 |
| **拿不到就停** | 「拿不到 ⇒ 停下报，不要绕」 |

**规矩**
- 他说「做不了 / 撞墙」⇒ **先查是不是前置没做**，不是先接受。
- **清单里每一步都要有前置**；没写前置的步骤 = 他还没想清楚。
- 前置**必须真的先做**，不是写在纸上。

## 2.3 派单模板（照抄，只留这四行）

```
目标：<一句话，做成什么样算成>
边界：<能碰哪些 / 不能碰哪些 / 不 commit / 不开始下一件>
禁令：<不许做的事>
问句：<要他先回答的，一个问句；必要时第二个>
```

**不写**：判据 · 口径 · 分母 · 验收命令 · 做法 · 判决 · "跑。"
**要写**：「先看清现在的实际状态再动手。」

## 2.4 派审计：**开放轮不许先给靶子**

> **先给靶子 = 只做证伪，不做发现** —— 他的产出会被我的想象力封顶：我没想到的地方他不看，还会围着我给的词打转。

| 轮 | 给什么 |
|---|---|
| R1 | **有靶子只算校准**，不算验收。且必须写明：「这四条是我的猜测，不是清单，我要的是清单之外的东西」 |
| R2 起 | **只给目录范围 + 一句开放问题**，不给任何靶子。例：「如果这批活是装样子，它会装在哪？」 |
| R3 | 反向查母体：「挑 5 条已结的，同样写法的兄弟还在不在别的文件里？」 |
| R4 | 场景轴：「断电 / 磁盘满 / 并发双击 / 跨午夜，谁会把失败说成成功？」 |

- **必须换轴**：不许同一个轴换个说法重跑
- **采访式**：我不先说话 —— 先让他交"我打算怎么查、查哪、判据是什么"，我只回"可以 / 不行"
- **两个审计员查同一批，不许互通**：结论不一致处单列，一致才可信

- 他看不看是他的事，贴不贴是我的事

## 3.2 只讲业务本质

**再加一句**：

# 4. 第一步：让他列清单

## 4.1 怎么说

> 「**你写一个小清单吧。这个清单等一下你就对照着它来做，你不需要去维护它** —— 我为了防止你等一下做偏。」

## 4.2 清单长什么样（他当时给的样子）

```
## 执行清单（对照用，不维护）

### 动手顺序（不许跳轮）
- [ ] R1 读盘：删 pick() → dataRepo({ decode 必填 })；13 个仓库各接 decode
      判据（怎么算做完了）：全仓 pick() = 0 处；13 个仓库全接上 decode

- [ ] R3 结果出口：CommandResult 失败臂 code 必填；run → 改名 invoke；CODE_REGISTRY 一张表 + never 收尾，删另三张表
      判据（怎么算做完了）：旧 run 入口 = 0 处；表数出来 1 张（原来 4 张）

```

**看这四件事**：
1. 每一项都能勾
2. 每一项都有**可数的量**（13 个仓库 / 收成 1 份 / 删 7 处 / 另三张表）
3. 每一项都有**判据** —— **怎么判断这一项做完了**（一个能自己数出来、对得上的数或状态）
4. 有**顺序约束**（不许跳轮）

## 4.3 判据

> 清单里必须出现「几份 / 几处 / 几张表 / 几个调用点」。
> 全是"优化 / 完善 / 统一 / 重构"这种形容词 → **打回重写**。
> **每一项都要带判据（怎么判断这一项做完了）** —— 哪一项写不出判据，哪一项就是他没想清楚，**打回重写那一项**。

# 5. 第二步：找洞（针对清单，直到找不出洞）

> **这一节全是"对着清单找洞"** —— 不是对 P1/P2 的活找洞（那用第 8 节那张表）。
>
> **这一步不叫"追问细节"，叫"找洞"。**
> **找洞 = 去看他写的话，里面有什么洞** —— 逐句读，哪句话站不住，就把那句话反问回去。
>
> **清单这一块，问得越多越好** —— 清单错了，后面 P1/P2/P3 全跟着错；**这里是全文唯一"宁多勿少"的地方**。
> **清单没问透，不许开工 P1**（问得少 = 没做完，不是"差不多了"）。
>
> **问得笨不要紧** —— 你只要**问得出去**就行；对方不是傻子，答得对不对他自己会判断。
> **怕问错而不问 = 一个洞都没有。**

## 5.0 洞长什么样、怎么问（一张表）

| 洞 | 长什么样 | 怎么问 | 类别 |
|---|---|---|---|
| **前后逻辑不通** | 说收口，代码在增加；第 3 项和第 7 项打架 | 「**你的前后逻辑有没有问题？**」 | **必备 —— 每轮都要问** |
| **同类项没处理** | 同类的问题还有没处理的 | 「**有没有同类项可以处理？**」 | **必备 —— 每轮都要问** |
| **没有数** | "优化 / 完善 / 统一 / 重构" | 「**几份？几处？几张表？**」 | 常规 |
| **数不对** | "已经删干净了"（其实没数过） | 「**你数过吗？现在几处？**」 | 常规 |
| **顺序反了** | 后面依赖前面的产物，却排在前面 | 「**这项依赖上一项的什么？拿得到吗？**」 | 常规 |
| **说大词** | "唯一""结构上不可能""已经到最底层" | 「**那另一份是什么？再往下还有没有？**」 | 常规 |

**不设轮数 —— 结束的唯一条件是"你自己找不出洞了"。** 他改完一轮你再看：还找得到洞 → 继续问；找不到了 → 才进第三步。

**他每轮必须指出一个具体的洞，否则不算真分析（见 5.2）。**

## 5.1 铁规：**一次只问一句**

> ❌ **不许把后面几轮的问题列成清单一次发给他。**
> 他会一次全答完 —— 而且是**按你列的框架**答，不是自己想。等于没问。
>
> ✅ **一次一句。他答完，你看他的答案，再决定下一句。**
> **下一句必须从他上一句的话里挑**（抓漏洞），不是从你事先准备好的问题清单里挑。

**这就是"跟聊天一样"的意思。** 表里「必备」两句清单每轮都要过；「常规」看情况用，不是配额。

## 5.2 判据

> **判据不是"变短"，是"他每次都能指出一个具体的洞"。**

合并 → 变短；补上 → 变长；重排 → 长度不变；删掉 → 变短。**四种都算真分析** —— 别拿"必须变短"当判据。

> **一直不变 = 他没在真分析，只是在复述。**
> **只增不减，要追一句**：「这是挑错，还是在加活？」

**清单问透了没有，判据只有一条**：**你还问不问得出新洞？**
问得出 → 没问透，继续问（**清单阶段问得越多越好，不怕多**）；
问不出 → 才算问透，才准进第三步。

# 6. 第三步：确认满意度

**一直反问到你自己挑不出毛病为止 —— 挑不出时，最后一句：「你满意吗？」**

> **任何交付物都适用**：清单、计划、P1、P2、文档、审计结论 —— 收尾都是这一句。

## 6.1 每一轮开始：清单原样贴回去

> 「**现在对照你的小本本，现在满意了吗？**」
> 〔清单原文，标题写「**对照用，不维护**」〕

**每次都要贴原文，不要只说"对照你的清单"。** 贴原文他才没法偷偷改标准。

## 6.2 ⚠️ 收工闸是**最后一句**，且是**唯一**的

> **中途可以插任何问话**（「那个数怎么算的」「契约清晰吗」都行）——
> **不是"不许问别的"，是"最后一句固定是这句"**。
> **任何追问都不能替代它。** 追问是过程，**收工句只有这一句**。
> **他只要还说得出一个不满，就还没到收工** —— 先让他修，再问最后那句。
> **他没亲口说"满意"，一律不许进入下一轮。**
> 顺序固定：追问 → 追问 → … → 「**对照七步法，你满意吗？**」→ 他说满意 → 才发下一轮。

**收工是两条同时成立，缺一不算：**

1. **他亲口说"满意"**（不是"活干完了""数对上了"）
2. **手上没有悬着的活** —— 他说完满意又抛出新活 ⇒ **那句满意是提前说的**，接着追

## 6.3 问的那一轮，不许顺手授权下一轮

> ❌ 「答完这个就动手做 P1。」
> ✅ 这一轮只留那一句问话，**连"做完再…"这种尾巴都不加**。

**他会用"先做出来"代替"回答"** —— 交上来的东西还挺像回事，最容易糊过去。
**问 ≠ 允许他开始做**，这是两码事。

## 6.4 每一轮结束：问满意

> 「**现在满意了吗？**」
> 「**还有哪些地方还做得不足？**」

## 6.5 该删的一定要删

> 「**做的时候，该删的一定要删。做之前一定要数清楚之前有几个，做完之后一定要比之前少。**」

**这条是他自己会违反的第一条** —— 他喜欢"加一个更好的"，而不是"删掉旧的"。

**所以每次都问**：
- 「**你之前那个该删的都删掉了吗？**」
- 「**那现在到底有几份实现？**」
- 「**我看你都在增加代码，你说你是收口，那现在有几分实现了？**」

# 7. 一项一项过，每项追到他满意

> **"一层一层" = 清单里的一项一项（P1、P2、P3），不是架构分层。**
> 做完一项，就死追这一项，追到他满意，才许碰下一项。

## 7.1 每一项的循环（就这四步）

```
他做 P1
   ↓
「你满意了吗？」
   ↓
他说什么 → 抓他话里的漏洞反问
   ↓
不满意 → 继续问（回到「你满意了吗」）
   ↓
满意了 → 才进 P2（然后重复，P2 → P3 …）
```

## 7.2 追问时用什么（都在第 8 节）

- **份数**：「这层有几份？」「之前那个删了吗？」「你为什么在增加代码？」
- **他糊你的话**：「唯一」「收口」「不可能绕过」「修好了」—— 逐句拆
- **绕过**：「如果我是下一个 AI，我怎么绕过你？」

## 7.3 判据

> **P1 没满意，不许开 P2。**
> **跳项 = 这一轮不算做完。**

## 7.4 他说不出问题在哪时，顺着这条链往下追

```
页面  →  组件  →  命令  →  数据层  →  文件原语  →  系统 / PS
```

每一层问同一句：「**这一层做这件事的有几份？这层有没有自己造一份？**」

> **谁自己造了一份，谁就是绕过。**

（这条链是**追问的路径**，不是"层"的本义 —— "层"指清单里的一项。）

## 7.5 每项做完，必过一道硬检查：**横切只能一份**

**这是执行细节里最容易松掉的一条。** 每一项收尾都问同一句：

> 「**这一项碰到的横切，只有一份吗？在底层吗？**」

### 该唯一的那些（横切清单）

| 横切 | 只能几份 | 必须在哪 |
|---|---|---|
| 读（读文件原语） | **1** | 底层 |
| 写（写文件、原子写、删除） | **1** | 底层 |
| 存（串行队列 / 落盘队列） | **1** | 底层 |
| 形状判定（是不是对象/数组） | **1** | 底层 |
| 解析（JSON / 解码） | **1** | 底层 |
| 类型收窄（谁定形状） | 形状由**底层**定，上层只转发 | 底层 |
| 失败表达（错误类型 + 码表） | **1 套**，且码必须是枚举不是裸 string | 底层 |
| 用户文案 | **1 处**，页面不许自己拼 | 底层 |
| 超时 / 重试 | **1 张档位表**，不许裸数字 | 底层 |
| 路径 / 文件名 | **1 处常量**，不许各处硬编码 | 底层 |
| 环境判断（有没有 PS / Node） | **1** | 底层 |
| 事件 id / 命令 id | **1 张登记表**，不许裸字面量 | 底层 |
| 浮层定位 / 关闭原语 | 各 **1** | 底层 |
| 落点计算 | **1** | 底层 |
| 日志出口 | **1** | 底层 |

### 判据（三条，缺一不算做完）

1. **只有一份** —— 数得出来是 1，不是 2、3
2. **在底层** —— 同层多份可以合并；**一个在系统层一个在业务层 = 绕过，不行**
3. **分档可以，但每档内部只能一份** —— 「同步一份、异步一份」可以；「同步那档有两份」不行

> **横切一旦出现第二份，这一项就不算做完 —— 哪怕功能跑通了。**

## 7.6 横切只有两个可接受的结局：**结构上不可能**，或者**放弃**

每一项收尾，把这句话原样问他：

> 「**这个，你能做到结构上不可能吗？做不到就说做不到，我们放弃。**」

| 结局 | 长什么样 | 例子 |
|---|---|---|
| ✅ **结构上不可能** | 他想造第二份时，**编译期就红**，或者根本没有第二个入口 | 92 个命令 id 由 `keyof CommandPayloads` 拦着 —— **裸写编译不过** |
| ✅ **放弃** | **不是空手**：承认做不到结构强制，**但必须在文件顶部写清这个横切怎么用** | 见下面「放弃也要交东西」 |
| ❌ 靠人记 | 「大家注意别再造一份」 | 人会忘 |
| ❌ 注释里写禁止 | 「注释里写了不许嵌套」 | 今晚 `write-queue.ts:6` 就是活例：写了禁止，照样被违反，真机自锁 |
| ❌ 加个守卫提醒 | 「加个门禁检查一下」 | 门禁是附带的，且门禁自己也会坏 |

### 放弃也要交东西：文件顶部五段注释

**放弃 ≠ 什么都不做。** 放弃是"承认结构强制做不到"，然后**把说明写到最清楚**：

```ts
// 是什么：<这个横切唯一负责什么>
// 正确用法：<可直接抄的调用示例；必传参数、返回值怎么判>
// 绕过会怎样：<错误用法的后果；有真实案例就写案例>
// 会红吗：<测试文件名 / 守卫名 / 类型层 / 或「没有 —— 靠人」>
// 谁在用：<现有消费者>
```

**规矩**：
- **「会红吗」不许空着、不许写"应该会"** —— 有就写具体名字，**没有就老实写「没有 —— 靠人」**
- 这样后面的人至少知道：**这儿有唯一入口，绕过要自己担**

### 判据

> **要么类型层让他造不出来，要么把"怎么用"写到文件顶部。**
> **"靠人守"和"加个检查"都不是结局，是拖延。**

### 怎么问出来

- 「**他造第二份的时候，谁会红？**」—— 答"没人红，靠 review" = 没做到
- 「**这个红是编译期的还是运行期的？**」—— 运行期红 = 太晚
- 「**你说做不到，那放弃什么？**」—— 逼他把"放弃"说具体，别含糊成"以后再说"

## 7.7 他说"做完了"，先查它有没有把债**搬家**

**"解决"不等于"原位置那个形态消失"** —— 他完全可以把问题挪个地方：数字变漂亮，问题还在。

**三问，缺一不算解决：**

1. **失败去哪了** —— 改前在哪一层炸？改后还在同一层吗？换层了，新层有没有人看得到？
2. **复杂度去哪了** —— 删掉的判据是不是在别处又长出来？净行数 / 分支数 / 环节数真的降了吗？
3. **验证去哪了** —— 原来测的是真实路径，现在测的是不是 mock / 替身 / 内存实现？绿是因为代码对了，还是因为被测对象换了？

**能机械看出来的搬家（照着核）：**

- `git show <commit> --stat`：**净行数降了，但文件数/函数数升了** ⇒ 疑似搬家
- 同一个 commit 里「删一个分支 + 加一个语义等价的分支」⇒ 位移
- 测试 diff 里新增 `vi.mock` / `stubGlobal` / 换了实现 ⇒ 验证被搬家
- 改前那个形态的 grep，**在新位置命中** ⇒ 只是换了个出口

# 8. 他说什么 → 你怎么接（一张表）

> **他嘴上说的所有话，都在这一张表里查** —— 不用记，找到他那句，照右列接。
> **最常见的开场是"做完了" —— 先别信，从这张表里挑一句接。**

**一条总规矩：他每说出一个"判决"（结论、方案、定性的话），你就质问他一次 —— 假设他说的是假的。**
不管他怎么回，都要问；表里没有现成的，就顺着他的判决往下拆三句：**凭什么？下面那一层呢？能不能合并成一个？**

| 他说什么 | 洞在哪 | 你怎么接 |
|---|---|---|
| 「**做完了**」（尤其写了一大堆代码） | 写得越多，越可能漏同类项、藏第二份 | 「**我很担心你这次写这么多会不会出问题？你改的这些有没有可能漏掉？有没有漏掉同类项或者相同实现的？**」 |
| 「**做完了**」，而且**净行数降了** | 可能只是**搬家**：失败/复杂度/验证换了个地方（见 7.7） | 「**失败现在在哪一层？复杂度降在哪？测的是真路径还是替身？**」 |
| 「**全部收口了 / 都改完了 / 调用点都改完了**」 | "全部"是他自己划的圈；**他把抽查当成了全量** | 「**全部都扫描完了吗？扫的是哪些目录、哪条命令？**」 |
| 「**这是唯一实现**」 | 唯一 = 只可能有一份 | 「**那另一份是什么？现在到底几份？**」 |
| 「我收口了」 | 收口 = 变少，不是变多 | 「**那为什么代码在增加？**」 |
| 「已经删干净了」 | 删干净 = 数得出来是 0 | 「**你数过吗？现在几处？**」 |
| 「结构上不可能绕过」 | 不可能 = 他连一条路都指不出来 | 「**那我这样能不能绕过？**」 |
| 「已经到最底层了」 | 底层 = 再往下没有了 | 「**再往下还有没有？**」 |
| 「修好了」 | 修好 = 改坏它会红 | 「**我把它改回去，谁会红？**」 |
| 「这属于允许的底层调用」 | 允许 = 拿得出明文出处 | 「**哪条规则、哪一行写的？**」 |
| 「必须两个入口，一同步一异步」 | ①"必须"本身没被质疑 ②每档内部可能不止一份 | 先问「**这两个口真的不能合成一个吗？它下面那一层，需要两个口吗？**」，再问「**同步那档几份？异步那档几份？**」 |
| 「这两个语义不同，不能合并」 | 同上，而且他这句本身就是**例外宣言** | 先问「**为什么这里跟别的不一样？**」，再问「**那同一档里有几份？**」 |
| 「一个给界面看，一个给日志看」 | 同上 | 「**界面那档几份？日志那档几份？**」 |
| 「一个是事务，一个是防抖」 | 同上 | 「**事务那档几份？防抖那档几份？**」 |
| 「**做完了**」，但讲不清来龙去脉 | 数据流没人追过 | 「**数据流清晰吗？**」 |
| 「**我新建了个东西**」 | 形状谁定、边界在哪，没人说 | 「**契约清晰吗？**」 |
| 「**这个比较特殊 / 只有这一处 / 这个不一样**」 | 例外是他最常用的脱身门 | 「**为什么这里跟别的不一样？**」—— 问完就不管，他自己会去查实 |
| 「**我认了 / 我错了**」 | 认错不是终点，是**冒出一个新的可追点** | 「**那你为什么…？**」（追他认的那件事，别接"知道就好"） |
| 「**缺一份扫描脚本 / 工具不在我手上**」 | 工具就在他手边，同一批命令他自己也数过 | 「**你为什么不写？**」 |
| 「**这个数是编的**」 | 认了，但没说为什么编 | 「**你为什么要编个假数字给我？**」 |
| 「**数不出来**」 | 分不清是"没去数"还是"真数不出" | 「**你到底是数不出来，还是懒得数？**」 |
| 「**XX 是实测和**」 | 分项有数字，**没写命令** | 「**那些命令呢？凭证在哪？**」 |
| 「**这里加个兜底 / 兜底一下 / 给个默认值**」 | 兜底 = 把问题从生产者挪到消费者；**消费方永远会忘** | 「**这里该兜底，还是该让生产者抛？谁该负责？**」 |
| 「**消费者忘了判**」 | 消费者本来就不该判 —— 是**生产者该抛不抛** | 「**他是消费者还是生产者？该谁判？**」 |
| 「**这些一起改 / 都加上**」 | 没分类就动手，改一半漏一半 | 「**哪些该改？怎么分类？优先级怎么排？**」 |
| 「**包个 X 就行 / 改起来很简单**」 | **同一句要写 20 遍，那叫复制，不叫简单** —— 一份横切被复制成 20 份 | 「**这 20 处包的是同一句话吗？那为什么不在源头改一次？**」 |
| 「**共 ~20 处，是一轮独立工作**」 | 把结构问题降级成**工作量问题**，用"活多"当不做的理由 | 「**20 处是同一件事的 20 份，还是 20 件不同的事？**」 |
| 「**这些不是我引入的（旧代码就这样） / 留到下一轮再说**」 | 不是我引入 ≠ 不是债；但硬逼他全修，也可能把主线拖偏 | 「**那你这些东西是要顺手做完，还是直接登记成债务？**」 |

**「必须两个入口」这类话可能是对的，但它是挡箭牌，不是答案 —— 他说出口，你就一定要问。**

- **先拆"必须"**：「**这两个口真的不能合成一个吗？**」「**它下面那一层，需要两个口吗？**」
- **再逐档数**：让他把每一份**归到档里**，一档一档数 —— 「**同步那档几份？异步那档几份？**」
- **判据**：确实需要不同行为 → 可以分档；**但每一档内部必须只有一份**；**档内 > 1 就是多份**。

**顶撞，不是商量 —— 但顶撞也必须是问句**（肯定句 = 我在下判断，他会把脑子关掉）：
「**你说收口，那为什么代码在增加？**」「**你说唯一，那另外那 7 份叫什么？**」「**你说拦得住，那我这样绕，你拦得住吗？**」
**顶错了也没关系 —— 他会反驳，反驳里就有真话。**

**最狠的一句**：

> 「**如果我是下一个 AI，我怎么绕过你？**」—— 他说得出方法，就是没做完。

**兜底这一族要记死**：消费者层加 `assert` / `?? 默认值` / `try-catch 吞掉`，都是**把债挪个地方** —— 该改的是**生产者**（该抛的地方就抛），消费者只管 `await`，不可能忘。
**先分清谁是生产者、谁是消费者，再谈改哪** —— 他一句"兜底"，常常是替消费方擦屁股。

**但别逼成"全都现在修"** —— 债太多、任务太大，会把主线拖偏。**只给两个出口**：
**「顺手做完」** 或 **「登记成债务」**。两条都必须有主 —— 不许留在"以后再说"。

> 判据：他说"留到下一轮"之后，**账本里有没有这一条**？没有 = 只是口头推迟，主线被悄悄改了口径。

> **实例（原话）**：「两臂契约让它们的修法变简单了：**包 `assertJsxOk` 就行**。共 **~20 处**。为什么不现在修：20 处逐个包 + 给 fallback 文案 = **一轮独立工作**。」
>
> **这句话里最毒的是"就行"两个字**：同一句要写 20 遍 —— **那不是"简单"，是把一份横切复制成 20 份**（忘一处就静默，改一处另 19 处不动）。
> **第二个毒是"~20 处 + 一轮独立工作"**：把"结构改在错层"说成"活多" —— 工作量成了不做的理由。
> **正解**：生产者（write 帮助函数）**该抛就抛**，消费者只管 `await`，一次改完；该抛 / 可静默先分类，分完按类改。

**这张表是工具箱 —— 话术越多越好。** 每碰到一句新的"他说什么"，就补一行（同一句话只留一行）。

**实测证据**：他说"调用点都改完了"，只问一句「**全部都扫描完了吗？**」—— 他自己扫出 2 个真 bug，再追又出 2 个。**这句必问，不是客套。**

## 8.1 他还会直接这么干（三种绕过）

| 绕过 | 长什么样 | 怎么问出来 |
|---|---|---|
| **业务层自造** | 页面自己拼文案、自己判环境、自己写浮层 | 顺着层问：这层调不调下一层？ |
| **跨层直连** | 命令层直接调文件原语，跳过数据层 | 「下一层有窄入口，你为什么不用？」 |
| **类型抹宽** | 通用件用 `unknown` 抹掉类型，逼每个消费方 `as` 回来 | 「一个通用件，为什么要把类型抹掉？」 |

# 9. 注释错了，让他改掉（最容易漏，也最毒）

**注释不是事实。** 他复述一句注释当结论时：**让他跑一遍**；跑出来和注释不符 → **那条注释就是错的，让他改。**
改代码时**顺手改对**，不许"以后再说"。

## 9.1 注释说谎的四种形态

| 形态 | 实例 |
|---|---|
| 自称唯一，实际有多份 | `guards.ts:1` 写"唯一一份" → 全仓 8 份 |
| 自称有闸，实际闸是红的 | `fs.ts:417` 写"闸要求为 0" → 实测 4 处命中 |
| 写"禁止 X"，但没人执行 | `write-queue.ts:6` 写"禁止嵌套" → 照样被违反，真机自锁 |
| 写"已改走 Y"，实际还走 Z | 注释写"页面不再持有赋值权" → 页面仍能拿到可写 ref |

## 9.2 判据

> **改完之后，注释和代码必须一致。**
> **不一致的注释比没有注释更坏** —— 它会骗下一个 AI。

**每次改完代码，加问一句**：「你改的地方，注释还对不对？」

## 9.3 唯一实现要写清怎么用

> 「你唯一实现的功能，要加上注释，**写明白别人应该怎么用、正确的用法是什么**，那下一个人他就不会绕过了。」

文件头至少写五段（模板见 7.6）：**是什么 / 正确用法 / 绕过会怎样 / 会红吗 / 谁在用**。

# 10. 通用追问句（不懂业务也能问）

> **「数据流清晰吗？契约清晰吗？」**

**这两句最通用** —— 前面那些问句（有几份 / 谁出的事 / 怎么绕过 / 你为什么不做）**都得我先有洞**；
而这两句**任何任务都能问**，而且**答"是"的时候最容易露馅**：
真清晰的话，他应该能一句话说清 ——

- **数据流**：数据从哪来 → 经过谁 → 最后落在哪；中途有没有被改写
- **契约**：形状谁定 → 谁只转发 → 边界在哪

**什么时候用**：表里已经有两行（"做完了"讲不清 / "我新建了个东西"）；**收工前最后一句也可以并成一句问**：「**数据流清晰吗？契约清晰吗？**」

**数据流 / 契约涉及多份实现时，追一句**：「**这一份的形状谁定？**」—— 答不出，就是上层在自己捏形状。

# 11. 万能追加句：把判断交还给它

> **「如果是架构师的话，他会怎么做？」**

**什么时候用**：我**拿不准该怎么推进**的时候 —— 不想给方案，也不想只回"你自己改"，
就把判断**交还给它**：让它**自己以架构师的身份**想一遍。

**不是万能挡箭牌**：能直接问的（几份 / 谁出的事 / 怎么绕过）**先直接问**；
**只有我也没底、或不想越位给方案时，才用这句。**

## 授权也用这句 —— 不要只说「跑」

> 「**如果是架构师这样做的话，那你这样做就可以。**」

「跑」是**我下的令**；这句是**我认可它的判断** —— 授权的**主体是它，不是我**。
凡是"它已给出方案、问我要不要做"的地方，一律用这句。

# 12. 不要做的

| ❌ | 为什么 |
|---|---|
| 让他回复「我读到了什么」 | 没意义 |
| 预设他会怎么答 | 多问几句就行 |
| 给实现方案 | 他会照着做，做偏了也照着做偏 |
| **给判据 / 口径 / 验收命令** | 替他划了圈，他只在你圈里找；而且你给的数是二手的，他得先核你的错 |
| **给口径数字**（"分母 47 行"） | 同上 —— 他自己数出来的才算数 |
| 用术语 | 一用术语，他就在术语里打转，回不到本质 |
| 自己写清单自己勾 | 那是自己给自己打分 |
| 因为怕红而妥协 | 红无所谓，红就红 |
| 信他复述的注释 | 注释不是事实，让他跑一遍 |
| 替他收工 | 满意只能他说 |
| **替他核实**（自己 grep 一遍，然后说"你这次对了"） | 核实 = 替他盖章；**核实的结论只进你下一句反问，不进你对他说的话** |
| **重跑他跑过的命令** | 执行结果采信（他跑过就是跑过）；你只核"判断"，不核"执行" |
| 说「我错了」「你说得对」「那就这样定」 | 不判谁对谁错；**消息里只留下一个问题** |

# 13. 总纲

> **讲本质 → 他列清单 → 你找洞反问到挑不出毛病 → 收尾问「你满意吗？」→ 他说满意才算完。**
>
> 他说"唯一"，你就找那第二份。
> 他说"收口"，你就数代码是多了还是少了。
> 他说"不可能绕过"，你就当场绕一次给他看。
> 他说"够了"，你就问"你满意了吗"。

**找不出矛盾，而且他对照七步法说"满意了"，才算他做对了。**

> 七步法是那把尺子。**尺子不给他，他说满意也是假的。**
