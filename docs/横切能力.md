# 横切能力清单

> 这份文档是给**后面接手的人或 AI** 看的：项目里已经有哪些跨页面的公共能力，新东西该往哪放，加了之后怎么登记。
>
> **不是可选的**：`npm run build` 会先跑 `npm run check`，`src/{cep,composables,stores,utils,styles}` 下有未登记的文件会直接构建失败。

---

## 一、什么算"横切"

满足任意一条才值得抽成横切，否则就写在页面里：

1. **会被 3 处以上重复** —— 比如列表页骨架、搜索框、空状态
2. **会改变页面骨架** —— 比如错误边界、路由过渡，后补要改所有页面
3. **出错会导致整个面板不可用** —— CEP 里没有"刷新页面"，比如全局异常兜底

反例（**不要**抽）：
- 只在字体页出现的字重芯片
- 一次性使用的布局
- 只有一个页面会调的业务接口

## 三、常用能力速查

### 动效

```vue
<transition name="fade">        <!-- 悬浮、图标反馈 120ms -->
<transition name="slide-up">    <!-- toast、回到顶部 180ms -->
<transition name="slide-down">  <!-- 下拉菜单 120ms -->
<transition name="scale">       <!-- 弹窗 240ms -->
<transition name="page">        <!-- 路由切换 -->
<TransitionGroup name="list">   <!-- 列表项入场 -->
```

```css
/* 需要自定义时只用 token，不要写 0.15s 这种 */
transition: opacity var(--dur-fast) var(--ease);
```

`prefers-reduced-motion` 已在 `motion.css` 里统一处理，组件不用管。

### 样式（token）

**所有数值都在 `src/styles/tokens.css`，组件里只允许引用变量。**

```css
/* 对 */
padding: var(--sp-3) var(--sp-5);
font-size: var(--fs-md);
color: var(--text-dim);
border-radius: var(--r-md);
background: var(--c-float);
box-shadow: var(--shadow-pop);

/* 错，会被 npm run check 拦住 */
padding: 6px 12px;
font-size: 12px;
color: #9a9a9a;
border-radius: 4px;
background: rgba(64, 64, 64, 0.96);
```

| 类别 | 前缀 | 例 |
|---|---|---|
| 颜色 | `--c-*` | `--c-surface` `--c-border` `--c-text-dim` `--c-accent` |
| 语义别名 | 无前缀 | `--bg` `--bg-panel` `--border` `--text` `--accent` |
| 间距 | `--sp-1..7` | 2 / 4 / 6 / 8 / 12 / 16 / 24 |
| 字号 | `--fs-xs..2xl` | 10 / 11 / 12 / 13 / 15 / 18 |
| 圆角 | `--r-sm/md/pill` | 2 / 4 / 999 |
| 尺寸 | `--h-*` `--nav-w` `--nav-item` | 控件高、行高、导航宽 |
| 层级 | `--z-*` | dropdown 50 / tooltip 60 / modal 8000 / toast 9000 |
| 阴影 | `--shadow-*` | pop / float |

想整体换肤、换密度：改 `tokens.css`，全项目生效，不用碰组件。

**写错了不用手改**：

```powershell
npm run style:fix      # 自动把已知裸值替换成 token，修不了的会列出来
npm run style:baseline # 清理后收紧允许上限
```

`docs/style-baseline.json` 记录每个文件当前允许的违规数，只许减少不许增加。
当前只剩 `_atoms` 演示页 2 处（开发用页面，不值得加 token）。

### 样式体系（规则层）

token 只管"值是多少"，下面四条管"怎么用"。

**① 命名**：三种前缀，别混

| 前缀 | 用途 | 例 |
|---|---|---|
| `g-` | 通用组件 | `.g-btn` `.g-dropdown__panel` |
| 页面名 | 页面私有 | `.font-item` `.shell__header` |
| `u-` | 布局 utility | `.u-stack` `.u-fill` |

元素用 `__`，状态用 `.is-*`。**禁止 `.content` `.info` `.glyph` 这类无前缀通用名**（已经有过，容易撞）。

**② 布局原语**：`src/styles/layout.css`

```html
<div class="u-stack u-fill">      纵向铺满，可放滚动区
<div class="u-row u-gap-3">       横向 + 6px 间距
<div class="u-center u-fill">     居中占满
```

替代每个页面重复写的 `display:flex; flex-direction:column; min-height:0; overflow:hidden`。

**③ 状态**：全项目统一，别再各写各的

| 状态 | 约定 |
|---|---|
| hover | `background: var(--bg-hover)`，文字 `var(--text)` |
| active | `background: var(--bg-active)`，文字 `var(--c-text-inverse)` |
| disabled | `opacity: .45` + `cursor: default` |
| focus | 全局 `:focus-visible` 已给 2px `var(--accent)` 描边，**不要写 `outline: none`** |
| selected | `var(--bg-active)` + 左侧 2px `var(--accent)` 指示条 |

**④ 覆盖出口**：可定制点必须是变量

```css
/* 组件内部留出口 */
.modal__body { padding: var(--modal-body-padding, var(--sp-5)); }

/* 外部改变量即可，不碰选择器 */
:root { --modal-body-padding: var(--sp-4); }
```

原因：scoped 样式特异性 `0,2,0`，全局 `0,1,0` **覆盖不了**。这是唯一的覆盖方式。

已留出口的组件：`CepModal`（`--modal-radius` `--modal-body-padding`）、`PageShell`（`--page-header-height`）、`ToastHost`（`--toast-max-width`）。新组件只给"以后可能会调"的属性留，别全包。

### 反馈

```ts
const feedback = useFeedbackStore()
feedback.ok('已应用 思源黑体')
feedback.error(describeCepError(e))   // 错误统一翻译
feedback.warn('该字体未安装')
feedback.info('共 259 个字体')
```

需要用户看清详情、或危险操作确认，用 `CepModal`，不要塞进 toast。

### 列表页

```vue
<PageShell title="动作" :count="filtered.length">
  <template #toolbar>
    <GInput v-model="keyword" placeholder="搜索" clearable />
  </template>
  <ul><!-- ... --></ul>
</PageShell>
```

```ts
const { items, visible, loading, error, load, bind, listRef, sentinelRef } =
  usePagedList(() => getActionList())

// 有筛选时把筛选结果绑成分页源（没有筛选就不用调）
const filtered = computed(() => items.value.filter(/* 页面自己的条件 */))
bind(filtered)

onMounted(() => void load())
```

```html
<ul ref="listRef">
  <li v-for="item in visible" :key="item.id">...</li>
  <li ref="sentinelRef" class="sentinel" />
</ul>
```

首屏渲染 60 条，滚到底自动加载。**别自己接 IntersectionObserver**。

加载失败用 `error` 在页面内联展示（要能重试）；**操作失败**用 toast。两者不要混。

### 宽度响应

```ts
const listRef = ref<HTMLElement>()
const width = useElementWidth(listRef)
const columns = computed(() => (width.value >= 420 ? 2 : 1))   // 原版阈值
```

不要用 `window.innerWidth`——面板宽度和视口不是一回事。

### 持久化

```ts
const previewMode = usePersistedRef('font.previewMode', 'small')
```

只用于**界面偏好**。业务数据每次从 PS 取，不要缓存到本地文件。

### 调 PS

```ts
import { getFontList, setFont, getLayerState } from '@/cep/ps'
```

页面里**禁止**出现 `window.__adobe_cep__`、`evalScript`、`$.evalFile`。
新的 PS 能力加在 `src/cep/ps.ts`，同时补 `src/cep/types.ts` 和 `src/cep/mock.ts`。

### 日志

```ts
import { log } from '@/utils/logger'
log.error('font', '设置字体失败', e)
```

控制台执行 `__pszDump()` 可以导出最近 200 条。

## 四、新增一项横切能力的流程

1. **先确认它符合第一节的判定标准**，不符合就写在页面里。
2. 在 `src/{cep,composables,stores,utils,styles}` 下建文件。
3. 在 `docs/registry.json` 补一条：`name`（中文名）、`entry`（相对路径）、`api`（怎么调）、`when`（什么时候用）。
4. 执行：

```powershell
npm run registry   # 重新生成上面的表格
npm run check      # 确认没有漏登记
```

5. 在本文档第五节「变更记录」加一行。

> 忘记第 3 步会怎样：`npm run build` 直接失败，并告诉你哪个文件没登记。
