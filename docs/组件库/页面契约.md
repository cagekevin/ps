# 页面契约

> **已完成页面冻结。**
> **只约束后面的新页面。**
>
> 已完成页面：
>
> - `/fontSet`
> - `/fontManage`
> - `/action`
> - `/freePanel`
> - `/set`
> - 以及已有的非占位页面
>
> 这些页面不再为了“统一”做视觉迁移。
>
> 允许动已完成页面的情况只有：
>
> - 修 bug
> - 修数据错误
> - 修安全问题
>
> 不允许：
>
> - 重排布局
> - 换控件皮肤
> - 删除页面私有结构
> - 借“收口”做重构
>
> 新页面仍必须先报备页面契约、批准后才写。

## 1. 流程

```text
报备页面契约
  → 用户审核
  → USER APPROVED PAGE: <route>
  → 才允许写该页 UI
  → 改结构重新报备
```

没有批准口令：

- 不新建页面组件；
- 不改页面布局；
- 不新增页面样式；
- 不借“删重复”“修 bug”“先跑通”开工。

## 5.1 `/fontManage` 审计结果

批准：

```text
USER APPROVED PAGE: /fontManage
```

现有结构：

```text
PageShell
├─ #extra
│  └─ GDropdown → GMenu → GMenuItem
├─ #toolbar
│  ├─ GInput（搜索）
│  └─ GDropdown（筛选）→ FilterPanel
├─ 标签区
├─ 字体列表
├─ 列表行：Rating / FontWeight / 预览
├─ #footer
│  └─ PreviewSetting
└─ TagMenu / TagContextMenu / TagCreator / CepModal
```

结论：

- 页面骨架已经是 `PageShell`；
- 列表结构符合 `ListPage`；
- 没有页面级按钮皮肤需要迁移；
- 不新增控件，不重写列表。

仍需收口的是页面私有的标签 chip / 图标小按钮 / 空态重试按钮：

- 它们不是 `GButton`；
- 要统一必须新增 `GIconButton` 或扩展 `GButton`；
- 未批准前不改。

## 6. 审核时要看什么

用户只审四件事：

1. 页面结构是不是官方结构；
2. 组件清单里有没有自造件；
3. 页面 CSS 是不是“无”；
4. 有没有未批准的新控件。

四项有任何一项不对，不批准。

## 7. 违规判定

- 没报备就写页面：回滚；
- 批准的是 A 结构，做成 B：回滚；
- 页面 CSS 写了按钮/输入框/颜色：回滚；
- 新控件没单列：回滚；
- 用“删重复”“修 bug”绕过报备：回滚。
