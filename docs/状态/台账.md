# 台账

> **唯一待办源。** 想到什么活先在这里加一行，再动手。
> 校验：`npm run ledger`（依赖不存在、done 的依赖没 done、代码里引用了不存在的 id，都会报错）

## 怎么挑下一条

1. 只看「状态 `todo` + 依赖全 `done`」的行——本文档已按这个顺序排好，从上往下就是推荐顺序
2. 优先级：**挡住后续页面的 > 验证架构的 > 用户能看见的 > 打磨**
3. 一次只开一条。标 `doing` 之后不要再挑第二条
4. 做完：状态改 `done` → 跑 `npm run ledger` → 有决策/踩坑才写日志

## 字段

| 列 | 说明 |
|---|---|
| ID | `T-xx` 任务 / `D-xx` 债务，唯一，代码里用 `TODO(T-01)` 引用 |
| 类型 | `task` 计划内 / `debt` 欠债 |
| 事项 | 一句话说清做什么 |
| 状态 | `todo` / `doing` / `blocked` / `done` |
| 依赖 | 必须先完成的 ID，多个用逗号；没有写 `-` |
| 说明 | 为什么阻塞、验收标准、注意点 |

## 开一个页面的任务，必须带这两条

在「说明」列里写不出这两条，就别标 `doing`——说明还没想清楚：

1. **扫第一页**：`pages/<已有页>/components/`、`pages/<已有页>/*.ts` 里，哪些本页要用 → 先搬上去（AGENTS 动作 3）
2. **入口增减**：本页预计新增 N 个文件/导出，删掉 M 个旧路径。M 为空要在说明里写清"为什么没有可删的"

这两条的作用不是记录，是**让搬移排在建页面前**。上一轮字体页 9 次返工，一半是因为先写完第二页才发现第一页已有实现。

## 怎么加一条

1. 在「可开工」表末尾加一行，ID 递增（T 和 D 各自独立编号）
2. 依赖填**已经存在的 ID**；依赖没完成就先放「可开工」表里并标 `blocked`
3. 跑 `npm run ledger` 确认没写错

## 状态规则

- 依赖没 done 时，状态只能写 `todo` 或 `blocked`，不能写 `doing`
- 标 `done` 之前，依赖必须全部 `done`
- 债务标 `done` 表示"已偿还"，不是"不做了"
- 完成的条目**移动到「已完成」表**，保持「可开工」表只放还没做的事

## 证据规则

- 视觉 / 行为类条目，**说明列必须能指到依据**：CSS 选择器、`app.v4.js:行号`、fixture 路径、
  测试文件与用例名。写不出来的，标不了 `done`——"看着对了"不是依据。
- 行为类条目的证据优先用测试（`tests/*.test.ts`）；没有测试路径的，说明里写明为什么测不了。
- **真实 PS 运行不验**（用户不参与 + 禁止 e2e）：所以 `done` 不等于"在面板里正常"，
  涉及真实数据的，末尾标「运行时未验」。写了测试的，可以写"组件级已验证"，不许写"功能正常"。
- 一个条目对应一次提交，commit 标题带 id（`fix(fontManage): … (T-23)`），
  复盘时 `git log --grep T-23` 就能看到这件事改了几次、每次为什么。
- 同一个值已经改过两次还没定，把条目改成 `blocked`，说明里写"缺什么依据"，
  不要继续在代码里试。
