# 形状收口手术

> **读者：改代码的人。**
>
> 配套 `.codebuddy/commands/架构师改码7步法.md`（303–537 行是全集）。
> 这份只留**开工前置 + 十刀 + 验收 + 证据**。冲突时以全集为准。

## 这是什么

**不是改 bug，是把 N 份混乱收成 1 份秩序。**

同一件事（读一个文件 / 判一份数据 / 写一次盘）在仓里长出 **N 种结果形状、N 个入口、N 种判别语法**时用它。
症状：消费侧每加一处，就要重新猜一次「失败了该怎么办」。

**它不是第 8 步**。七步法管「要不要改 / 改哪层」，这套管「**怎么把 N 收成 1**」。

## 三条根本判据

| # | 判据 | 一句话 |
| --- | --- | --- |
| 1 | **层数 = 形状数 = 入口数** | 三个数对不上 ⇒ 有层在兼职。这是「职责不明」唯一的量化判据。 |
| 2 | **失败在类型上取不到值** | 不是「用字段提醒坏了」，是「坏了就拿不到值」。`ok:false` 那一臂上不许有 `.value`。 |
| 3 | **一个函数只干一件事** | 同一函数里同时出现「兜底 / 归一化」和「判断好坏」⇒ 必然长出可忽略字段 ⇒ 拆。 |

## ⛔ 开工前置：六个量 + 一件凭据

**单立在刀 0 之前**：刀 0 写得再细，也会被「一上手就写代码」绕过。**没数就没有刀。**

| # | 必须报 | 怎么数 |
| --- | --- | --- |
| 1 | **形状有几个** | 表 A：`形状名 / 判别位 / 失败怎么表达 / 生产函数 / 消费点数` |
| 2 | **判别语法几种** | 表 C：同一句「成没成」在几种语法里各写一遍，报**去重后的种数**，不是行数 |
| 3 | **载体有几个** | 逐处列出：`ref` / `defineModel` / `v-if` 挂载 / 值对象字段 / 返回值。**只报「有 8 处」不列位置 = 没数** |
| 4 | **入口有几个** | 表 B：谁在写 / 谁在判 / 谁在关 各几条。「注释里说唯一」不算 |
| 5 | **分几层、谁在兼职** | 四层各归谁；三个数对不上就**点名哪层在兼职** |
| 6 | **改前改后 N→1** | 拿不出可比数（因为 N 还没有名字）⇒ 先「让它有名字」，**不许宣称收口** |

**第七件不是数，是凭据**：**哪一处会红** —— 单测用例名 / 探针 / 临时断言，三选一。答不出 ⇒ 全文只能写 `UNVERIFIED`，禁止出现「已完成 / 正常 / 应该没问题」。

**落点**：六个量与凭据**写进轮次文件**（`daily/架构日志/<NN>-*.md`）。**没落盘 = 没数。**

## 十刀（顺序不可换）

| 刀 | 动作 | 判据 |
| --- | --- | --- |
| **0** | 画**形状地图**（不是调用图） | 判别语法 > 1 种 ⇒ 一定还有形状没收 |
| **1** | 按**职责**分四层（不按文件） | 层数 = 形状数 = 入口数 |
| **2** | 砍**可忽略字段** | `ok:false` 臂上还有 `.value` / `.groups` / `.stars` ⇒ 还是裸形状 |
| **3** | 砍**自由文本失败** | 生产者不写用户文案；文案收口到 `msg`，失败才可穷举、可测 |
| **4** | **拆兜底** | **兜底数量净减**（X → Y，Y < X），不是「症状消失了」 |
| **5** | 拆**职责混装** | 一个函数里同时有「兜底 / 归一化」和「判断好坏」⇒ 必拆。这是刀 2 的根因 |
| **6** | **收路** + 方向互斥守卫 | 判据唯一 ≠ 收口，还要问「到判据的路有几条」 |
| **7** | **一次替换：删掉被它替代的旧实现** | **这次 diff 里必须有删除行**。只加不删 ⇒ 新结构是死代码 |
| **8** | **同步化与错误通道同批换** | 同步 `throw` 比 Promise 更容易被 `catch` 吞。只换同步不换通道 = 用静默吞换锁 |
| **9** | **焊死：让绕过在结构上不可能** | 删掉注释和文档后，违规还写得出来吗？写得出来 ⇒ 它只是约定，不是结构 |

> **刀 9 是收尾刀。** 前九刀把东西收成 1 份，刀 9 把「不许变回 N 份」**焊进结构**，而不是写成一句要求。

### 刀 0 的落点：三张表 + 先查再画

**表 A 形状清单**：`形状名 / 判别位 / 失败怎么表达 / 生产函数 / 消费点数`
**表 B 入口清单**：`入口名 / 谁在用 / 有没有守卫 / 能不能绕过判据`
**表 C 判别语法清单**：`grep -rn "\.ok\b\|\.status\b\|\.kind\b\|\.shape\b\|\.degraded\b\|\.note\b" src/`

**三条硬规矩**：

1. **必须先看** —— 同类任务已有形状地图（本仓在 `daily/架构日志/18-横切-*.md` 六份）⇒ **引用它的表 + 当场复算数字**。旧数会漂，**拿旧数不报时点 = 引用过期事实**。
2. **不许重画** —— 重画一张新表 = 造第二份真相。除非能一句话证明那份为什么不适用。
3. **看漏的边界** —— `--include=*.ts` 会漏 `.vue`；只扫 `src/` 会漏 `types/` / `tests/` / `scripts/`。**跨文件类型要一起数。**

### 刀 1 的落点：四层

| 层 | 职责 | 它**知道** | 它**不知道** |
| --- | --- | --- | --- |
| ① 观测 | 把外部世界变成三态 | 在不在 / 读不读得到 / 字节是什么 | 内容对不对、业务能不能用 |
| ② 判据 | 观测 + 解析 折成**结论** | 能不能当 T 用、坏了的原因 | 用户该看到什么话 |
| ③ 纯解析 | 不可信形状 → 可信形状 | 哪个字段不对 | 文件在不在、能不能写回 |
| ④ 业务结论 | 表达一个**业务判断** | 该域特有的三态 | 通用读的细节 |

**分层判据一句话**：**问它「失败了说不出原因」会不会伤人**。① 可以说不出（只报 errno），②③④ 不行。

**处置**：① 只许两个（文本 / 字节）；② 只许一个入口 + 一个形状；③ 只许一个契约，不许 `null`、不许 `throw`；④ 允许存在，但必须有判别位、不许带可忽略字段。

### 刀 2 的落点：四种裸形状

| 形态 | 长什么样 | 为什么是吞 |
| --- | --- | --- |
| 裸 `ok: boolean` + 空值 | `{ ok: boolean; stars: {} }` | `{}` 同时表示「一个都没有」和「读不到」 |
| 裸 `degraded: string` | `{ value: T; degraded: string }` | 空串正常、非空是坏，但 `.value` 永远可取 |
| 裸 `note: string` | `{ groups: []; note: string }` | 同上 |
| 自由文本 `fail: string` | `{ fail: '台账顶层不是对象' }` | 生产者写用户文案，绕过 `msg`，不可穷举 |

### 刀 4 的落点：六种兜底形态

刀 2 砍的是「形状」，刀 4 砍的是「**让旧路继续能跑**」的那层东西。它不收，新结构就是死代码 —— 调用点还在走旧路，而且旧路永远不报错。

| 形态 | 长什么样 | 处置 |
| --- | --- | --- |
| **静默吞** | `catch {}` · `.catch(() => …)` · 空 catch | 删；改成抛 / 告警 / 标 `degraded` |
| **失败归一空值** | 读失败返回 `[]` / `{}` / `null` | 改 `{value, degraded}` 或判别联合 |
| **占位对象 + 事后补** | 先塞空对象，等回调补 | 改成一次性拿到真值再入状态 |
| **默认值兜底** | `?? 默认值` 掩盖缺失字段 | 缺失要**看得见**（字段可选 + 显式缺失标记） |
| **UI 层提前宣告成功** | 点了就显示「已保存」，落盘还没发生 | 改成「处理中 → 成功 / 失败」两态 |
| **只在一入口补的补偿步骤** | 某个页面多调一步「刷新列表」才看得到 | 补偿收进唯一入口，删调用点的补丁 |

**共同判据**：**读可降级但必须标记；写不可降级必须抛。**

### 刀 6 的落点：五个收路手段

| 手段 | 本仓实例 |
| --- | --- |
| 入口数 = 层数 | 读：`readRepoFile`（判据）/ `readOwnFileText`（原文）/ `readExternalText`（外部）/ `readBase64File`（字节） |
| 路径守卫方向互斥 | 只收 `userDir()` **内** / 只收**外** ⇒「读哪个目录」结构上没有第三种选择 |
| 原语消费者收窄到底座 | `readTextSync` / `readTextAsync` 的消费者只剩 `disk-write` + `repo-read` |
| `decode` 必填 | `readRepoFile(target, decode)` —— 不给 decode 就调不了 |
| `\| null` 从契约里删掉 | `Decoder<T> = (raw) => Decoded<T> \| DecodeFail` ⇒「失败但说不出原因」编译不过 |

**做不到时**：宣称唯一入口却结构上堵不住 ⇒ **文件头写清「下一个人必须怎么用 / 不许碰什么 / 碰了会怎样」**，并如实登记缺口，不许宣称做到了。

### 刀 7 的落点：这条不做到，前面八刀全白做

新增入口 / 新函数 / 新模块时，**同一次改动里必须删掉它替代的旧实现**。

- 只加不删 ⇒ 旧路还在，调用点继续走旧路 ⇒ **新结构是死代码，而且没人发现**
- 删了但没改调用点 ⇒ 编译不过，**反而是好事**（会红）
- 判断标准：**这次 diff 里有没有删除**。没有删除的「重构」，就是搬家

**反例（本仓真实发生过）**：拆出 `appDataRoot()` 之后，`swatch-repo.dataRoot()` 的 `slice(0,-USER_DIR.length)` 与 `fs-read.appRoot` 的 `dirname()` 两处反推**必须同批删掉**，否则「根」永远有三份答案，新函数没人调用。

### 刀 9 的落点：结构上不可能 —— 不是加闸

**这是收尾刀。** 前九刀把东西收成 1 份，刀 9 把「不许变回 N 份」焊进结构。

| 手段 | 例子 |
| --- | --- |
| **不导出内部实现** | 只 export 那一个入口，其余保持模块私有 |
| **只给窄接口** | 参数收窄成字面量联合（`getSystemPath('extension' \| 'userData')`）⇒ 拼错编译期就红 |
| **类型层挡住** | 判别联合里「失败但说不出原因」编译不过（`Decoded<T> \| DecodeFail`，没有 `\| null`） |
| **import 边界拦** | `no-restricted-imports` 让 `pages` 结构上无法 import `cep/data` |
| **漏改即编译失败** | 改接口签名，所有调用点同批红 —— 不用靠人记得去改 |

**判据**：**把注释和文档全删掉，违规还写得出来吗？**
- 写得出来 ⇒ 它只是**约定**（靠人记得），不是结构
- 写不出来 ⇒ 才是**结构**

**做不到时**（TS 表达不了 / 要给实现级用例留导出 / 跨进程边界）——**做不到可以，但必须两件都做**：

1. **在唯一文件顶部前 8 行写清四段**，少一段等于没声明：

   ```ts
   // 是什么：
   // 唯一入口：<哪类事只能经过这里>
   // 替代了什么：
   // 谁在用：
   // 禁止：<页面 / 组件 / 其他层不许做什么 + 碰了会怎样>
   ```

   **少一段 = 没声明；没写清怎么用 = 没做。**

2. **去 `docs/生成/注册表.json` 加一条**（`name / api / when / status`）。**只有底层能登**：
   - **能登**：`cep` / `utils` / `domain` / `styles`
   - **不许登**：`stores` / `composables` / `components` / `pages`
   - **只登唯一入口**，内部实现文件不登
   - **不许留占位**（`（待补：…）`）

   现状（2026-10-26 实测）：124 条里 `stores` 16 / `composables` 10 / `components` 5 条是中间层与上层；**51 条是占位**，而 `registry.mjs check` 不拦占位 ⇒ 插一条空骨架就能过。

#### ⛔ 禁止加闸

刀 9 不许用下面四种东西顶替结构：

- 新增 lint 规则
- 新增 `check` 步骤
- 新增 grep 断言
- 新增「必须遵守」的文档条目

**以上禁止，不需要理由。**

## 收口验收：六个数字 + 三个净减

答不出数 ⇒ 没做。

```
形状份数              N → 1
判别语法种类          5 → 1
可忽略字段            3 → 0
自由文本失败          N → 0
入口数                每层 1 个（不是每个调用点一个）
Decoder 的 null 通道  有 → 无
兜底数量              X → Y（Y < X）        ← 刀 4
diff 里的删除行        有                    ← 刀 7
约定条数              X → Y（Y < X）        ← 刀 9（写成注释/文档才算约定）
新增闸数量            0                    ← 刀 9（禁）
做不到结构的条目      已进注册表，且都是底层唯一入口、无占位   ← 刀 9
```

**每条都要贴命令 + 改前改后数字。**

## 行为证据：形状账答不了的那一半

十个数字全是 `grep` 出来的静态量。它们能证明「形状收干净了」，**证明不了「改完还能跑」**。
只交形状账 = 交一个收拾整齐但没通电的房子。

| # | 问 | 答不出就是 |
| --- | --- | --- |
| 1 | 改前什么样、改后什么样（具体到用户能看见的提示 / 列表 / 中断） | 只做了形状，没想行为 |
| 2 | **哪一处会红？** | 没有证据，只有自信 |
| 3 | 哪些路径没验？逐条标 `UNVERIFIED` | 假装验过（最坏的一种） |

**合法的「会红」只有三种**：

- **单测** —— 改坏实现它必红（不是自证式）
- **探针** —— `node scripts/probe.mjs` 临时还原旧实现 → 精确变红 → 自动还原
- **临时断言** —— 改完立刻删掉那种，但**必须粘进轮次文件**，否则等于没做

## 四种偷懒信号（出现任意一条，本轮作废重来）

| 长什么样 | 为什么是偷懒 | 正确动作 |
| --- | --- | --- |
| **只给「做法」不给数**（「把 X 换成 Y 就行」） | 没数就没有 N→1，收没收干净无法判定 | 先交六个量，再谈做法 |
| **用「我判断 / 我认为」代替证据** | 判断不是判据；「不做」的举证责任比「做」**更重** | 走取证三问，或写 `UNVERIFIED` |
| **拿别处的结论当本处的理由**（「原版也一样 / 别处都这样」） | 别处 0 处 ≠ 本处合理 | 回源到 `file:line` 再判 |
| **收一半就报「收口」**（形状收了口数没降 / 入口没降到层数） | 判据唯一 ≠ 收口 | 交「入口数 = 层数」的前后对照 |

## 施工纪律（前三次返工的直接原因）

1. **先分类再动手** —— 凭印象上手，改到一半才发现依赖还在
2. **原子单元** —— 接口 + 全部实现同批改完才 typecheck
3. **从下往上** —— 底层实现 → 接口 → 上层 helper → 调用点
4. **不用脚本做语义改写** —— 只用精确锚点，一处一验
5. **单元内不 typecheck，边界才验** —— 否则满屏预期内的红，分不清「真错」还是「还没改到」

## 交付前自检

- [ ] 六个量报了吗？**落进轮次文件了吗**（没落盘 = 没数）？
- [ ] 三个数（层 / 形状 / 入口）对得上吗？兼职点名了吗？
- [ ] 十个数字都贴了命令吗？
- [ ] 六种兜底逐条过一遍了吗？净减了吗？
- [ ] **旧路删了吗？这次 diff 里有删除行吗？**
- [ ] **每一条「不许这样写」，都问过「能不能让它结构上写不出来」了吗？**
- [ ] **有没有哪一条是靠加闸/加规则糊过去的？有就退回刀 9。**
- [ ] **做不到结构的：文件头顶部四段写了吗？注册表里加行了吗？加的是底层唯一入口、且没留占位吗？**
- [ ] 哪一处会红？红在具体那一行吗？
- [ ] 没验的路径列出来了吗？

## 一句话

**七步法管「改对」，这套管「改得完」。** 改完之后，能焊进结构的，就别写成要求。
