### 逐条判决（死了 / 假死 / UNVERIFIED + 证据）

#### TD-13-1（jsx 超时常量收口成 timeouts.ts 三档）→ **假死（一归只归了一处）**

- 收口本体成立：`src/cep/jsx/timeouts.ts:23-25` 是唯一三档；8 个域文件全部 `import { READ/WRITE/LONG } from './timeouts'`（`font.ts:2`、`style.ts:2`、`commonUse.ts:2`、`layer.ts:2`、`action.ts:2`、`legacy.ts:2`、`rename.ts:2`、`env.ts:2`），`grep -rn "timeout: *[0-9]" src/` 在 `src/cep/jsx/**` 内 0 命中。
- **但收口只覆盖 `src/cep/jsx/**` 这一个目录**，同一判据（「这次调用等多久」）在本区还有**第四、第五份**：
  - `src/cep/transport.ts:4` `const DEFAULT_TIMEOUT = 30000`（jsxCall/evalScriptRaw 的兜底值）
  - `src/cep/http.ts:60` `const DEFAULT_TIMEOUT = 15000`（同名不同值，另账 TD-09-31）
  - `src/cep/ps.ts:39` 裸数字 `30000`、`src/cep/ps.ts:50` 裸数字 `10000` —— 这两条是**同一个 evalScript 通道**的超时，却绕开了 `timeouts.ts`
  - `src/cep/fs.ts:436` 与 `src/cep/fs.ts:463` 两次 `evalScriptRaw(script, 15000)`
  - `src/commands/fontSet.ts:296` `{ timeout: 20000 }`（@见 区 10）
- 「母体 = 同一真相抄 N 份」没死：`timeouts.ts:2` 写「所有 `jsxCall` 的 `timeout` 都从这里取，不许写裸数字」，但 `ps.ts:37-50` 与 `fs.ts:436/463` 走的是 `evalScriptRaw`，不在它的句式管辖内。**口径写在注释里、无机器守卫**：`npm run check` 的十步链（`package.json:25`）里 `style:guard / template:guard / assert:guard / dispatch:check / boundary:pages / layer:boundary / jsx:dispatch:check / spec:check / ledger / stats:check / lint / format:check` **没有任何一条扫裸超时数字**；`assertion-guard.mjs:44-45` 的规则集只有 `as any` 与 `as unknown as` 两条。
- 结论：症状在 `src/cep/jsx/**` 内消失，**母体和检测闸都在**。定「假死」。

#### TD-13-3（裸 fetch 收进 cep/http.ts）→ **死了**

- 出口收口成立：`grep -rn "fetch(" src/ --include=*.ts` 全仓只有 `src/cep/http.ts:42` 一处（@见 区 11 的 `cloud/transport.ts:80` 已改走 `postText`，并在 `:78` 留了「网络出口只有一个」的注）。
- 兄弟写法也一起查了，没有漏网的第二出口：`grep -rn "createElement('script'\|sendBeacon\|new WebSocket\|new Image(" src/` 只命中 `src/cep/http.ts:89`（JSONP 自己，在同一文件内）；`src/commands/fontSet.ts:18` 只 import `jsonp`，没有第二个 HTTP 封装。
- 判据不是「改了一个调用点就结账」：`cep/http.ts` 是**唯一实现**（`postText` + `jsonp`），不是「把某个调用改过去」。
- 结论：**死了**。唯一残留是同文件内 `postText` 与 `jsonp` 各有各的默认超时（`:60` 15000，两处共用），那是 TD-09-31 的范畴，不在这里重复记。

#### TD-13-7（jsx 端口环境判据从模块快照改到调用点）→ **假死（改了一个调用点就结账）**

- 判据那一半真死了：`src/cep/jsx/index.ts:47-57` `portNow()` **每次调用** `hasCep()`，不再是模块求值期快照（原 `:32` 的 `createJsxPort(hasCep())` 已不存在）；`grep -rn "hasCep" src/` 里 `jsx/index.ts` 只剩 `:48` 一处且在函数体内。有测试钉：`tests/cep/jsx-port-lazy.test.ts:24-41`（同一实例先 mock 后补桥，第二次走真实实现）。
- **但它的母体——「选错实现后调用方拿到全成功、且无人知情」——没死**：
  - `src/cep/jsx/mock.ts:11` `const ok = () => Promise.resolve(null)`，其余写操作大多挂这个 `ok`（`:70-98`），读操作返回 `{err:0,data:…}`（`:41-68`）。即 mock 侧**恒成功**这一点没变。
  - `src/cep/jsx/index.ts:49` `if (cachedPort && cachedInCep === inCep) return cachedPort` —— 命中缓存直接返回，**不打日志**；`:53-55` 的 `log.warn('走 mock')` 只在**端口重建**（环境翻转）那一次打。
  - 于是「非 CEP 会话里第 2 次及以后的每一次 PS 调用」都返回成功且**零痕迹**，命令层/UI 拿不到 `degraded` 标记 → 与 ADR-0014「读可降级但必须标记」冲突。测试也只钉第一次（`tests/cep/jsx-port-lazy.test.ts:27` 断言第一次的 `log.dump()` 含「走 mock」）。
  - 这正好是题面说的「改了一个调用点就结账」：改的是**判据的位置**，没改**标记的传递**。
- 守卫也没补上：`scripts/assertion-guard.mjs:143-146` 明写「只扫 `src/cep/data/**`」，并把 `src/cep/jsx/index.ts:32` 那条**排除在本条判据之外**（原文「故不在本条判据内（另案登记）」）——排除理由成立（危害不同形），但**没有另案落闸**，红线只在注释里。
- 结论：定罪据那一半死了，**母体标记为假死**（与 TD-13-14 同处，本轮独立命中，不重复建号，只在下面把它升级成「母体 + 无闸」）。

#### TD-13-9（读失败被折成「没有选区」）→ **死了**

- 实现侧：`src/cep/ps.ts:134-155` `getLayerState` 对两个查询各自设了可判定区间，读不懂一律 `throw new CepError('PARSE', …)`，**没有 `Number(...) || 0` 也没有 `?? 0`**：`ps.ts:164-171` `parseTypeNumber` 只接受有限数（含数字字符串），其余 `return null` → 调用方 `:147-152` 抛 PARSE。
- 兄弟副本查过了，本区没有第二份：`grep -rn "Number(\|?? 0\||| 0" src/cep/{transport,ps,events,dialog,http,env,types,mock,log-file,open-url}.ts` 命中的 `Number(` 全在 `events.ts:231/250/253/259`（事件 ID 反查，另一判据）与 `ps.ts:169`（已受 `Number.isFinite` 护住）。
- 类型契约也同步了：`src/cep/types.ts:33-43` `LayerState` 注释明写「只承载读成功的值」。
- 测试钉住了：`tests/cep/layer-state.test.ts:42,50,58,66` 四条分别钉「类型号读不懂抛 PARSE，不产 typeNumber=0」「空串/非数字/NaN 不当 0」「有没有选中读不懂抛 PARSE，不产 hasSelection=false」「失败路径不产出 {false,0} 形状」。
- 结论：**死了**。唯一残留 `src/selection/index.ts:18` `const EMPTY = {hasSelection:false,typeNumber:0}` 是**初值**不是兜底（`selectionRef` 起手值），且 `getLayerState` 已不产这个形状，不判债。

#### TD-13-2（写操作超时被报成普通失败 / 提前放队列锁）→ **死了**

- 错误码分开了：`src/cep/transport.ts:86-91` 超时抛 `CepError('TIMEOUT_UNKNOWN', …)`，不是普通失败；`src/utils/errors.ts:14-20` 把 `TIMEOUT` 与 `TIMEOUT_UNKNOWN` 分成两个码并写清差别。
- 文案不再劝重试：`src/utils/error-text.ts:18-20` 明写「不说没做成，也不劝重试」，返回「无法确认这条操作是否生效…请先确认结果」；`grep -rn "请稍后重试" src/` 只剩 `error-text.ts:17` 的 `TIMEOUT`（读场景）那一档，写场景不共用。有断言钉：`tests/utils/describe-cep-error.test.ts:26` `expect(text).not.toMatch(/请重试|请稍后重试|重新操作|再试一次/)`、`tests/cep/host-failure-e2e.test.ts:168`。
- 队列锁不再提前放：`transport.ts:26` 引入 `bridgeReturned`，`:44` `queue = task.then(releaseQueue, releaseQueue)`、`:48-53` 只等「PS 真回包」放行；超时后 `:92-102` 有 `LOCK_GRACE_MS = 120_000` 宽限期兜底并留 `log.warn`。测试钉：`tests/cep/transport.test.ts:62`（超时后不提前放行）、`:86`（宽限期强制放行并留 warn）、`:47`（抛 TIMEOUT_UNKNOWN 且不二次结算）。
- 结论：**死了**（三处——码 / 文案 / 队列——都到位，不是只改一个点）。
