## 3. 五条判据（「解析」横切收口 = 五条同时成立）

> 每条一条命令能复算；判据 2 / 4 是**区分"真收口"和"看起来收口"**的两条，判据 5 **覆盖没想到的形态**。

**判据 1 · 单通道（解析只能有一个入口）**
不可信原文 → 可信形状只能经 `Decoder<T>` 契约（`decode` 必填，`| null` 不存在）。
```bash
grep -rn "JSON.parse(" src/ --include=*.ts | grep -v "JSON.parse(JSON.stringify" | grep -vE ":[0-9]+: *(\*|//)" | wc -l   # 现 16
grep -rn "JSON.parse(" src/cep/data/repo-read.ts | wc -l        # 现 1（唯一通道）
```
**收口 = 解析点收敛到通道内**；`JSON.parse` 裸用处数只许降不许升。

**判据 2 · 失败取不到值（真收口的第一判据）**
`ok:false` / `DecodeFail` 那一臂上，类型层**取不到 `.value/.groups/.list`**。真收口是**编译期红**，不是运行时判。
```bash
npx vue-tsc --noEmit       # 往任一失败臂补取 value ⇒ 这里红 ⇒ 真收口
```
**"看起来收口"的判据**：靠 `if (ok) return value` 的运行时约定 ⇒ typecheck 不红 ⇒ 假收口。

**判据 3 · 无自由文本失败（生产者不写用户话）**
失败臂只许**枚举码** + 观测（`field/expected/actual`）；中文渲染只在 `describeDecodeFail` 一处。
```bash
grep -rn "fail: '" src/ --include=*.ts | grep "[一-龥]" | wc -l      # 现 0，收口后仍须 0
grep -rnE "reason: '[^']*'|fail: '[^']*'|note: '[^']*'" src/ --include=*.ts | wc -l   # 现 18，只许降
```

**判据 4 · 无「可忽略字段」（真收口的第二判据）**
`ok:true` 臂上不许有"坏了也能照常取值"的旁路字段（`degraded/note/reason: string`）；`Decoded<T>` 只许 `degraded?: string` 且**带值即降级信号**。
```bash
grep -rn "  ok: boolean\|  degraded: string\|  note: string\|  reason: string" src/ --include=*.ts | wc -l   # 现 13，收口须 0
```
真收口 = 失败在类型上取不到值；假收口 = 失败能被无视（`note: string` 空串正常、非空是坏，但 `.groups` 永远可取）。

**判据 5 · 判别语法 = 1 种（覆盖没想到的形态）**
"这个解析结果成没成"只能有**一种判别语法**。现 11 形态 / 10 字段名 ⇒ 未收口。
```bash
{ ...| sort -u | wc -l }    # ① 字段名种数：现 10，收口须 1
bash 形态命令组             # ② 形态种数：现 11，收口须 1
```
**修正口径**：收口后 ①=`1` 且 ②=`1`；"只许降"测的是 ①② 的**去重后种数**，不是原始行数。行数降而种数不降 = 假收口。

## 4. 按刀 1 四层的分层结论（哪些形状该被同一条判据管住，哪些是合理分层）

**四层判据（刀 1 原文）**：问它「失败了说不出原因」会不会伤人 —— ① 说不出原因=只报 errno（**可以**）；②③④ 说不出原因=**不行**。
**处置规则**：① 只许两个（文本/字节）；② 只许一个入口一个形状（`readRepoFile`+`RepoRead`）；③ 只许一个契约（`Decoded|DecodeFail`）；④ 允许存在但必须有判别位、不许带可忽略字段。**判据：层数=形状数=入口数。**

## A. 新发现（盲区 13–17）

### 盲区 13 · `utils/decode.ts` 注释仍在教人"返回 `null`"，与类型 `Decoder<T>`（无 `|null`）**自相矛盾**

```bash
grep -c "null" src/utils/decode.ts                    # 17
grep -n "null" src/utils/decode.ts
```
- **类型**（`:118`）：`Decoder<T> = (raw:unknown) => Decoded<T> | DecodeFail` —— **无 `|null`**，`return null` 编译不过（这是**真结构保证**，前两遍已确认）。
- **注释却说**：`:27`「返回值只有三种，**没有 null**」✅ 对；但 `:32`「不许 return null」、`:43`「要拒就整份 null」、`:49`「返回 null = 结构不认识」、`:64`「说不清才用 null」、`:115`「整份返回 null」、`:120`「区分三种返回：null/{fail}/{value}」—— **多处仍把 `null` 当合法返回教**。
- **判定**：注释是**旧契约残留**（`{value}|null` 时代的），类型已升级为 `Decoded|DecodeFail` 但注释没跟。**A7「回改要一次改完」的反面**：改了类型没改注释。
- **后果**：下一个人读注释会以为"可以 return null"，照写 → 编译不过（好），或照写 `{value:T}|null` 传给测试 decoder（tests 正是这么做的，见第二遍债 15）。**注释本身是"第二份判据"**（教的和类型不一致）。
- **归横切**：**解析**（契约自述失真；与 38 号文债 2「guards.ts 头注释过期」同根）。
- **怎么修**：`decode.ts` 注释统一到类型现实（`Decoded<T> | DecodeFail`，无 `null`），删掉所有"返回 null / 说不清才用 null"的教导。**登记时与 38 号文债 2 归一类（自述失真）**。

### 盲区 14 · `ok` 是**同一判别位名、三种取值域**（最隐蔽：字段名一样，种数看不出来）

```bash
grep -rhoE "ok: (true|false|boolean|'cancelled')" src/ --include=*.ts | sort | uniq -c
#   3 ok: 'cancelled'   8 ok: boolean   81 ok: false   69 ok: true
grep -rhoE "ok: (true|false|boolean|'cancelled')" src/ --include=*.ts | sort -u | wc -l   # 4 种取值域
```
- **第一遍判据 5 数的是"字段名种数"（10）**，但**同一个 `ok` 字段名下其实有 3 种不同类型**：
  - `ok: boolean`（`RepoRead`/`JsxOutcome`/`WriteOutcome`/`UploadResult`/`translate` 等，两臂）
  - `ok: true | false`（字面量判别联合，`CommandOutcome` 前两臂）
  - `ok: 'cancelled'`（**字符串**，`CommandOutcome` 第三臂，`commands/types.ts:95`）
- **`CommandOutcome = {ok:true} | {ok:false;code} | {ok:'cancelled'}`** —— `ok` 在这里是 `boolean | 'cancelled'`，而别处是纯 `boolean`。**同名判别位、不同类型 ⇒ 消费侧判法不同**（`if(!ok)` 漏掉 `'cancelled'`、`ok==='cancelled'` 只对命令族成立）。
- **判定**：判据 5 的"字段名种数=10"**低估了**真实判别形态 —— 还要数**同名取值域**。真实判别形态 ≈ 字段名 10 种 × 各自取值域，`ok` 一项就 3 种。

`src/cep/jsx/index.ts:42` 注释自己写：「mock 每个函数都返回成功 → 面板弹「完成」、数据全是假的」——
**"返回成功"这个假象正是 mock 手写 `{ok:true}` 造出来的**，它绕过了唯一会判失败的解释器。

**⇒ 这是"测试覆盖假安全感"的更深一层**（接第四遍盲区 19）：第四遍说"消费侧有测试"，
但**消费侧很多测试喂的是 mock 假数据，从没经过真实解析器**。真实解析器的失败臂测试覆盖**远低于表面**。

**归横切**：**解析**（jsx 返回值档）。**怎么修**：mock 也走 `asJsxOutcome`（哪怕 mock 造的 `{err,data}` 喂给它），
让"解释器"这一步在 mock 路径上也跑；或至少给 `asJsxOutcome` 单测覆盖各失败臂（**核对现有 `tests/utils/` 有没有**，见 §C）。
⚠️ 不改 mock 的"返回成功"语义（那是 mock 的职责），只补"过解释器"这一步。

## F. 补第五遍缺口 1（自查：这次的"缺口"本身是错的）

第五遍 §D 说"没核 `tests/utils/jsx-result.test.ts` 有没有直接测 `asJsxOutcome`"。**当场核了，结论是：测了，而且很全。**
