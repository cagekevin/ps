## 4. 刀（顺序不可换）

### 刀 A · 收「上一版原文」为 1 个形状（本轮主体）

1. **新增** `DiskBefore = { status: 'ok'; text: string } | { status: 'absent' }`（`disk-write.ts`，模块内 + 给 `CasMode` / `BackupMode` 用）。
   失败臂不存在 ⇒ **读不到在类型上取不到 `text`**（判据二）。
2. `CasMode.expected: string | null` → `expected: DiskBefore`；`BackupMode.previous?: string | null` → `before?: DiskBefore`（省略 = 由 `backupStep` 自己读一次）。
3. **删** `previousInput()`（三义 → 0）。
4. **删** `requireReadable` / `requireExisting` 两个布尔开关：读不到 ⇒ 构造不出 `DiskBefore` ⇒ 抛。`file-repo` 的 `requireExisting` 判定改判 `before.status === 'absent'`（与「首次使用」同一个判据，不再自带一个开关）。
5. **删** `writeDisk`（async）：它存在的唯一理由是「读原文本身得异步」，而读搬进 `backupStep` 后该理由消失，两个入口同形 ⇒ 刀 7 一次替换。两个调用点（`commands/font.ts:325`、`commands/rename.ts:203`，均为 `backup: none` 的外部导出）改 `writeDiskSync`。
6. `file-repo.readRaw()` 不再返回 `text: string | null`，改返回 `DiskBefore`；`persist(value, before, cas)` 同批。
7. 传参 8 处同批改（`common-use:70,81` → `{status:'absent'}`；`style-library-io:93,314` · `style-library-repo:562` 同；`style-library-io:127,131` → `{status:'ok',text:original}`；`settings:153` → 由 `rawText: DiskBefore` 承载；`file-repo:140` → 传读到的 `before`）。

**行为变化（3 条，必须写清）**：
1. `backup: keep` + 原文读不到 ⇒ **抛**（旧：静默不写 `.bak` 继续写）。这是刀 2「静默吞 → 0」+ ADR-12「备份恒定开」。
2. `Repo.replace` / `settings.writePrefFile` 的「读不到就拒写」从**布尔开关**变成**结构上不可能不判**。
3. `writeDisk` 删除 ⇒ 外部导出改同步写；**无行为差异**：`writeTextFileAtomic` 本来就要求 Node，无 Node 时异步读回退也用不上。

### 8.2 没做到目标的一处（如实登记）

**`requireExisting` 仍是构造期布尔声明**（布尔开关 2 → 1，不是 → 0）。
理由：它表达的是**仓库构造时的约定**（「这个文件必须已存在」，D-20），不是每次写盘的临场判断；
删掉它会让 `legacy-settings` / `common-use` 失去「不用 fallback 覆盖不存在的文件」这条保证。
**判据本身已收口**：它现在只是 `outcome.status === 'notSeen'`（与「首次使用」同一个 `absent` 臂），
不再自带第二套判别语法。⇒ 要让布尔归零，得把它改成形状（如 `writePolicy: 'mustExist' | 'mayCreate'`），
那只是给布尔换名字，不减少判别语法，**不做**。

### 8.4 行为三问

1. **改前什么样、改后什么样**
