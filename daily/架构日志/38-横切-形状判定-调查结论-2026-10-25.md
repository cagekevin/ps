### 角度 2 · 数据流是否清晰

**链路（本轮实测，工作区状态）**：

```
磁盘文本 / PS jsx 返回
  └─ cep/fs-read.ts   readTextSync → TextRead 三态（ok / notSeen / error）
  └─ cep/data/repo-read.ts  readRepoFile(target, decode)   ← 档 1 唯一读入口

       ③ foldAbsent(outcome, fallback)  → RepoRead<T>（判别联合）
  └─ utils/decode.ts   Decoder<T> = (raw: unknown) => Decoded<T> | DecodeFail | null

       ├─ decodeList(raw, isItem)      —— 裸数组容器
       └─ 元素谓词 = guards.isRecord / isArrayOf / isString   ← **形状判定的落点就在这**
  └─ domain/<域>.ts   decodeFooFile(raw) + isFooItem(x): x is FooItem
```

**哪里没被改写 / 猜 / 造 —— 这一版是干净的**：

- `decode` 是**必填参数**（`repo-read.ts:10`：「`decode` 必填 ⇒『把 JSON.parse 的结果直接当 T』写不出来」）；
  `data-repo.ts:143` 同句。**类型层真挡住了**（这是本条横切唯一一处"结构上不可能"）。

- `guards.isUnknownArray` 存在的唯一理由就是**不让 `any` 流出**（`guards.ts:14-18`）。

**但数据流里有 3 处"被改写 / 猜 / 造"**：
