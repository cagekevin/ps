## 四点四、探针纪律（**所有阶段强制**）

> **临时改文件这一动作，只允许通过 `scripts/probe.mjs` 做。** 禁止手改源码再手工还原。

**为什么**：手工注入有三个真实风险 —— ①忘还原（注入态留在工作区，后续闸/单测带着违规跑 = 假账）；
②红的不是那点（注入没命中时命令照样失败，人眼分不清"打中了"还是"本来就红"）；
③证据靠手抄（失真）。`probe.mjs` 把这三件变成机器判定：**原子还原 + 精确断言 + 结论块直出**。

**用法（闸探针）**：

```bash
node scripts/probe.mjs --label "boundary:pages 负例" \
  --file src/pages/fontSet/index.vue \
  --find "<原文>" --replace "<原文 + 违规>" \
  --run "npm run boundary:pages" \
  --expect-exit 1 --expect-out "pages"
```

**用法（行为探针：把修复临时还原成旧实现，期待单测变红）**：

```bash
node scripts/probe.mjs --label "TD-xx 行为探针" \
  --file src/cep/fs.ts --find "<新实现>" --replace "<旧实现>" \
  --run "npx vitest run tests/cep/fs-atomic.test.ts" \
  --expect-exit 1 --expect-out "expected"
```

**退出码语义**：`0` = 观测与期望一致（**探针命中**）；`1` = 不一致（未命中）；`2` = 探针本身无效（参数错 / 注入点 0 处或 >1 处 / **基线本来就不绿** / 还原失败）。

**四条保命机制（别绕过）**：journal 兜底 + 崩溃后先还原 · 注入点必须恰好命中 1 处（0 处也算无效）·
还原后 sha256 自校验 · 并发编辑守卫（目标文件在运行期间被改过就拒绝覆盖）。

**必做前置**：先 `--suggest-out` 或直接跑一次未注入的同命令 —— **基线必须绿**，否则注入后的红与你的改动无关（这是最常见的假证据）。

**禁用**：`--keep` 式保留（假账入口）。

## 四点三七、🔴 凭证怎么写才不算造假（2026-10-25 · 结账闸落地时定）

> 闸只能保证「**命令跑得出声明**」，**不保证这条命令真能证伪** —— 有人可以写 `grep -c xxx` `claim=0` 这种恒真命令照样过闸。
> 所以补凭证的**唯一判据**是这一句：

> **把这条债修的那件事改回原样，这条命令的输出必须变。不会变的命令不算凭证。**

**claim 的写法（按稳到不稳，实测踩过坑）**

| 写法 | 稳不稳 | 说明 |
|---|---|---|
| **断「用例名」**（首选） | ✅ 稳 | `npx vitest run <file> --reporter=verbose` + `claim=<用例名里的稳定子串>`。加用例不漂；只有**那个用例被删/改名**才漂 —— 那正是该报警的 |
| 断自己那个文件的 `it(` 计数 | 🟡 一般 | 新增用例即漂，语义上正确（我加的就该重结） |
| 断整包 `npm test` 的 `N passed` | ❌ 会误报 | 受并行会话加用例影响，**断的不是"我这条债"**。实测 `TD-09-38` 从 9 漂到 11，真因是别的会话加了两条用例 |
| 恒真命令（`grep -c xxx` claim=0 之类） | ❌ 造假 | 过得了闸，过不了这一节 |

**非测试类证据怎么写（删除类最常见）**

> **删除类证据的判据同样是「改坏必变」，只是"改坏" = 把删掉的那份加回去。**
> `cmd` 必须是那条「旧实现一回来就变红」的命令（守卫脚本 / 用例 / `grep -c` 数到"只剩 1 处"这种**正数**判据），
> `claim` 写它现在跑出的那个**非零**数字或用例名。**写不出这样的命令 ⇒ 它不可机验，走 `kind=人工`，别用 `claim=0` 冒充。**

**当前能力边界（诚实记）**：`claim` 只有「子串包含」，**没有 `min=` 之类的比较语义**。要"下界语义"得改闸，属另一轮。

**两条对称的「不销毁历史」默认**
- `reopen`（降级）：原结账句写进 `原记「…」`，逐字不截断 —— 已落地
- `edit --field solution`：只替换解法那一段，`原记` / `evidence` 逐字保留；冲突要 `--drop-original` —— 已落地
- `resolve`（重结账）：**默认也要保 `原记`**，丢要显式 `--drop-original` —— 🟡 在做（`TD-09-41`）
  > 为什么必须对称：74 条「有结论无命令」现在**全带 `原记`**，补凭证要重结账；若 resolve 冲掉原文，等于一边修销毁口一边用另一个命令销毁同一批历史。

## 四点三六、🔴 位移检测（用户 2026-10-25 早 · 一整晚审计设计的盲区）

> 用户原话：「他假设那个 AI，在做之前没有使中心，做之后也没使中心。万一他只是改了一个位置，把复杂度或者错误移了个位置，那这个债务只是转移了而已，根本就没有被彻底解决。」

**前面所有轮次（靶子轮 / 开放轮 / 母体轮 / 场景轴 / 数字对账）都默认了一条错误前提**：
「这条债解决了」= **原位置那个形态消失了**。

但施工方完全可以只是**换了个地方放**：

| 位移形态 | 长什么样 | 谁看不见 |
|---|---|---|
| 删旧实现 + 加包装层 | 复杂度搬进黑盒，行数还少了 | 下一个人 |
| `catch` 从深处挪到浅处 | 失败还在，换了个人吞 | 用户 |
| 默认值从 A 挪到 B | 缺字段仍然不可见 | 用户 |
| 错误码改名语义不变 | 换成一个更漂亮的死码 | 我们自己 |
| 判据从"入口"挪到"调用点" | N→1 数字变漂亮，覆盖范围变小 | 下一轮审计 |
| **验证从真实实现挪到替身** | **测试绿是因为被测对象被换了** | 所有人（memoryRepo 那件事就是活证据） |

### 三种「清单之外」的位移（审计16 实测挖出，比上面六种更隐蔽）

| 形态 | 长什么样 | 实例 |
|---|---|---|
| **7 · 前提被隔壁改掉** | A 债改掉了某个参数的含义，B 债的判据还建立在旧含义上，没人复核 | `TD-11-4` 让 sweep 传 `[]`，`TD-11-7` 立的 `units.length === 0` 早退前提失效 ⇒ 离线 sweep 完全无痕（**TD-11-14**） |
| **8 · 待办挂在已结的债后面** | 残差注释写「XX-债 留待处理」，那债却已标记已解决，账本里没有第二行 | floatStyle 残差指向已结的 `TD-04-1`（**TD-04-2**）· 宪法 14×14 指向 `TD-12-5`（该债不含尺寸）（**TD-12-30**） |
| **9 · 单点整改冒充唯一入口** | 加了唯一写入口，但旧的可写出口还开着，改回去测试照样绿 | `setListType` 加了，`stores/action.ts:107` 仍导出可写 `listType`（**TD-03-3**）；`Repo` 3 方法变 6 个、21 处各自记"锁内用 InLock"（**TD-09-35**） |

> **共同点**：三种都是"判据没有机器执行，只活在注释/命名/账本标签里"。
> **推论**：以后看到「唯一」「必须」「留待」「待拍板」这类词，就要去问一句——**这句话谁来执行？** 答不出人，就是位移。

### 消债三问（缺一不算解决）

1. **失败去哪了** —— 改前在哪一层炸？改后还在不在同一层？换层了，新层有没有人看得到？
2. **复杂度去哪了** —— 删掉的判据是不是在别处又长出来？净行数 / 分支数 / 环节数真的降了吗？
3. **验证去哪了** —— 原来测真实路径，现在测的是不是 mock / 替身 / 内存实现？绿是因为代码对了，还是因为被测对象换了？

### 机械判据（能直接跑，别靠感觉）

- `git show <sha> --stat`：净行数下降但**函数数 / 文件数上升** ⇒ 疑似搬家
- 同一 commit 里「删一个分支」+「加一个语义等价的分支」⇒ 位移
- 测试 diff 新增 `vi.mock` / `stubGlobal` / 换 repo 实现 ⇒ **验证被搬家**
- 改前那个形态的 grep 在**新位置**命中 ⇒ 换出口
- 删了 `catch{ return X }`，但上游冒出 `?? X` ⇒ 换地方兜底

> **派单规矩**：每一批施工之后，必须有一轮专门问「这条债的失败 / 复杂度 / 验证，现在住在哪？和改前是同一个地方吗？」——不问这个，前面几轮全会给出「合格」。

## 六点九五、回访审计（2026-10-25 早 · 用户指令：文档搞完之后开始）

### 用户否决（2026-10-25 早，原话）

> 「我觉得你说得太具体了，反而人家查不出问题来，因为你把问题说得太具体了。下轮等他们，你起码还是查 3~4 轮。后面就要开始问，开放就不要让他说，就让他自己去找。」

**这是我第 9 个错，写在这里防复发**：`§六点九五` 第一版把每个审计员的"重点验什么"写成了**四条我自己的猜测**。后果是双层的：
- **审计员的产出被我的想象力封顶** —— 他最多只能证实/推翻我列的四条，我没想到的地方他就不看；
- **他连我这四条里最关键的都查不出** —— 因为我一说"验三态有没有被压回两态"，他就在三态这个词上打转，不会去看三态之外的东西；
