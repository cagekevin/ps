#### 判据 3 · **一个函数只干一件事** ⇒ `describeCepError` 违例

```ts
// src/utils/error-text.ts:13-18
export function describeCepError(e: unknown): string {
  if (e instanceof CepError) return codeText(e.code, e.message)   // ① 判「是不是 CepError」+ ② 查码→文案表
  return e instanceof Error ? e.message : String(e)               // ③ 兜底转字符串（任何 unknown 都能过）
}
```

**它一个函数干了两件事**：
1. **判别**（`e instanceof CepError` / `e instanceof Error`）—— 这是 ② 判据层的活；
2. **生产用户文案**（`codeText` / `e.message` 原样透传）—— 这是 ④ 业务结论层的活。

**后果**：`String(e)` 那一臂让**任何 unknown 都能变成一句用户文案**，包括非 `Error` 的对象、字符串、数字。
`tests/utils/describe-cep-error.test.ts:68-69` 甚至把这种行为**钉成了用例**（`describeCepError(42)` → `'42'`）。
⇒ **这是刀 3 要砍的「自由文本失败」在本仓的总入口**：**生产者抛什么，用户就看什么**，`msg` 表完全管不到这半句。

### 3.2 刀 3「砍自由文本失败」—— 本横切主刀，逐条判违反次数

刀 3 原文：**生产者不写用户文案；文案收口到 `msg`，失败才可穷举、可测。**
刀 2 原文列「自由文本 `fail: string`」为裸形状，理由是「生产者写用户文案，绕过 `msg`，不可穷举」。

## 4. 按刀 1 四层的分层结论

**四层判据（刀 1 原文）**：问它「失败了说不出原因」会不会伤人 —— ① 说不出原因 = 只报 errno（**可以**）；②③④ 说不出原因 = **不行**。
**处置规则**：① 只许两个；② 只许一个入口一个形状；③ 只许一个契约；④ 允许存在但必须有判别位、不许带可忽略字段。**判据：层数 = 形状数 = 入口数。**

**文案域的四层对应**（把「观测 / 判据 / 解析 / 业务结论」映射到「谁生产一句话」）：

| 层 | 文案域职责 | 本仓归谁 | 行号 | 判定 |
|---|---|---|---|---|
| **① 观测层** | 只报「发生了什么」的事实（errno / 字段名 / 字节数），**不说用户该看到什么** | `utils/errors.ts:9-54`（`CepErrorCode` **14** 个码 + `ERR_PREFIX`）· `domain/cloud.ts:100-111`（`CloudErrorCode` 9 个码）· `utils/decode.ts`（`DecodeFail` 码）· `cep/fs-read.ts`（三态）| — | ✅ **干净**：只定义码，不配文案 |
| **② 判据层** | 把码折成「这一条该显示什么」 | `utils/code-registry.ts:26`（`CODE_REGISTRY` 14 码 → `text`/`prefix`/`toast`/`cancelled`）· `utils/code-registry.ts:51`（`codeText()`）· `cep/data/repo-read.ts:154-169`（`describeDecodeFail`，**唯一渲染处**）· `pages/set/cloud-status.ts:57-60`（`reasonText()`）| — | ❌ **两个入口**：`codeText` 与 `reasonText` 各判一次；且 `reasonText` 在 `pages/` 下 |

**⇒ 结论（决定后续该删谁）**：
1. **`msg` 表是真单源，但只覆盖 6 个域中的 4 个**（业务结果 / 数据读写 / PS 能力 / 部分选区）；**「命令失败原因」与「云同步失败」「页面前置校验」三个域在它之外**。
2. **`CODE_REGISTRY` 与 `msg` 表是「码 → 文案」的两层，但 `CODE_REGISTRY` 的 `text` 字段自己写了字面量、没引 `msg`**（`git grep -c "msg\." src/utils/code-registry.ts` → **0**；`error-text.ts` 同样 **0**）⇒ **同一件事（码 → 用户话）在类型层有两份定义处**。
3. **`CODE_HINT` 是该删的那个**：它与 `CODE_TEXT` 对同 3 个码各写一句，且它**只进日志**（`pending.ts:57` `log.warn`）——
   按 §3.1 判据 2 的结论「用户看到的那句与系统记住的那句是两条通道」，**日志侧应记码 + 事实，不应记第二套用户文案**。
4. **`describeCepError` 的 `String(e)` 臂是该收口的那个**：它是刀 3「自由文本失败」的总入口，收了它，22 处违反里最大的一类（不可穷举）才可能归零。
