#### ① TD-11-1（触发源下沉到每个 entry 的 `watch`）→ **死了（母体真死），但闸是「半截闸」，另记一债**

- **母体真死**：`src/cep/cloud/change-sync.ts:29` 是**遍历注册表**而非手列——`offs = cloudEntries.map((entry) => entry.watch(() => cloudSyncQueue.markDirty(entry.id)))`。

  原先"手列 2 根线"的写法在本区已无副本（`grep -rn "actionIndexRepo\|hierarchyRepo" src/cep/cloud/` 只命中 entry 自身）。
- **"漏声明编译不过"这一条成立**：`src/domain/cloud.ts:72` `watch(markDirty: () => void): () => void` 无 `?`，`npm run typecheck`（含 `tsconfig.tests.json`）**零错误**；且 `tests/cep/cloud-change-sync.test.ts:171-188` 用真 repo 写盘驱动、期望值取自 `cloudEntries` 本身（不抄第二份清单），五个 unit 全脏才绿。
- **结论：病因母体死了**——"改了不同步、不报错"这条链已被 `watch` 必填 + 遍历 + 结构断言三层堵住。
- ⚠️ **但"漏声明编译不过"这句是 overclaim（半截闸）**：类型只约束**字段存在**，不约束**字段有什么效果**。反证就在本仓测试里——`tests/cloud/engine.test.ts:131-132` 的假 adapter 写的是 `watch: () => () => {}`（**空实现：永不回调**），`typecheck` **照过**。

#### ④ TD-11-7（离线走闸门 skip 不留痕 → 记 pending + 重排）→ **假死（5 个 skip 理由只治了 1 个）**

- **没治的 4 个**：`setup.ts:62-76` 产出 5 个 skip 码（NOT_CONFIGURED / AUTO_SYNC_OFF / LEDGER_BROKEN / NO_LEDGER / OFFLINE），
