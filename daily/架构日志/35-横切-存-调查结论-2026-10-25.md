## 3. 核心发现：`sj_dz*` 库文件与索引分两个动作写、中间可被插

**这是本轮唯一值得立刻定性的洞。** 用户已单独问过两次，结论钉在下面。

### 3.1 事实（行号即锚点）

| # | 事实 | 证据 |
| --- | --- | --- |
| 1 | **同一个文件**：云端写回写的 `userDir()/entry.fileName`（= `sj_dz*.json`）与 `actions.ts:90` 的 `actionLibraryImpl` `resolvePath = userDir()}/${currentFile}` 是同一个 `%APPDATA%\SheJiZhuLi\sj_dz*.json` | `cloud/entries/action-library.ts:112` · `data/actions.ts:90` |
| 2 | **两个动作**：`write()` 先 `:114` 逐个 `writeDisk(target, ...)` 写库文件（**不排队**）→ `:125` 再 `actionIndexWriter.write(index)` 写索引（这一步才进 `runQueued`） | 同文件 `:95-131`；`grep -c runQueued` = **0** |
| 3 | **中间可被插**：`action-archive.ts:114` 的 `importActionArchive`（`runQueued` 任务体）可插进 `:114` 与 `:125` 之间；它 `:141` `writeBase64File(pathOf(entry.name))` 写**同一批 `sj_dz*.json`**、`:149` `writeInLock(next)` 写**同一索引** | `data/action-archive.ts:114,141,149` |
| 4 | **两种半态都可能出现** | 见下 |

### 3.2 两种半态

| 半态 | 顺序 | 用户后果 | 可见性 |
| --- | --- | --- | --- |
| **索引指向不存在 / 内容不符的库** | 先插 A（`removeAll` / `removeFile`，`action-archive.ts:58,159`）再落 C 的索引 | 动作页顶部 `action-warning`「…，动作库可能不完整」，**仓库列表缺项 / 动作不见了** | ✅ UI 可见（`pages/action/index.vue:487` + `stores/action.ts:75` `degraded`） |
| **孤儿库文件** | 先落 C 的库文件，A 的索引已 splice 掉条目、`removeAll` 清了孤儿，C 又把旧库文件写回去 | 用户目录堆垃圾；云同步 `build()` 按索引 `entry.fileName` 打包（`entries/action-library.ts:77`）⇒ 孤儿不进包但磁盘残留 | ❌ **UI 不可见**，只 `log.warn('action', '清理旧仓库文件失败（留下孤儿）')`（`action-archive.ts:59`） |

### 3.3 归属（**归「写」那条，不是「存」这条**）

判据一句话：**「存」问"同一能力有没有 N 份实现"，「写」问"有没有第 N 个绕过唯一写链的入口"**。
本洞是后者 —— 病在 `cloud/entries/action-library.ts:114` **在 A 链的事务半途之外直调 `writeDisk`**，
把"写 N 个库文件 + 写索引"这个跨文件事务拆成锁外半段 + 锁内半段。
这正是普查第 2 项列的 `action-library.ts:109` 绕过 data owner 直写 `sj_dz*.json` 的**症状之一**
（普查当时只记"绕过 data owner"，**没记"拆散事务、可被插"**）。

「存」这条横切本身没病：`runQueued`（A）与 `settings.writeQueue`（B）写的文件交集 = 0，语义不同，合并没有收益。

### 3.4 危险度

**中危 P1，用户可感知，不是开发者自知的洁癖问题**：

- 触发条件 = **云下载写回** 与 **面板里导入 `.dzx` / 删仓库** 同一刻撞上（手动同步 + 手动导入同时点）⇒ 不是启动就坏。
- 一旦撞上：**恢复要用户手动收拾 `%APPDATA%\SheJiZhuLi\` 的孤儿文件**，代价不小。
- 云写回失败有出口（`write()` 的 `catch` 返回 `{ok:false, message:'动作库写回失败'}`），**但半态不在这个出口里** —— 返回"整包失败"时磁盘已是半截。
