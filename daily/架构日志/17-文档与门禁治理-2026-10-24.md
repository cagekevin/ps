## 一、链路快照（实证，非凭文件名猜）

```
产品层闸（npm run check，12 步，全部与 scripts/ 无关）：
  style:guard → template:guard → assert:guard → dispatch:check → boundary:pages
  → layer:boundary → spec:check → ledger → stats:check → lint → format:check

工具层闸（npm run check:tools，2 步）：
  lint:tools (eslint scripts) → format:check:tools (prettier scripts/**)
```

**改动前**：`lint` = `eslint .`、`format:check` = `prettier --check "scripts/!(adr).mjs"` ——
**两条都按目录扫到 `scripts/**`**，于是"往 scripts/ 放一个文件"＝"往产品闸里塞一个检查点"。

**实证（2026-10-24）**：从 maomao 拷入 `scripts/probe.mjs`（21KB）后，
`npm run check` 立刻红：prettier 1 处 + eslint 7 条（`no-control-regex`、未用 import、`no-useless-assignment`）。
**产品代码一行没动，闸红了** —— 机制不合理：工具层不该有权力卡住产品层。

## 二、溯源

- **症状**：搬一个工具脚本 ⇒ 产品闸红 ⇒ 面板构建被工具脚本的风格问题卡住。
- **病根**：门禁**只有一条链**，没有按"被闸的东西属于哪一层"分层；`scripts/**` 与 `src/**` 混在同一批检查里。
- **顺带暴露**：eslint 豁免里写着「原样拷自 maomao，下次上游更新就合不回来」——
  **本仓作者即上游，这理由不成立**（作者裁定 2026-10-24：没有上游，我就是作者）。

## 三、定海（唯一真相源）

| 事实                       | 落点                           | 机器守卫                                    |
| -------------------------- | ------------------------------ | ------------------------------------------- |
| 哪些代码算"产品"           | `src/**` + `tests/**` + 根配置 | `npm run lint` / `format:check` 的路径参数  |
| 哪些代码算"工具"           | `scripts/**`                   | `npm run lint:tools` / `format:check:tools` |
| 工具层能不能卡产品层       | **不能**                       | `deploy` 链里**没有** `check:tools`         |
| 工具脚本坏掉会不会被发现   | 会（功能坏 = 节点抛错 = 闸红） | `node` 非零退出即中断                       |
| 工具脚本风格脏会不会卡面板 | 不会                           | 工具闸独立，不进 `deploy`                   |

## 四、切割

**为什么这样切**：门禁的价值 = "拦住会伤到用户的东西"。工具脚本的**风格问题**（缩进、引号、未用变量）
对用户零影响；它的**功能问题**（语法错、逻辑错）会直接让闸失效或误判 —— 那必须红。
⇒ 判据落点：**功能坏 = 产品闸红；风格脏 = 工具闸红，不卡产品**。

**为什么 `deploy` 不带 `check:tools`**：交付面板不需要工具层干净；
把"写脚本的人该自己跑的那条闸"塞进交付链，等于让工具层有权力否决交付。
