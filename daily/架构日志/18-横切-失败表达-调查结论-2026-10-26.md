## 9. 一句话总结

**「失败表达」这条横切 = 19 个失败结果形状 × 32 个判别字段名 × 13 种判别语法，散在 4 层、7 张码/文案表，而四层全在兼职（7 处越权）。**
真正做到的只有两处结构保证：**`readRepoFile(target, decode)` 的 `decode` 必填**（「把 JSON.parse 结果直接当 T」写不出来）
与 **`CODE_REGISTRY: Record<CepErrorCode, …>` 的 never 收尾**（新增码不补表编译不过）。
19 个形状里**只有 `RepoRead` 一个**做到「`ok:false` 那一臂类型上取不到 `.value`」，**8 个**的失败臂仍可取 `.value` 或仍带自由文本；
其中 3 个（`ActionListRead` / `KuGroupsSource` / `ProvenKu` 族）**结构上只能改一半**（失败臂必须带空值给页面渲染）⇒ 判据二的本仓上限是 **14/19**。

## 12. 只留一种写法：`RepoReadBad` 拆两臂（2026-10-26 夜，续）

### 12.1 判据

interface RepoReadBad<T> {

## 13. 子码名也只有一个：`fail`（2026-10-26 夜，续）

### 13.1 目标口径（第三处更正）

判别位统一成 `status` 之后，曾经想"判别字段名种数 → 1"。**那个目标不成立**：`fail` / `why` / `kind` / `shape` 是**失败臂内部的子码**，不是判别位；把它们并进 `status` 会让 `{status:'notJson'}` 与 `{status:'error'}` 同形——更差。

**正确目标**：**判别位只有一个名字（`status`）；子码不占用判别位的名字；子码名也只有一个（`fail`）。**

### 13.2 改了什么：`why` → `fail`

| 形状 | 位置 |
|---|---|
| `RepoReadBad<T>` | `cep/data/types.ts` |
| `RepoFileOutcome<T>` | `cep/data/repo-read.ts` |
| `QuickFontGate` | `domain/quick-font.ts` |

改成 `fail` 的理由：`DecodeFail` 全仓最广（173 处引用）已经在用 `fail`，而 `RepoFileOutcome.fail` 的取值（`notJson` / `badShape`）**本来就是从 `DecodeFail` 折过来的** —— 同一个名字，同一种语义。

**联动改动 11 个消费文件 + 3 个夹具**（全部由编译器逐条列出，不是 grep 猜）。`messages.ts` 的形参名 `(why: string)` 也跟着改成 `(fail: string)`。

### 13.3 一个撞名的坑（记下来）

`CasMode` 里也有 `why`：`backup: { mode: 'none', why: '导出产物，无原文可备' }` —— 那是**"为什么不备份"**，不是失败子码。机械替换误伤 3 处（`cloud/ledger.ts` ×2、`data/style-library-repo.ts` ×1），typecheck 当场报 `'fail' does not exist in type '{ mode: "none"; why: string }'`，已改回。

⇒ **同名字段在不同语义下不能用同一把替换刀**；typecheck 是唯一能抓住这种误伤的东西。

### 13.4 数字

| 量 | 改前 | 改后 |
|---|---|---|
| 用 `why` 当失败子码的形状 | **3** | **0** |
| `fail` 作为子码名覆盖的形状 | 1（`DecodeFail`） | **4**（`DecodeFail` / `RepoReadBad` / `RepoFileOutcome` / `QuickFontGate`） |
| `vue-tsc` src / tests | — | **0 / 0** |
| 全量 | — | **147 文件 / 1,135 用例全绿** |
| eslint / prettier（19 个文件） | — | 0 / 通过 |

### 13.5 还剩一个 `kind`，以及为什么留着

`ReadFailure.kind`（`'errno' | 'noNode' | 'noCep' | 'pathEscape'`）仍然叫 `kind`。

**它不是"为什么这份数据不可用"，是"观测被什么挡住的"**：`errno` 是系统错误码、`noNode` 是没开 `--enable-nodejs`、`pathEscape` 是守卫没过。与 `fail` 的取值（`readError` / `notJson` / `badShape`）不在同一层：一个是**观测受阻的方式**，一个是**内容不可用的原因**。

要合并也能做（11 行 + `describeReadFailure` + 3 条测试），但那会把两个语义压成一个名字。**如果口径是"字面上只许一个名字"，说一声我就改。**（当前保持 `kind`。）

## 15. 删掉"错的示范"：失败臂字面量收进唯一工厂（2026-10-26 夜，续）

### 15.1 为什么做这一刀

问：**下一个 AI 来了还会不会写错？** 拿探针实测（模拟"照直觉写"的 7 种违规）：

| # | 违规写法 | 编译 |
|---|---|---|
| ① | 读 `read.failure` 但不判 `fail` | ❌ 挡住 |
| ② | 云失败用 `code:` 当字段名 | ❌ 挡住 |
| ③ | 手搓 `RepoRead` 字面量绕过 `foldAbsent` | ✅ **写得出来** |
| ④ | 新造失败形状，字段随手起名 | ✅ **写得出来** |
| ⑤ | `new CepError('IO', '内容读不懂')` | ✅ **写得出来** |
| ⑥ | `log.error('x', '库文件读不到：EPERM…')` | ✅ **写得出来** |
| ⑦ | 再造一个 `describeXxx` | ✅ **写得出来** |

**7 条只挡住 2 条。** 而且刀 9 原来给"结构上做不到"留的出口是 **文件头五段 + 注册表** ——
**注册表已被删除**，文件头没有一份是五段齐的 ⇒ 兜底也不存在。

**所以口径改成：不能靠"拦"，就靠"删"。**
下一个人是**按就近原则抄**的 —— 只要仓里没有任何一处"错的示范"，他就抄不到错的。
`docs/生成/注册表.json` 不存在这件事，正是这条口径的由来：**没有登记表，就只有代码本身能当样板。**

### 15.2 改法：三个工厂 = 失败臂的唯一构造入口

| 工厂 | 用途 |
|---|---|
| `badRead(reason, fallback, failure)` | 读盘失败臂 —— `fail:'readError'` **必带现场** |
| `badContent(fail, reason, fallback)` | 内容失败臂 —— 没有系统错误可带，**不存在 `failure` 字段** |
| `rebad(src, fallback)` | 把另一个失败的 `RepoRead` 重包成新 payload 类型（**字段一个不丢**） |

`rebad` 是这一刀的重点：手写"重包"是本仓最容易**悄悄丢掉 `failure`** 的地方
（`readError` 的现场整段消失，而且**不报错**）。`font-meta` / `legacy-settings` 原来各写一遍两臂字面量，
现在各一行 `rebad(read, <新fallback>)`。

### 15.3 数字

| 量 | 改前 | 改后 |
|---|---|---|
| `RepoReadBad` **字面量**构造点（`src` 内） | **6 文件 / 14 处** | **1 文件 / 3 处**（就是三个工厂自己） |
| 手写"两臂重包"的地方（最容易丢 `failure`） | 4 处 | **0**（`rebad` 一个） |
| 失败臂字段名种数 | 一套（`fail`/`reason`/`failure`/`fallback`） | 不变 |
| `vue-tsc` src / tests | — | **0 / 0** |
| 全量 | — | **147 文件 / 1,135 用例全绿** · `npm run check` exit 0 |

### 15.4 还挡不住的 4 条（如实写）

| # | 为什么挡不住 | 现在靠什么 |
|---|---|---|
| ④ 新造失败形状起名 | TS 管不了新文件的字段名 | **存量**：全仓失败臂只剩 `fail`/`reason`/`failure`/`fallback` 一套 |
| ⑤ `CepError` 塞中文 | `message: string` 本身就是 UI 文案，285 处都得这么写 | **存量**：日志侧已 0 处把文案当诊断（§11）；`catch` 断链 6→0（§11.4） |
| ⑥ `log.error` 写文案 | `warn` 有 8 处纯事件日志没有错误对象可传 ⇒ `detail` 必填这一刀焊不上（会逼人编假数据） | **存量**：135 处 `log.*` 里 0 处 message 是用户文案 |
| ⑦ 再造渲染器 | TS 管不了新函数 | 现有三个 `describe*` 按层分（①技术原文 / ③中文 / ④码+原文），不是一个东西的三份 |

**结论：结构上只有 3/7 条真正被焊死（① ② ③）。剩下 4 条靠"仓里没有错样板"——这不是保证，是概率。**
能给的准确说法是：**下一个人抄的时候抄不到错的**，而不是"他写不错"。
