## 5. 判据 5 的口径（**本轮定，不再问**）

**问题**：卷数出「字段名 10 种」，但漏了一维 —— 同一个 `ok` 在仓里有 **4 种取值域**（`boolean` / `true` / `false` / `'cancelled'`）。
`CommandOutcome = {ok:true} | {ok:false;code} | {ok:'cancelled'}` ⇒ `ok` 的类型是 `boolean | 'cancelled'`，别处是纯 `boolean`。**已核消费侧不会错判**（`useCommand.ts` 用穷举三态），所以这是**结构债不是行为 bug**。

**决定**（判据一 + 判据二推出来的，只有这一个解）：

1. **判别位名全仓统一 = `status`**。`ok` 作为判别位**退休**（`ok` 只允许出现在"HTTP 语义的原样透传"里，且必须立刻转成形状）。
2. **`cancelled` 从 `ok` 的取值域搬进 `status` 的取值域**：
   `CommandOutcome.status: 'ok' | 'cancelled' | 'error'` —— 名字就位了，类型不再跨域。
3. **每域一套取值，但**：`status` 的取值必须来自同一张词表 —— `ok` / `notSeen` / `cancelled` / `error`（四选，按域裁剪），**不许自造第五个**。
   - 读链、解析：`ok` / `notSeen` / `error`
   - 命令：`ok` / `cancelled` / `error`
   - jsx、云：`ok` / `error`
4. **验收口径升级**（写进本域验收）：`字段名种数 = 1` **且** `同名字段取值域种数 = 1`（每域一套）。只降行数不降种数 = 假收口。
5. **不改 `JsxOutcome` / `CommandOutcome` 的臂数**（它们是判别联合，判据二已满足）；只改**判别位名**与**`cancelled` 的位置**。理由是判据一（一个概念一个名字），不是"统一好看"。

**这条决定的爆炸半径（实测，别到时候才发现）**：
`git grep -nP "\.ok\b" -- src | wc -l` = **46 行 / 21 文件**；其中 `commands` + `components` + `utils/jsx-result` = **26 行**。
⇒ 改名是**独立一整刀**，不塞进本轮解析收口：本轮只做 §8 的解析点，改名另开一轮，届时先出这 46 行的逐文件清单。

### 11.12 刀 7 · 读不到只剩一种处置（抛）· 已落地

**判据**：`notSeen`（文件本来不存在）是**正常状态**，给默认值；`error`（文件在、读不到/读不懂）**一律抛**。
「当空继续」与「记日志跳过」这两种处置取消 —— 它们是"降级但不敢承认"，用户会以为操作成功、实际少了一半数据。

**两个薄入口**（都在 `cep/data/repo-read.ts`，背后同一个 `readRepoFile`）：

| 入口 | 用途 | 语义 |
|---|---|---|
| `readForWrite(target, decode, fallback)` | 数据文件（要过 decoder） | `notSeen` ⇒ `fallback()`；`error` ⇒ 抛（`IO`/`PARSE` + 路径 + 底层原文） |
| `readTextForWrite(target)` | 只要原文（导出旁路图、枚举图片名） | `notSeen` ⇒ `null`；`error` ⇒ 抛 |

**删掉的字段（四个）**：

| 字段 | 原位 | 为什么删 |
|---|---|---|
| `Decoded.degraded` | `utils/decode.ts` | 半成品值不允许流到业务层：读不懂就是 `DecodeFail` |
| `RepoFileOutcome.ok.degraded` | `repo-read.ts` | 同上 |
| `RepoReadOk.reason?` | `data/types.ts` | ok 臂上记"降级原因"的唯一用途消失 |
| `StyleLibrarySnapshot.degraded` | `style-library-repo.ts` | 同上；`FoldOptions.notSeenReason` 一并删 |

**迁移的调用点**：
- `style-library-repo`：导出读原文（`readKuFileText`）、删仓库枚举（`groupsOfFile`）、读原始组（`readRawGroups`）、索引读取（`readIndexState` 读不懂就抛）
- `classification-repo`：不再给 ok 臂挂"文件不存在"的 reason；`decodeIndexed` 的 `index` 缺失从"按 0 + 标记"改成**整份拒绝**（补 0 与"选中第 0 条"在值上不可分辨）
- 六个 store 的 `degraded` 改为**只从 error 臂取**（`read.status === 'ok' ? '' : read.reason`）

**保留的 4 处「跳过」**（不是降级，是清理路径）：替换导入的旧文件回收、删仓库的文件回收、
日志 dump、云写回前读本地库文件。理由：这些是**回滚/清理**，中断会让"删了一半 / 回滚了一半"，
比留下残留更难收拾；且每一处都 `log.warn` 留了痕。**它们不返回业务值，所以不构成"第二种读法"**。

**行为变化（4 条，都会让用户看见）**：

| # | 场景 | 以前 | 现在 |
|---|---|---|---|
| 1 | 样式库索引读不懂 | 页面显示空仓库 + 顶部提示条 | **整页报错**（`error` ref 显示原因） |
| 2 | 导出时某个库文件读不懂 | 跳过它，导出继续（少几张图） | **导出失败**（不让用户以为导全了） |

**验收**：全量 **147 文件 / 1,135 用例全绿** · `vue-tsc` src+tests 0 错 · `npm run check` 绿 ·

1. **判据 4 的验收不是「grep 命中 0」。** 剩下 7 处，**按判据四（`ok` 臂上 0）算过关**；`RepoReadOk.reason` / `StyleLibrarySnapshot.degraded` 还额外有 ADR-14 背书（「读可降级但必须标记」）。
