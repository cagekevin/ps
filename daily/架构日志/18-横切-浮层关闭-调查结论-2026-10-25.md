## 2. 三个角度

### 角度 1 · 是否唯一

**a) `usePopover` 与 `useDismiss` 是两套独立监听器（`document.addEventListener('mousedown'/'keydown')` 共 4 处）：**

```
grep -rn "document.addEventListener" src/composables/usePopover.ts src/composables/useDismiss.ts
# src/composables/usePopover.ts:80:    if (closeOnOutside) document.addEventListener('mousedown', onDocMouseDown)
# src/composables/usePopover.ts:81:    document.addEventListener('keydown', onKeydown)
# src/composables/usePopover.ts:83:    document.addEventListener('scroll', onViewportChange, true)
# src/composables/useDismiss.ts:36:  document.addEventListener('mousedown', onPointerDown)
# src/composables/useDismiss.ts:37:  document.addEventListener('keydown', onKeydown)
```

`useDismiss.ts:50` 的注释自己写着「所有弹窗、菜单、下拉、卡片都必须用它，不要各自 `document.addEventListener`」——
但 `usePopover.ts` **正是**"各自 `document.addEventListener`"，注释和实现**自我矛盾**。

**b) 关闭原语的入口（4 个）与消费者（文件数，命令见 §7）：**

| 入口 | 消费者文件数 | 有没有守卫 | 能不能绕过判据 |
| --- | --- | --- | --- |
| `usePopover()` | 4（`GPopover`/`GDropdown`/`SelectBox`/`ActionWarehouse`） | ✅ `bind/unbind` + `onBeforeUnmount` | **能绕过 `useDismiss`**（`grep useDismiss src/composables/usePopover.ts` = 0 命中） |

| `usePointPopover()` | 2（`TagContextMenu`/`TagMenu`） | ✅ 内部委托 `useDismiss` | ✅ 不能绕过 |
| `useFloatingPosition()` | 6（含 `usePopover`/`usePointPopover` 两个转发层 + `style`/`StyleMenu`/`action`/`rename` 4 个页面直用） | ✅ 纯几何，无副作用 | ✅ 不能绕过（不判开关） |

### 角度 2 · 数据流是否清晰

**打开链（以 `GPopover` 为例）**：触发器 `@click` → `usePopover.toggle()` → `open.value = !open.value`
→ `watch(open)` → `await nextTick()` → `update()`（调 `useFloatingPosition.update()` 算几何）→ `bind()`
（挂 `document` 监听 + `ResizeObserver`）。**清晰，但只对"用 `usePopover` 的那 4 个"成立。**

**关闭链（本域真正的分叉点）**：

| 触发 | `usePopover` 走的路 | `useDismiss` 走的路 | `FontWeight.vue` 走的路 |
| --- | --- | --- | --- |
| 点外部 | `onDocMouseDown`（`usePopover.ts:63`）→ `close()` | `onPointerDown`（`useDismiss.ts:13`）→ `entry.close()` | **无** |
| Esc | `onKeydown`（`usePopover.ts:71`） | `onKeydown`（`useDismiss.ts:21`）→ 逆序关最上层 + `stopPropagation()` | **无** |
| 点触发器再点一次 | `toggle()`（`usePopover.ts:59`） | 由调用方自己 `@click` 处理 | `open = !open`（:54） |
| 点某一项 | 由调用方 slot 的 `close()` 决定 | 由调用方 `close()` 决定 | `pick()` 设 `open=false` |

**数据流问题**：同一件"点外部/Esc 该关掉"的事，**三列各写一遍判断**（`usePopover` 自己判、`useDismiss` 自己判、
`FontWeight` 不判）。`useDismiss` 的 `onKeydown` 有多层嵌套处理（逆序关最上层 + `stopPropagation`），
`usePopover` 的 `onKeydown` **没有**（`usePopover.ts:71-73`，直接 `close()`，不区分嵌套）——
**两套的 Esc 语义本身就不一样**，不是"等价的两种实现"，是"**两种不同行为**"。

### 角度 3 · 结构上别人是否不可能绕过

**不能保证不绕过。** 三条证据：

1. **`usePopover` 绕过 `useDismiss` 已经发生**（`grep useDismiss src/composables/usePopover.ts` = 0），
   且不是"忘了用"，是 `usePopover` 在 `useDismiss` 出现之前就自己实现了同样的事。
2. **`useDismiss` 的"唯一入口"自述是注释，不是结构保证**：`useDismiss.ts:50` 写着
   「所有弹窗、菜单、下拉、卡片都必须用它，不要各自 `document.addEventListener`」——
   但 `usePopover.ts:80/81` 就在同一个目录下违反了这句，**没有任何闸会红**（§7 无闸探针，
   本轮只查不改、不跑注入式探针，属已知空白）。
3. **游离浮层 `FontWeight.vue` 结构上零约束**：没有 import 任何 `composables/`，没有 `Teleport`，
   关闭机制是本地 `open.value = false`（三处赋值：`pick()` :37、`@click.stop` :54、无第三处）。
   **想加第四种关闭方式（比如 Esc）只能改这个文件**，收口对它无效。

### A2 · `usePopover` 的 Esc **不 `stopPropagation`**，`useDismiss` 的 Esc **会**（**不对称**）

```
grep -n "stopPropagation\|Escape" src/composables/usePopover.ts src/composables/useDismiss.ts
# usePopover.ts:72: if (open.value && closeOnEscape && event.key === 'Escape') close()   ← 无 stopPropagation
# useDismiss.ts:30: if (handled) event.stopPropagation()
```
**同一个 Esc 事件**：`usePopover` 收到就 `close()` 但**继续冒泡**；`useDismiss` 收到会 `stopPropagation()` 阻止继续。
两者都挂在 `document` 上（bubble 阶段，`addEventListener` 无 `true` 参数，见下条），
**同一事件两个处理器都会跑**，只是顺序不定（`document` 上多个 listener 按注册顺序触发）。

### A3 · 两者都注册在 bubble 阶段（无 `capture`），**触发顺序 = 注册顺序 = 挂载顺序**

```
grep -n "addEventListener('keydown'\|, true" src/composables/usePopover.ts src/composables/useDismiss.ts
# usePopover.ts:81: document.addEventListener('keydown', onKeydown)          ← 无 capture
# usePopover.ts:83: document.addEventListener('scroll', onViewportChange, true) ← 这个是 capture，但不是 keydown
# useDismiss.ts:37: document.addEventListener('keydown', onKeydown)          ← 无 capture
```
`keydown` 两处都是 bubble 阶段（第 3 参数缺省 = `false`）⇒ **谁先 `onMounted` 谁先触发**。
`usePopover` 是"打开才 `bind()`"（`watch(open)` 驱动，`:112-124`），`useDismiss` 是"挂载就 `install()`"（`:71`）——
**两者的注册时机不同源**，顺序完全取决于组件打开的先后，**不确定**。

### A4 · **真冲突场景存在**：`action/index.vue` 同一页面同时活两套

- `usePopover` 的 `onKeydown` **也**会跑（如果它先注册），`close()` 后**不 `stopPropagation`**，继续冒泡；

## 0. 先纠正前一节的结论（"一诚实"）

第六遍写「`useDismiss` 的"点外部"关所有、"Esc"只关最上层」——**读代码与实测都表明这句说错了**：

```ts
// 改前 useDismiss.ts:21-31
for (const entry of [...entries].reverse()) {
  if (!entry.visible()) continue
  entry.close()
  handled = true          // ← 没有 break ⇒ Esc 关的是"所有可见浮层"
```

`reverse()` 是装饰：**Esc 和点外部现在都是关所有**。所谓"不对称"不存在，存在的是**漏 break**。
