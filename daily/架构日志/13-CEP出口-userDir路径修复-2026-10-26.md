# 13 区 · `userDir()` 数据目录算错（Windows）· 修复轮次 · 2026-10-26

## 1. 背景与根因（已实证）

面板把用户数据目录算成了 macOS 路径：

| | 路径 | 事实 |
|---|---|---|
| 面板实际读写 | `C:\Users\xinye\Library\Application Support\SheJiZhuLi` | 真实存在，面板在错路径下种了 `sj_kuStoreInfo.ini` / `sj_v5_ui.json` / `sj_v5_log.txt` |
| 正确目录 | `%APPDATA%\SheJiZhuLi` | 用户数据全在这儿（`sj_commonFunction.json` 3539B、`SysFont2.json` 54828B 等） |

**根因不是运行时读不到 `process`，是编译期被替换**：Vite 的 definePlugin 内置
`"globalThis.process.env": "{}"`（`node_modules/vite/dist/node/chunks/config.js:26682-26688`，
条件 `if (!isBuildLib)` ⇒ **dev 与 build 都生效**），于是 `src/cep/paths.ts` 里
`globalThis.process?.env` 被 esbuild 换成常量空对象 `define_globalThis_process_env_default = {}`，
`env.APPDATA` 恒 `undefined` ⇒ 永远落 macOS 回退。

**为什么只在 Windows 现形**：回退链 `env.APPDATA ?? os.homedir() + '/Library/Application Support'`
在两个平台都会走到，但 macOS 上 `~/Library/Application Support` **本来就是正确答案**，
Windows 上是错的。所以 Mac 侧从来没出过问题，bug 因此长期潜伏。
