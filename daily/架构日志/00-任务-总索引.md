# 架构日志 · 任务索引（112 条 `T-xx` 的唯一可检索表）

> **为什么单独一份**：maomao 账本只管债（`TD-<NN>-<n>`），没有任务表；本仓的 `T-xx` 是**任务**不是债
> （「把某页做出来」「给某函数补 fixture」——它们有开始有结束，还清了就消失，不产生持续利息）。
> 混进 `债务.md` 会让「债」这个字失去含义：一条 `done` 的任务和一条 `已解决` 的债务排在一起，
> 就再也没法回答「我们还欠什么」。
>
> **怎么被查到（三条路，都不依赖本文件被记住）**：
>
> 1. `git grep -n 'T-88' -- src tests docs` —— 代码注释里 `TODO(T-88)` 直接命中本表行号；
> 2. `node scripts/debt.mjs search <关键词>` —— 债侧检索；任务侧没有脚本，**就靠本文件 + git grep**；
> 3. `docs/状态/进度.md` 每页「缺什么」列里写的 `T-xx` —— 那是给页面视角的指针，最终回到本表。
>
> **唯一写入口 = 手改本文件**（没有脚本：任务不需要 `debt.mjs` 那套枚举校验 / 取号 / 归档，
> 加了就是把任务当债管，正是上面要避免的事）。新增一条往对应表尾加一行，ID 递增。
> **编号沿用旧 `T-xx`**：2026-10-24 从 `docs/状态/台账.md` 迁入时**没有重新编号**——
> 代码注释里有 6 处 `TODO(T-18)` / `TODO(T-88)`，重新编号会让它们全部悬空。

## 与 `债务.md` 的边界

|          | `债务.md`（`TD-<NN>-<n>`）            | 本文件（`T-xx`）         |
| -------- | ------------------------------------- | ------------------------ |
| 是什么   | 已经发生的行为缺陷 / 结构偏差         | 计划要做的活             |
| 有终点吗 | 有（还清即消失）                      | 有（做完即消失）         |
| 谁管     | `node scripts/debt.mjs`（唯一写入口） | 手改本文件               |
| 利息     | 有（不还会持续造成损害）              | 无（不做也不会自己变坏） |
| 编号     | 按区编号，跨区不搬                    | 全局递增，不按区         |

**同一条活该进哪边？** 判据一句：**「现在不做，它会自己变坏吗？」**
会 → 债；不会 → 任务。例：`D-62 transport.ts as unknown as T` 是债（每次加 jsx 函数都在复制这个错）；
`T-54 字体面板 fixture` 是任务（不做也只是少一份样本，不会腐化）。
